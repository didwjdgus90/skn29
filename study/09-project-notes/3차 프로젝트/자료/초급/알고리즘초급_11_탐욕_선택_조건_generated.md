# [알고리즘] 탐욕 선택 조건

## 1. 한 줄 요약

> 탐욕 선택 조건은 지금 고른 최선의 선택이 나중에도 전체 정답을 망치지 않는지 판단하는 기준입니다.

---

## 2. 선수 지식

- 그리디 알고리즘: 매 단계에서 가장 좋아 보이는 선택을 하는 풀이 방식입니다.
- 정렬: 어떤 기준으로 먼저 볼지 정할 때 자주 사용합니다.
- 우선순위 큐: 매번 가장 큰 값이나 가장 작은 값을 빠르게 꺼낼 때 사용합니다.
- 힙: 우선순위 큐를 구현하는 대표적인 자료구조입니다.
- 최적해: 문제에서 요구하는 가장 좋은 답입니다.
- 부분 문제: 전체 문제를 작은 단위로 나누어 본 문제입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

그리디는 빠르고 단순하지만, 아무 문제에나 적용할 수 없습니다. 탐욕 선택 조건은 "이 문제를 그리디로 풀어도 되는가?"를 판단하기 위해 필요합니다.

### 기존 방식의 문제

- 모든 경우를 탐색하면 후보 수가 너무 많아질 수 있습니다.
- 동적 계획법으로 풀 수 있어도 상태 설계가 복잡할 수 있습니다.
- 문제마다 어떤 기준으로 선택해야 하는지 다릅니다.

예를 들어 여러 일정 중 겹치지 않게 최대한 많이 골라야 한다고 해봅시다. 가능한 모든 일정 조합을 확인하면 일정 수가 늘어날수록 경우의 수가 크게 증가합니다.

### 이 알고리즘을 사용하면

- 매 순간 하나의 기준으로 선택하므로 구현이 단순해집니다.
- 정렬이나 우선순위 큐를 함께 쓰면 큰 입력도 빠르게 처리할 수 있습니다.
- 탐욕 선택 조건이 성립하는 문제라면, 모든 경우를 보지 않아도 최적해를 얻을 수 있습니다.

핵심은 속도가 아니라 정당성입니다. 빠르게 고르는 것보다 "그렇게 골라도 항상 맞는가"를 먼저 확인해야 합니다.

## 4. 핵심 아이디어

탐욕 선택 조건은 보통 두 가지 관점으로 생각합니다.

1. 지금의 최선 선택을 해도, 남은 문제의 정답 가능성이 사라지지 않아야 합니다.
2. 지금 선택한 뒤 남은 문제를 최적으로 풀면, 전체도 최적이 되어야 합니다.

첫 번째는 탐욕 선택 속성이라고 부릅니다. 두 번째는 최적 부분 구조라고 부릅니다.

### 쉬운 비유

책장에 책을 꽂으려고 합니다. 목표는 한 칸에 최대한 많은 책을 넣는 것입니다. 책의 두께가 모두 다르다면, 얇은 책부터 고르는 선택은 직관적으로 유리합니다. 얇은 책을 먼저 골라도 나중에 두꺼운 책을 넣을 기회가 줄어드는 방식이기 때문입니다.

하지만 목표가 "가장 비싼 책 조합을 고르기"라면 얇은 책부터 고르는 기준은 틀릴 수 있습니다. 같은 그리디라도 문제의 목표에 맞는 선택 기준이 필요합니다.

### 직관적으로 이해하기

겹치지 않는 상담을 최대한 많이 선택해야 한다고 해봅시다. 이때 빨리 끝나는 상담을 먼저 고르면 남은 시간에 다른 상담을 배치할 가능성이 커집니다.

반대로 상담 시간이 짧은 것부터 고르면 항상 좋은 것은 아닙니다. 짧지만 늦게 끝나는 상담을 먼저 고르면, 앞쪽 시간대의 좋은 선택들을 놓칠 수 있습니다.

즉 그리디에서는 "좋아 보이는 기준"이 아니라 "전체 정답으로 이어지는 기준"을 찾아야 합니다.

## 5. 동작 과정 살펴보기

### 예제 상황

하루 동안 들을 수 있는 특강을 최대한 많이 선택하려고 합니다. 한 번에 하나의 특강만 들을 수 있고, 시간이 겹치면 둘 중 하나만 선택할 수 있습니다.

### 예제 입력

```text
5
1 4
2 3
3 5
4 6
6 7
```

각 줄은 `시작 시간 종료 시간`을 의미합니다.

### 예제 출력

```text
3
```

예를 들어 `(2, 3)`, `(3, 5)`, `(6, 7)`을 선택하면 총 3개의 특강을 들을 수 있습니다.

### 단계별 동작

1. 특강 목록을 종료 시간이 빠른 순서로 정렬합니다.
2. 아직 아무 특강도 선택하지 않았으므로 현재 종료 시간을 `0`으로 둡니다.
3. 정렬된 특강을 앞에서부터 확인합니다.
4. 시작 시간이 현재 종료 시간 이상이면 선택합니다.
5. 선택한 특강의 종료 시간으로 현재 종료 시간을 갱신합니다.
6. 끝까지 확인한 뒤 선택한 개수를 출력합니다.

## 7. 기본 코드 템플릿

```python
def count_available_sessions(sessions):
    sessions.sort(key=lambda item: (item[1], item[0]))

    selected_count = 0
    last_finish_time = 0

    for start_time, finish_time in sessions:
        if start_time >= last_finish_time:
            selected_count += 1
            last_finish_time = finish_time

    return selected_count


def main():
    session_count = int(input())
    sessions = []

    for _ in range(session_count):
        start_time, finish_time = map(int, input().split())
        sessions.append((start_time, finish_time))

    print(count_available_sessions(sessions))


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `sessions` 리스트에 시작 시간과 종료 시간을 저장합니다.
* 종료 시간이 빠른 순서로 정렬합니다.
* `last_finish_time`은 마지막으로 선택한 특강이 끝나는 시간입니다.
* 반복문은 정렬된 특강을 하나씩 확인합니다.
* 조건문은 현재 특강이 이전 특강과 겹치지 않는지 검사합니다.
* 겹치지 않으면 선택 개수를 늘리고 종료 시간을 갱신합니다.
* 모든 특강을 확인하면 선택 가능한 최대 개수를 반환합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: 정렬에 `O(n log n)`, 순회에 `O(n)`이 걸립니다.
* 최악의 경우: 입력이 어떤 순서로 들어와도 정렬이 필요하므로 `O(n log n)`입니다.
* 입력 크기가 커졌을 때 부담되는 부분: 후보를 확인하는 반복보다 정렬 비용이 더 큽니다.

우선순위 큐를 사용하는 그리디에서는 삽입과 삭제가 각각 `O(log n)`입니다. 후보가 계속 추가되고 가장 좋은 후보를 반복해서 꺼내야 한다면 우선순위 큐가 유리합니다.

### 공간복잡도

* 입력 목록을 저장하기 위해 `O(n)` 공간을 사용합니다.
* 정렬 이후에는 선택 개수와 마지막 종료 시간만 추가로 사용합니다.
* 우선순위 큐를 쓰는 문제라면 큐에 저장되는 후보 수만큼 `O(n)`까지 공간이 필요할 수 있습니다.

## 9. 예제로 이해하기

다른 예제로 물품을 작은 상자에 최대한 많이 담는 상황을 생각해봅시다. 상자에 담을 수 있는 총 무게는 `10`이고, 물품 무게는 다음과 같습니다.

```text
2 3 5 6 7
```

목표가 "물품 개수 최대화"라면 가벼운 물품부터 담는 선택이 자연스럽습니다.

처리 과정:

```text
선택 후보   현재 무게   판단
2           2          선택
3           5          선택
5           10         선택
6           16         초과
7           17         초과
```

최종 결과는 물품 3개입니다.

하지만 목표가 "가치 최대화"이고 각 물품의 가치가 다르다면, 가벼운 것부터 담는 전략은 틀릴 수 있습니다. 탐욕 선택 조건은 바로 이런 차이를 확인하게 해줍니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "매번 가장 큰 값", "매번 가장 작은 값"을 선택하는 흐름이 보입니다.
* 정렬 기준을 잘 잡으면 앞에서부터 한 번만 확인해도 될 것 같습니다.
* 현재 선택이 이후 선택의 범위를 단순하게 줄입니다.
* 선택을 되돌릴 필요가 없어 보입니다.
* 부분 문제의 최적 선택이 전체 최적해로 이어질 가능성이 있습니다.
* 입력 크기가 커서 완전탐색은 어렵습니다.
* 우선순위가 계속 바뀌는 후보 중 하나를 골라야 합니다.
* 기한, 종료 시간, 비용, 이익, 남은 용량 같은 기준이 뚜렷합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 그리디와 완전탐색

완전탐색은 가능한 선택을 모두 확인합니다. 그리디는 기준에 따라 한 선택만 고르고 앞으로 나아갑니다. 그리디가 훨씬 빠를 수 있지만, 선택 기준이 틀리면 정답도 틀립니다.

### 그리디와 동적 계획법

동적 계획법은 여러 선택지를 비교하며 부분 문제의 답을 저장합니다. 그리디는 현재 선택을 확정하고 되돌아가지 않습니다. 현재 선택이 나중에 손해가 될 수 있다면 동적 계획법을 고려해야 합니다.

### 정렬 그리디와 우선순위 큐 그리디

정렬 그리디는 후보를 한 번 정렬한 뒤 순서대로 확인합니다. 우선순위 큐 그리디는 후보가 계속 추가되거나 제거될 때 유리합니다. 매번 다시 정렬해야 하는 상황이라면 우선순위 큐를 생각해볼 수 있습니다.

### 탐욕 선택 속성과 최적 부분 구조

탐욕 선택 속성은 "지금 최선의 선택을 해도 되는가"에 가깝습니다. 최적 부분 구조는 "남은 문제의 최적해가 전체 최적해와 연결되는가"에 가깝습니다. 둘 중 하나만으로는 그리디 정당성을 설명하기 부족한 경우가 많습니다.

## 12. 자주 하는 실수

* 기준이 그럴듯하다는 이유만으로 그리디를 적용하는 실수
* 정렬 기준을 잘못 잡는 실수
* 가장 큰 값이 항상 좋은 선택이라고 착각하는 실수
* 현재 선택이 미래 선택에 어떤 영향을 주는지 확인하지 않는 실수
* 그리디로 풀 수 없는 문제를 억지로 그리디로 푸는 실수
* 우선순위 큐에서 최소 힙과 최대 힙 처리를 헷갈리는 실수
* 후보를 선택한 뒤 상태 갱신을 빠뜨리는 실수
* 동점일 때 어떤 기준으로 정렬할지 정하지 않는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

모든 경우를 비교하지 않고도 한 번의 선택을 확정할 수 있는지 생각해보세요. 현재 선택이 이후 문제를 더 단순하게 만드는 기준을 찾아야 합니다.

### 2단계 힌트: 접근 힌트

문제의 목표가 최대화인지 최소화인지 먼저 확인하세요. 그 다음 어떤 값을 기준으로 정렬하거나 우선순위 큐에 넣어야 하는지 생각해보세요.

### 3단계 힌트: 구현 힌트

후보를 정렬해서 한 번만 훑을 수 있다면 정렬 그리디를 사용하세요. 후보가 계속 들어오고 그때마다 가장 좋은 값을 꺼내야 한다면 `heapq` 같은 우선순위 큐를 사용할 수 있습니다.

## 14. 언제 사용하면 좋은가

* 현재 선택을 확정해도 나중에 후회하지 않는 구조일 때 좋습니다.
* 정렬 기준이 명확한 문제에 적합합니다.
* 가장 빠른 종료, 가장 작은 비용, 가장 큰 이익처럼 선택 기준이 분명할 때 사용할 수 있습니다.
* 후보가 동적으로 변하면 우선순위 큐와 함께 사용하기 좋습니다.
* 입력 크기가 커서 완전탐색이 어려울 때 후보가 됩니다.
* 선택을 되돌려야 정답을 찾을 수 있는 문제에는 적합하지 않습니다.
* 이전 선택에 따라 미래의 가치가 복잡하게 바뀌면 동적 계획법을 검토해야 합니다.

## 15. 요약 정리

* 탐욕 선택 조건은 그리디를 써도 되는지 판단하는 기준입니다.
* 핵심은 현재 최선의 선택이 전체 최적해로 이어지는지 확인하는 것입니다.
* 주요 자료구조는 정렬된 리스트와 우선순위 큐입니다.
* 정렬 기반 그리디는 보통 `O(n log n)` 시간복잡도를 가집니다.
* 문제에서 "가장 작은", "가장 큰", "가장 빠른", "최대한 많이" 같은 표현이 보이면 그리디를 의심해볼 수 있습니다.
* 초급자는 선택 기준의 정당성을 확인하지 않고 구현부터 시작하는 실수를 주의해야 합니다.
