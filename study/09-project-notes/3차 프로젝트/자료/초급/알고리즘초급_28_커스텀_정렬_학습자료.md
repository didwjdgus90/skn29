# [알고리즘] 커스텀 정렬

## 1. 한 줄 요약

> 커스텀 정렬은 기본 오름차순이나 내림차순이 아니라, 문제에서 요구하는 기준을 직접 정해 데이터를 정렬하는 방법입니다.

---

## 2. 선수 지식

- 정렬: 데이터를 특정 기준에 맞게 순서대로 배치하는 작업입니다.
- key 함수: Python에서 정렬 기준이 되는 값을 만들어 주는 함수입니다.
- 튜플 비교: `(첫 번째 기준, 두 번째 기준)`처럼 여러 기준을 순서대로 비교할 수 있습니다.
- 전처리: 정렬 전에 필요한 정보를 미리 계산해 두는 과정입니다.
- 시간복잡도: 정렬 기준 계산이 전체 성능에 어떤 영향을 주는지 판단할 때 필요합니다.
- 안정 정렬: 같은 기준값을 가진 원소들의 기존 순서를 유지하는 정렬입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

커스텀 정렬은 데이터 자체의 크기순이 아니라 문제에서 정한 우선순위대로 정렬해야 할 때 사용합니다.

### 기존 방식의 문제

- 단순 오름차순 정렬만으로는 문제 조건을 만족하지 못할 수 있습니다.
- 여러 조건이 섞이면 정렬 기준을 코드로 명확히 표현해야 합니다.
- 정렬 중에 무거운 계산을 반복하면 시간초과가 날 수 있습니다.

예를 들어 파일 목록을 정렬할 때 이름순만 보는 것이 아니라, 확장자 우선순위, 파일 크기, 이름 사전순을 함께 고려해야 할 수 있습니다.

### 이 알고리즘을 사용하면

- 문제의 우선순위를 정렬 기준으로 직접 표현할 수 있습니다.
- 여러 기준을 튜플로 묶어 간단하게 정렬할 수 있습니다.
- 정렬 전에 필요한 값을 미리 계산하면 비교 비용을 줄일 수 있습니다.

커스텀 정렬에서 중요한 것은 "무엇을 기준으로 먼저 비교할 것인가"와 "그 기준을 얼마나 효율적으로 계산할 것인가"입니다.

---

## 4. 핵심 아이디어

커스텀 정렬의 핵심은 각 원소를 비교하기 쉬운 기준값으로 바꾸는 것입니다.

1. 정렬해야 하는 데이터를 확인합니다.
2. 문제에서 요구하는 우선순위를 정합니다.
3. 각 데이터에서 정렬에 필요한 값을 뽑아냅니다.
4. 여러 기준이 있다면 튜플로 묶습니다.
5. 정렬 중 반복 계산이 크다면 미리 전처리합니다.

### 쉬운 비유

대회 참가자를 줄 세운다고 생각해봅시다. 단순히 이름순으로 세우는 것이 아니라, 먼저 점수가 높은 사람, 점수가 같으면 나이가 어린 사람, 나이도 같으면 이름순으로 세워야 할 수 있습니다.

이때 "점수, 나이, 이름"이 커스텀 정렬 기준입니다. 기준을 명확히 정하면 줄 세우는 규칙도 흔들리지 않습니다.

### 직관적으로 이해하기

다음 학생 정보를 정렬한다고 해봅시다.

```text
이름  점수  제출시간
민수  90    15
지아  90    12
도윤  80    10
```

조건이 "점수 높은 순, 점수가 같으면 제출시간 빠른 순"이라면 정렬 결과는 다음과 같습니다.

```text
지아, 민수, 도윤
```

점수는 내림차순이고 제출시간은 오름차순입니다. 이런 식으로 기준마다 방향이 다를 수 있습니다.

## 5. 동작 과정 살펴보기

### 예제 상황

파일 목록을 정렬합니다. 조건은 다음과 같습니다.

1. 중요한 확장자 `py`, `md`가 먼저 옵니다.
2. 중요한 확장자끼리는 확장자 이름순으로 정렬합니다.
3. 같은 확장자라면 파일 이름순으로 정렬합니다.

### 예제 입력

```text
5
note.txt
main.py
guide.md
test.py
image.png
```

### 예제 출력

```text
guide.md
main.py
test.py
image.png
note.txt
```

중요 확장자인 `md`, `py`가 먼저 오고, 그 안에서는 확장자와 이름 기준으로 정렬됩니다.

### 단계별 동작

1. 중요한 확장자 집합을 준비합니다.
2. 각 파일을 이름과 확장자로 나눕니다.
3. 확장자가 중요한지 미리 계산합니다.
4. 정렬 기준을 `(중요하지 않은지, 확장자, 이름)`으로 만듭니다.
5. 기준에 따라 정렬합니다.
6. 원래 파일명만 출력합니다.

## 7. 기본 코드 템플릿

```python
def split_file_name(file_name):
    name_part, extension_part = file_name.rsplit(".", 1)
    return name_part, extension_part


def sort_files(file_names, important_extensions):
    prepared_files = []

    for file_name in file_names:
        name_part, extension_part = split_file_name(file_name)
        is_not_important = extension_part not in important_extensions

        prepared_files.append({
            "original": file_name,
            "name": name_part,
            "extension": extension_part,
            "is_not_important": is_not_important,
        })

    prepared_files.sort(
        key=lambda file_info: (
            file_info["is_not_important"],
            file_info["extension"],
            file_info["name"],
        )
    )

    return [file_info["original"] for file_info in prepared_files]


def main():
    file_count = int(input())
    file_names = []

    for _ in range(file_count):
        file_names.append(input())

    important_extensions = {"py", "md"}
    sorted_files = sort_files(file_names, important_extensions)

    for file_name in sorted_files:
        print(file_name)


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `split_file_name`은 파일명을 이름과 확장자로 나눕니다.
* `important_extensions`는 먼저 정렬해야 하는 확장자 목록입니다.
* `prepared_files`에는 정렬에 필요한 정보를 미리 계산해 저장합니다.
* `is_not_important`는 중요한 확장자가 아니면 `True`입니다.
* Python에서는 `False`가 `True`보다 먼저 오므로 중요한 확장자가 앞에 배치됩니다.
* `key` 튜플은 첫 번째 값부터 차례대로 비교됩니다.
* 정렬이 끝나면 원래 파일명만 뽑아서 반환합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: 정렬 자체는 `O(n log n)`입니다.
* 최악의 경우: 일반적인 비교 기반 정렬이므로 `O(n log n)` 범위로 봅니다.
* 입력 크기가 커졌을 때 부담되는 부분: 정렬 기준 계산이 무거우면 `n log n`번 수준의 비교 과정에서 비용이 커질 수 있습니다.

Python의 `key` 함수는 보통 원소마다 한 번씩 계산됩니다. 그래서 정렬 기준을 `key`로 미리 만들어 두면, 비교 함수 안에서 문자열 분리나 검색을 반복하는 방식보다 안정적입니다.

### 공간복잡도

* 전처리한 정보를 저장하면 `O(n)` 공간이 필요합니다.
* 정렬 결과를 새 리스트로 만들면 추가로 `O(n)` 공간이 필요할 수 있습니다.
* 메모리를 조금 더 쓰더라도 정렬 중 반복 계산을 줄이면 시간 측면에서 유리한 경우가 많습니다.

## 9. 예제로 이해하기

다른 예제로 참가자 목록을 정렬해봅시다.

조건:

1. 점수는 높은 순서
2. 점수가 같으면 페널티는 낮은 순서
3. 둘 다 같으면 이름순

입력 데이터:

```text
민수 80 10
지아 95 20
도윤 95 12
하린 80 8
```

정렬 기준:

```text
(-점수, 페널티, 이름)
```

처리 결과:

```text
도윤
지아
하린
민수
```

점수는 내림차순으로 해야 하므로 `-점수`를 사용합니다. 페널티와 이름은 오름차순이므로 그대로 둡니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 정렬 기준이 여러 개입니다.
* 오름차순과 내림차순 조건이 섞여 있습니다.
* 특정 그룹을 먼저 보내야 합니다.
* 문자열 일부, 확장자, 날짜, 점수 같은 가공된 값으로 정렬해야 합니다.
* "같으면 다음 기준으로 정렬"이라는 표현이 나옵니다.
* 정렬 전에 값을 나누거나 변환해야 합니다.
* 비교 함수 안에서 무거운 작업을 하면 시간초과가 날 수 있습니다.
* 기본 정렬 결과와 문제의 요구 순서가 다릅니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 기본 정렬과 커스텀 정렬

기본 정렬은 값 자체를 기준으로 정렬합니다. 커스텀 정렬은 값에서 필요한 기준을 뽑아낸 뒤 그 기준으로 정렬합니다.

### key 함수와 compare 함수

`key` 함수는 각 원소를 정렬 기준값으로 바꿉니다. compare 함수는 두 원소를 직접 비교합니다. Python에서는 가능하면 `key`를 쓰는 편이 단순하고 안전합니다.

### 전처리와 정렬 중 계산

정렬 중 비교는 많이 발생합니다. 따라서 파일명 분리, 확장자 확인, 날짜 변환처럼 반복 비용이 있는 작업은 정렬 전에 해두는 것이 좋습니다.

### 안정 정렬과 동점 처리

Python 정렬은 안정 정렬입니다. key가 같은 원소들은 기존 순서가 유지됩니다. 하지만 문제에서 동점 기준이 따로 있다면 key 튜플에 명확히 넣어야 합니다.

---

## 12. 자주 하는 실수

* 내림차순 기준에 음수 처리를 빼먹는 실수
* 문자열 내림차순을 숫자처럼 `-문자열`로 처리하려는 실수
* 동점 기준을 빠뜨리는 실수
* 정렬 기준의 우선순위를 잘못 배치하는 실수
* 비교 함수 안에서 문자열 분리나 탐색을 반복하는 실수
* `reverse=True`를 전체 기준에 적용해 일부 기준 방향까지 뒤집는 실수
* 전처리한 값과 원본 출력값을 혼동하는 실수
* 같은 기준값일 때 원래 순서가 유지되는 안정 정렬 성질을 고려하지 않는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

문제의 정렬 조건을 말로 풀어쓴 뒤, 가장 먼저 비교해야 하는 기준부터 순서대로 적어보세요.

### 2단계 힌트: 접근 힌트

각 데이터에서 정렬에 필요한 값만 미리 뽑아두세요. 여러 기준은 튜플로 묶으면 왼쪽 기준부터 차례대로 비교할 수 있습니다.

### 3단계 힌트: 구현 힌트

Python에서는 `list.sort(key=...)` 또는 `sorted(..., key=...)`를 사용하세요. 점수 내림차순은 `-score`, 일반 오름차순은 그대로 key에 넣으면 됩니다.

---

## 14. 언제 사용하면 좋은가

* 여러 조건으로 정렬해야 할 때 좋습니다.
* 파일명, 날짜, 점수처럼 원본에서 기준값을 뽑아야 할 때 적합합니다.
* 특정 그룹을 먼저 정렬해야 할 때 사용할 수 있습니다.
* 정렬 조건이 문제의 핵심인 코딩 테스트 문제에 자주 등장합니다.
* 비교 중 반복 계산이 많다면 전처리와 key 기반 정렬을 우선 고려해야 합니다.
* 단순 숫자 오름차순이면 기본 정렬만으로 충분합니다.

## 15. 요약 정리

* 커스텀 정렬의 목적은 문제에서 요구하는 기준대로 데이터를 배치하는 것입니다.
* 핵심 아이디어는 정렬 기준값을 직접 만들고, 여러 기준은 튜플로 표현하는 것입니다.
* 주요 도구는 `key` 함수, 튜플 정렬, 전처리입니다.
* 정렬 시간복잡도는 보통 `O(n log n)`이고, 기준 계산 비용도 함께 고려해야 합니다.
* 문제에서 다중 조건, 특정 그룹 우선, 가공된 기준이 보이면 커스텀 정렬을 떠올릴 수 있습니다.
* 초급자는 기준 순서, 오름차순/내림차순 혼합, 정렬 중 무거운 계산을 특히 주의해야 합니다.
