# [알고리즘] HashMap, 해시맵

## 1. 한 줄 요약

> 해시맵은 고유한 key로 value를 빠르게 저장하고 찾기 위한 key-value 형태의 자료구조입니다.

---

## 2. 선수 지식

- 배열
  - 인덱스를 이용해 값을 빠르게 찾는 자료구조입니다.

- key-value 구조
  - 이름표처럼 쓰는 `key`와 실제 데이터인 `value`를 한 쌍으로 저장하는 방식입니다.

- 해시 함수
  - key를 숫자 위치로 바꾸는 함수입니다. 이 위치를 이용해 값을 빠르게 찾습니다.

- 중복
  - 해시맵에서 key는 중복될 수 없습니다. 같은 key에 새 값을 넣으면 기존 value가 바뀝니다.

- 반복문
  - 여러 데이터를 읽으며 해시맵에 저장하거나 조회할 때 사용합니다.

- Python dict
  - Python에서 해시맵 역할을 하는 기본 자료구조입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

해시맵은 어떤 값이 있는지 빠르게 확인하거나, 특정 항목의 개수를 세야 할 때 사용합니다.

### 기존 방식의 문제

- 리스트에서 어떤 값이 있는지 찾으려면 앞에서부터 하나씩 확인해야 합니다.
- 데이터가 많아질수록 검색 시간이 길어집니다.
- 이름과 점수, 상품명과 가격처럼 서로 연결된 값을 관리하기 어렵습니다.

예를 들어 학생 10만 명의 점수를 저장해두고 특정 학생의 점수를 찾아야 한다고 해봅시다. 리스트에서 이름을 하나씩 비교하면 오래 걸립니다.

### 이 알고리즘을 사용하면

- key를 이용해 value를 평균적으로 매우 빠르게 찾을 수 있습니다.
- 등장 횟수, 중복 여부, 빠른 조회 문제를 간단하게 풀 수 있습니다.
- key와 value가 한 쌍으로 묶여 있어 데이터 의미가 분명해집니다.

입력 크기가 커졌을 때도 매번 전체를 훑지 않아도 되므로 효율적입니다.

---

## 4. 핵심 아이디어

해시맵은 key를 해시 함수에 넣어 저장 위치를 정합니다. 나중에 같은 key로 찾으면 같은 위치를 다시 계산해 value에 접근합니다.

### 쉬운 비유

도서관에서 책 제목만 보고 책장을 전부 뒤진다면 시간이 오래 걸립니다. 하지만 책마다 분류 번호가 있고, 그 번호가 꽂힌 위치를 알려준다면 바로 찾아갈 수 있습니다.

해시맵의 key는 책 제목처럼 찾고 싶은 대상이고, 해시 함수는 그 대상을 보관 위치로 바꾸는 규칙입니다.

### 직관적으로 이해하기

다음과 같은 데이터를 저장한다고 해봅시다.

- `"apple"` → `3`
- `"banana"` → `2`
- `"orange"` → `5`

이제 `"banana"`의 값을 알고 싶다면 리스트 전체를 확인할 필요가 없습니다. `"banana"`라는 key로 바로 value `2`를 꺼내면 됩니다.

해시맵에서 중요한 점은 key가 고유하다는 것입니다. `"banana"`에 다시 `7`을 저장하면 기존 `2`는 새 값으로 바뀝니다.

## 5. 동작 과정 살펴보기

### 예제 상황

가게에서 하루 동안 팔린 음료 이름이 순서대로 주어집니다. 각 음료가 몇 번 팔렸는지 세려고 합니다.

### 예제 입력

```text
7
tea
coffee
tea
juice
coffee
tea
milk
```

### 예제 출력

```text
coffee 2
juice 1
milk 1
tea 3
```

### 단계별 동작

1. 빈 해시맵을 만듭니다.
2. 첫 번째 음료 이름을 읽습니다.
3. 음료 이름이 key로 이미 있으면 value를 1 증가시킵니다.
4. 음료 이름이 없으면 value를 1로 새로 저장합니다.
5. 모든 입력을 처리할 때까지 반복합니다.
6. 마지막에 key와 value를 출력합니다.

출력을 보기 쉽게 하기 위해 key를 정렬해서 보여줄 수 있습니다. 해시맵 자체는 입력 순서나 정렬 순서를 보장하는 자료구조라고 생각하면 안 됩니다.

## 7. 기본 코드 템플릿

```python
def count_items(items):
    item_count = {}

    for item in items:
        if item in item_count:
            item_count[item] += 1
        else:
            item_count[item] = 1

    return item_count


item_total = int(input())
sold_items = []

for _ in range(item_total):
    sold_items.append(input().strip())

counts = count_items(sold_items)

for name in sorted(counts):
    print(name, counts[name])
```

### 코드 흐름 설명

* `item_count`는 Python의 `dict`이며 해시맵 역할을 합니다.
* 음료 이름을 key로 사용합니다.
* 판매 횟수를 value로 저장합니다.
* `item in item_count`는 해당 key가 이미 있는지 확인합니다.
* 이미 있으면 기존 value에 1을 더합니다.
* 없으면 새 key를 만들고 value를 1로 저장합니다.
* 결과 출력에서는 `sorted(counts)`를 사용해 key를 정렬했습니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - key 저장, 조회, 갱신은 평균적으로 `O(1)`입니다.

* 최악의 경우
  - 해시 충돌이 많이 발생하면 조회가 느려질 수 있습니다.
  - 일반적인 코딩 테스트에서는 평균 `O(1)`로 생각하고 풀이하는 경우가 많습니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 입력 데이터를 한 번씩 처리하므로 기본 처리 시간은 `O(N)`입니다.
  - 결과를 정렬해서 출력하면 key 개수를 `M`이라고 할 때 `O(M log M)`이 추가됩니다.

### 공간복잡도

* 서로 다른 key 개수만큼 해시맵 공간을 사용합니다.
* 서로 다른 항목이 `M`개라면 공간복잡도는 `O(M)`입니다.
* 모든 입력을 따로 리스트에 저장하지 않고 바로 세면 추가 공간을 줄일 수 있습니다.

## 9. 예제로 이해하기

앞에서 사용한 음료 예제와 다른 상황을 보겠습니다.

### 입력 데이터

```text
6
red
blue
red
green
blue
red
```

### 처리 과정

처음에는 해시맵이 비어 있습니다.

- `red` 입력 → `{"red": 1}`
- `blue` 입력 → `{"red": 1, "blue": 1}`
- `red` 입력 → `{"red": 2, "blue": 1}`
- `green` 입력 → `{"red": 2, "blue": 1, "green": 1}`
- `blue` 입력 → `{"red": 2, "blue": 2, "green": 1}`
- `red` 입력 → `{"red": 3, "blue": 2, "green": 1}`

### 중간 상태 변화

같은 key가 다시 등장하면 새로 추가하지 않고 기존 value를 바꿉니다.

### 최종 결과

```text
blue 2
green 1
red 3
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 값의 등장 횟수를 세야 합니다.
* 중복 여부를 빠르게 확인해야 합니다.
* 이름, 번호, 문자열 같은 key로 데이터를 찾아야 합니다.
* 두 목록을 비교해야 합니다.
* 어떤 값이 이미 나온 적 있는지 확인해야 합니다.
* key-value 관계가 자연스럽게 보입니다.
* 리스트로 매번 검색하면 시간초과가 날 것 같습니다.
* "빈도", "개수", "존재 여부", "매핑", "사전순 출력" 같은 표현이 나옵니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 해시맵과 리스트
  - 리스트는 위치 인덱스로 접근합니다.
  - 해시맵은 key로 접근합니다.

* 해시맵과 집합
  - 집합은 값의 존재 여부를 빠르게 확인합니다.
  - 해시맵은 key에 연결된 value까지 저장합니다.

* 해시맵과 정렬된 맵
  - 해시맵은 보통 순서를 보장하지 않습니다.
  - 정렬된 맵은 key 순서를 유지하지만 조회 비용이 다를 수 있습니다.

* key와 value
  - key는 고유해야 합니다.
  - value는 중복될 수 있습니다.

* 해시맵과 해시테이블
  - 해시테이블은 해싱을 이용한 자료구조 개념입니다.
  - 해시맵은 그 개념을 구현한 key-value 자료구조로 이해하면 됩니다.

---

## 12. 자주 하는 실수

* key가 없는데 바로 값을 꺼내려는 실수
* 같은 key를 넣으면 value가 덮어써진다는 점을 잊는 실수
* 해시맵의 출력 순서가 입력 순서와 같다고 생각하는 실수
* value로 key를 바로 찾을 수 있다고 착각하는 실수
* 빈도 세기에서 처음 등장한 key를 0 또는 1로 초기화하지 않는 실수
* 리스트 검색을 반복해서 `O(N^2)` 풀이를 만드는 실수
* 정렬된 결과가 필요한데 정렬하지 않고 출력하는 실수
* 변경 가능한 객체를 key로 쓰려는 실수
* 서로 다른 key가 같은 value를 가질 수 있다는 점을 놓치는 실수

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 데이터가 많고 빠른 조회가 필요한 경우

* 문제 유형
  - 빈도 세기, 중복 확인, 문자열 개수 세기, 이름과 점수 매핑, 두 배열 비교

* 자주 등장하는 표현
  - "몇 번 등장", "존재하는지 확인", "key에 해당하는 값", "중복 제거", "빈도"

* 적합한 자료구조
  - Python에서는 `dict`, Java에서는 `HashMap`, JavaScript에서는 `Map` 또는 객체를 사용할 수 있습니다.

* 사용하면 안 되는 경우
  - key 순서가 항상 정렬되어 있어야 하는 경우
  - 범위가 작고 배열 인덱스로 바로 처리하는 편이 더 단순한 경우
  - 모든 원소를 순서대로 유지하며 처리해야 하는 경우

## 15. 요약 정리

* 해시맵의 목적
  - key를 이용해 value를 빠르게 저장, 조회, 갱신하는 것입니다.

* 핵심 아이디어
  - key를 해시 함수로 위치에 연결하고, 그 위치를 이용해 빠르게 접근합니다.

* 주요 자료구조
  - Python의 `dict`, Java의 `HashMap`, JavaScript의 `Map`이 대표적입니다.

* 시간복잡도
  - 평균적으로 저장, 조회, 삭제가 `O(1)`입니다.

* 문제에서 떠올리는 신호
  - 빈도 세기, 존재 여부, key-value 매핑이 보이면 해시맵을 떠올릴 수 있습니다.

* 초급자가 주의할 점
  - key는 중복되지 않고, 해시맵은 기본적으로 순서를 보장하지 않는다고 생각해야 합니다.
