# [알고리즘] 버블 정렬

## 1. 한 줄 요약

> 버블 정렬은 이웃한 두 값을 비교해 순서가 틀리면 바꾸는 과정을 반복하여 큰 값을 뒤쪽부터 차례로 고정하는 정렬 알고리즘입니다.

---

## 2. 선수 지식

- 배열 또는 리스트
  - 정렬할 값을 순서대로 저장하는 자료구조입니다.

- 반복문
  - 인접한 값을 여러 번 비교하기 위해 사용합니다.

- 조건문
  - 두 값의 순서가 잘못되었는지 판단할 때 사용합니다.

- swap
  - 두 원소의 위치를 서로 바꾸는 동작입니다.

- 시간복잡도
  - 입력 개수가 늘어날 때 비교 횟수가 얼마나 증가하는지 판단할 때 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

버블 정렬은 정렬의 기본 원리를 이해하기 위해 자주 배우는 알고리즘입니다. 실제 대규모 데이터 정렬에는 효율이 낮지만, 인접한 값 비교와 교환이라는 정렬의 핵심 동작을 익히기 좋습니다.

### 기존 방식의 문제

- 아무 규칙 없이 값을 찾으면 데이터가 정리되지 않습니다.
- 모든 값을 매번 직접 비교해서 가장 작은 값을 찾는 방식도 가능하지만, 정렬 과정의 흐름을 이해하기 어렵습니다.
- 정렬 알고리즘을 처음 배울 때 복잡한 분할이나 재귀가 들어가면 진입 장벽이 높습니다.

예를 들어 `[5, 2, 4, 1]`을 오름차순으로 만들고 싶다면, 이웃한 값끼리 비교해 큰 값을 오른쪽으로 보내는 방식만으로도 정렬할 수 있습니다.

### 이 알고리즘을 사용하면

- 구현이 매우 단순합니다.
- 한 번의 큰 반복이 끝날 때마다 가장 큰 값이 오른쪽 끝에 고정됩니다.
- 작은 입력이나 정렬 학습용 예제에 적합합니다.
- 이미 정렬된 배열이라면 조기 종료 최적화로 빠르게 끝낼 수 있습니다.

다만 평균적으로 느리기 때문에 큰 데이터에는 Python의 `sort()`나 더 효율적인 정렬 알고리즘을 사용하는 편이 좋습니다.

## 4. 핵심 아이디어

버블 정렬의 핵심은 "옆 사람과 비교해서 큰 사람이 오른쪽으로 이동한다"는 것입니다.

오름차순 정렬에서는 왼쪽 값이 오른쪽 값보다 크면 두 값을 바꿉니다. 이 과정을 왼쪽부터 오른쪽까지 반복하면 가장 큰 값이 맨 오른쪽으로 이동합니다.

### 쉬운 비유

키 순서대로 줄을 세운다고 생각해봅시다. 바로 옆 사람끼리만 비교해서 키가 큰 사람이 오른쪽으로 가도록 자리를 바꿉니다.

한 번 줄 끝까지 비교하면 가장 키 큰 사람이 맨 오른쪽에 서게 됩니다. 다음에는 그 사람을 제외하고 나머지 사람들끼리 같은 작업을 반복합니다.

### 직관적으로 이해하기

배열 `[4, 1, 3, 2]`를 오름차순으로 정렬해봅시다.

첫 번째 큰 반복에서 다음 비교가 일어납니다.

- `4`와 `1` 비교 → 바꿈 → `[1, 4, 3, 2]`
- `4`와 `3` 비교 → 바꿈 → `[1, 3, 4, 2]`
- `4`와 `2` 비교 → 바꿈 → `[1, 3, 2, 4]`

가장 큰 값 `4`가 맨 뒤에 고정되었습니다. 이후에는 마지막 값을 제외하고 같은 과정을 반복하면 됩니다.

## 5. 동작 과정 살펴보기

### 예제 상황

숫자 카드 `6, 2, 5, 1`을 오름차순으로 정렬합니다.

### 예제 입력

```text
4
6 2 5 1
```

### 예제 출력

```text
1 2 5 6
```

### 단계별 동작

1. 배열의 첫 번째 값부터 인접한 두 값을 비교합니다.
2. 왼쪽 값이 더 크면 두 값을 교환합니다.
3. 배열 끝까지 비교하면 가장 큰 값이 맨 뒤에 고정됩니다.
4. 다음 반복에서는 이미 고정된 맨 뒤 값을 제외합니다.
5. 교환이 더 이상 일어나지 않으면 정렬이 끝났다고 판단할 수 있습니다.
6. 정렬된 배열을 반환합니다.

첫 번째 반복의 변화는 다음과 같습니다.

- `[6, 2, 5, 1]`
- `[2, 6, 5, 1]`
- `[2, 5, 6, 1]`
- `[2, 5, 1, 6]`

## 7. 기본 코드 템플릿

```python
def bubble_sort(numbers):
    sorted_numbers = numbers[:]
    length = len(sorted_numbers)

    for end in range(length - 1, 0, -1):
        changed = False

        for index in range(end):
            if sorted_numbers[index] > sorted_numbers[index + 1]:
                sorted_numbers[index], sorted_numbers[index + 1] = (
                    sorted_numbers[index + 1],
                    sorted_numbers[index],
                )
                changed = True

        if not changed:
            break

    return sorted_numbers


number_count = int(input())
numbers = list(map(int, input().split()))

answer = bubble_sort(numbers)
print(*answer)
```

### 코드 흐름 설명

* `sorted_numbers`는 원본 리스트를 복사한 정렬 대상입니다.
* 바깥 반복문의 `end`는 이번에 비교할 마지막 위치를 의미합니다.
* 안쪽 반복문은 `0`부터 `end - 1`까지 인접한 두 값을 비교합니다.
* 왼쪽 값이 오른쪽 값보다 크면 두 값을 교환합니다.
* 한 바퀴가 끝나면 가장 큰 값이 `end` 위치에 고정됩니다.
* `changed`는 교환이 한 번이라도 있었는지 기록합니다.
* 교환이 없으면 이미 정렬된 상태이므로 반복을 멈춥니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - 대부분의 원소를 여러 번 비교하므로 `O(N^2)`입니다.

* 최악의 경우
  - 배열이 거꾸로 정렬되어 있으면 비교와 교환이 많이 발생합니다.
  - 이때도 시간복잡도는 `O(N^2)`입니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 원소가 2배가 되면 비교 횟수는 대략 4배 가까이 늘어납니다.
  - 큰 데이터에는 적합하지 않습니다.

이미 정렬된 배열에 조기 종료 최적화를 넣으면 한 번만 확인하고 끝날 수 있어 최선의 경우 `O(N)`이 됩니다.

### 공간복잡도

* 원본 리스트를 직접 바꾸면 추가 공간은 `O(1)`입니다.
* 위 코드처럼 원본 보존을 위해 복사본을 만들면 `O(N)` 공간을 추가로 사용합니다.
* 알고리즘 자체는 제자리 정렬 방식으로 구현할 수 있습니다.

## 9. 예제로 이해하기

앞에서 사용한 예제와 다른 배열을 보겠습니다.

### 입력 데이터

```text
5
3 4 1 5 2
```

### 처리 과정

첫 번째 반복에서는 가장 큰 값 `5`가 맨 뒤로 이동합니다.

- `3`과 `4` 비교 → 그대로
- `4`와 `1` 비교 → 교환
- `4`와 `5` 비교 → 그대로
- `5`와 `2` 비교 → 교환

배열은 `[3, 1, 4, 2, 5]`가 됩니다.

두 번째 반복에서는 남은 구간 `[3, 1, 4, 2]`에서 가장 큰 값 `4`가 뒤쪽으로 이동합니다.

- `3`과 `1` 비교 → 교환
- `3`과 `4` 비교 → 그대로
- `4`와 `2` 비교 → 교환

배열은 `[1, 3, 2, 4, 5]`가 됩니다.

### 중간 상태 변화

반복이 진행될수록 오른쪽 끝부터 정렬된 값이 하나씩 늘어납니다.

### 최종 결과

```text
1 2 3 4 5
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 정렬 알고리즘의 기본 동작을 설명해야 합니다.
* 인접한 두 값을 비교하고 교환하는 조건이 주어집니다.
* 데이터 크기가 작습니다.
* 정렬 과정의 중간 상태를 출력해야 합니다.
* 안정 정렬이 필요한 간단한 예제입니다.
* 이미 거의 정렬된 데이터에 대해 조기 종료를 활용할 수 있습니다.
* 효율보다 구현 단순성이 더 중요한 학습용 문제입니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 버블 정렬과 선택 정렬
  - 버블 정렬은 인접한 값을 계속 비교해 큰 값을 뒤로 보냅니다.
  - 선택 정렬은 남은 구간에서 최솟값 또는 최댓값을 찾아 한 번에 위치를 정합니다.

* 버블 정렬과 삽입 정렬
  - 버블 정렬은 큰 값을 뒤쪽으로 밀어냅니다.
  - 삽입 정렬은 현재 값을 앞쪽의 알맞은 위치에 끼워 넣습니다.

* 버블 정렬과 퀵 정렬
  - 버블 정렬은 구현이 쉽지만 느립니다.
  - 퀵 정렬은 평균적으로 훨씬 빠르지만 분할 과정이 필요합니다.

* 안정 정렬과 불안정 정렬
  - 버블 정렬은 같은 값끼리는 바꾸지 않도록 구현하면 안정 정렬입니다.
  - 같은 값의 상대적 순서를 유지해야 할 때 안정성이 중요합니다.

## 12. 자주 하는 실수

* 안쪽 반복문의 범위를 `end`까지 잘못 잡아 인덱스 오류를 내는 실수
* `numbers[index + 1]` 접근 범위를 고려하지 않는 실수
* 이미 정렬된 뒤쪽 구간까지 계속 비교하는 실수
* 오름차순과 내림차순의 비교 부등호를 반대로 쓰는 실수
* 같은 값일 때도 교환해서 안정성을 깨는 실수
* 조기 종료용 변수를 반복마다 초기화하지 않는 실수
* 원본 리스트를 바꿔도 되는지 확인하지 않고 직접 수정하는 실수
* 큰 입력에 버블 정렬을 사용해 시간초과가 나는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

정렬되지 않은 구간에서 인접한 두 값을 비교해보세요. 오름차순이라면 큰 값을 오른쪽으로 보내는 방식입니다.

### 2단계 힌트: 접근 힌트

한 바퀴 순회가 끝나면 가장 큰 값 하나가 맨 뒤에 고정됩니다. 다음 반복에서는 그 위치를 제외하고 비교하면 됩니다.

### 3단계 힌트: 구현 힌트

안쪽 반복문은 `index`와 `index + 1`을 비교하므로 마지막 접근 범위를 조심하세요. 한 바퀴 동안 교환이 없었다면 `break`로 종료할 수 있습니다.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 데이터 수가 작거나 정렬 과정을 보여주는 것이 중요한 경우

* 문제 유형
  - 정렬 기본 구현, 인접 원소 교환, 정렬 중간 상태 출력

* 자주 등장하는 표현
  - "인접한 두 원소", "교환", "한 바퀴마다 가장 큰 값이 뒤로 이동", "버블"

* 적합한 자료구조
  - 배열 또는 리스트

* 사용하면 안 되는 경우
  - 입력 크기가 큰 정렬 문제
  - 빠른 정렬이 필요한 실전 문제
  - `O(N log N)` 정렬이 요구되는 문제

## 15. 요약 정리

* 버블 정렬의 목적
  - 인접한 두 값을 비교하고 교환하면서 배열을 정렬하는 것입니다.

* 핵심 아이디어
  - 한 바퀴마다 가장 큰 값이 오른쪽 끝에 고정됩니다.

* 주요 자료구조
  - 리스트 또는 배열을 사용합니다.

* 시간복잡도
  - 평균과 최악은 `O(N^2)`입니다.
  - 조기 종료를 사용하면 이미 정렬된 경우 `O(N)`이 될 수 있습니다.

* 문제에서 떠올리는 신호
  - 인접 원소 비교, 교환, 정렬 과정 추적이 핵심인 문제입니다.

* 초급자가 주의할 점
  - 안쪽 반복문의 범위와 비교 부등호를 정확히 설정해야 합니다.
