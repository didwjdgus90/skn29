# [알고리즘] 큰 수 만들기

## 1. 한 줄 요약

> 큰 수 만들기는 숫자 문자열에서 정해진 개수만큼 숫자를 지워, 앞자리부터 최대한 큰 숫자가 오도록 만드는 그리디 문제입니다.

---

## 2. 선수 지식

- 문자열 순회: 숫자가 문자열로 주어지므로 왼쪽부터 한 글자씩 확인합니다.
- 스택: 마지막에 넣은 값을 먼저 꺼낼 수 있는 자료구조입니다.
- 그리디: 현재 위치에서 더 좋은 선택이 보이면 바로 이전 선택을 바꾸는 방식입니다.
- 사전식 비교가 아닌 숫자 자리 비교: 전체 숫자의 크기는 앞자리 숫자가 클수록 커집니다.
- 시간복잡도: 입력 길이가 최대한 클 수 있으므로 중첩 반복문을 조심해야 합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

이 알고리즘은 "순서를 유지한 채 일부 숫자를 제거해서 가장 큰 수를 만들라"는 문제를 해결합니다.

### 기존 방식의 문제

- 모든 제거 조합을 만들면 경우의 수가 너무 많습니다.
- 숫자의 길이가 길어지면 조합을 직접 비교하는 방식은 사용할 수 없습니다.
- 단순히 작은 숫자 `k`개를 지우는 것도 정답이 아닙니다. 숫자는 위치가 중요하기 때문입니다.

예를 들어 `31592`에서 2개를 지운다고 할 때, 작은 숫자 `1`과 `2`만 지우면 `359`가 됩니다. 하지만 더 큰 답을 만들려면 앞자리 배치를 함께 생각해야 합니다.

### 이 알고리즘을 사용하면

- 왼쪽부터 한 번만 훑으면서 답 후보를 만들 수 있습니다.
- 새로 들어온 숫자가 이전 숫자보다 크면, 앞자리의 작은 숫자를 제거해 더 큰 수를 만들 수 있습니다.
- 각 숫자는 스택에 한 번 들어가고 많아야 한 번 빠지므로 긴 입력도 처리할 수 있습니다.

---

## 4. 핵심 아이디어

큰 수를 만들 때 가장 중요한 것은 앞자리입니다.

앞자리에 작은 숫자가 남아 있으면 뒤에 큰 숫자가 와도 전체 수의 크기를 크게 만들기 어렵습니다. 그래서 새로운 숫자를 볼 때마다 다음 질문을 합니다.

- 아직 지울 수 있는 횟수가 남았는가?
- 지금 숫자가 바로 앞에 둔 숫자보다 큰가?
- 그렇다면 앞의 작은 숫자를 지우는 것이 더 유리한가?

이 조건이 맞으면 스택의 마지막 숫자를 제거합니다. 그리고 현재 숫자를 넣습니다.

### 쉬운 비유

대표 사진을 고른다고 생각해 봅시다. 앞쪽에 배치된 사진일수록 더 먼저 보입니다. 새로 확인한 사진이 바로 앞 사진보다 훨씬 좋고, 아직 사진을 뺄 수 있는 기회가 남아 있다면 앞 사진을 빼고 새 사진을 앞으로 살리는 편이 좋습니다.

큰 수 만들기도 비슷합니다. 앞자리는 눈에 가장 먼저 보이는 자리라서, 가능한 한 큰 숫자를 남기는 것이 중요합니다.

### 직관적으로 이해하기

숫자 `28173`에서 2개를 지운다고 해 봅시다.

왼쪽부터 보면서 `2`를 먼저 둡니다. 다음 숫자 `8`은 `2`보다 큽니다. 아직 숫자를 지울 수 있으므로 `2`를 지우고 `8`을 앞에 둡니다.

이 선택은 자연스럽습니다. 같은 길이의 숫자라면 첫 자리가 `2`인 수보다 첫 자리가 `8`인 수가 무조건 큽니다.

## 5. 동작 과정 살펴보기

### 예제 상황

숫자 문자열 `528341`에서 숫자 3개를 제거해 가장 큰 수를 만들겠습니다.

### 예제 입력

```text
number = "528341"
k = 3
```

### 예제 출력

```text
"841"
```

### 단계별 동작

1. 빈 스택을 준비합니다.
2. `5`를 넣습니다.
3. `2`는 `5`보다 작으므로 그대로 넣습니다. 스택은 `5, 2`입니다.
4. `8`은 앞의 `2`보다 크므로 `2`를 제거합니다.
5. `8`은 다시 앞의 `5`보다 크므로 `5`도 제거합니다.
6. `8`을 넣습니다. 지금까지 2개를 제거했습니다.
7. `3`은 `8`보다 작으므로 넣습니다.
8. `4`는 앞의 `3`보다 크고 아직 1개를 더 지울 수 있으므로 `3`을 제거합니다.
9. `4`, `1`을 차례대로 넣습니다.
10. 최종 스택은 `8, 4, 1`이므로 답은 `"841"`입니다.

## 7. 기본 코드 템플릿

```python
def make_largest_number(number, remove_count):
    digits = []
    remaining_remove = remove_count

    for current_digit in number:
        while (
            remaining_remove > 0
            and digits
            and digits[-1] < current_digit
        ):
            digits.pop()
            remaining_remove -= 1

        digits.append(current_digit)

    if remaining_remove > 0:
        digits = digits[:-remaining_remove]

    return "".join(digits)


if __name__ == "__main__":
    print(make_largest_number("528341", 3))
    print(make_largest_number("765432", 2))
    print(make_largest_number("392917", 2))
```

### 코드 흐름 설명

* `digits`는 현재까지 남기기로 한 숫자들을 담는 스택입니다.
* `remaining_remove`는 앞으로 더 지울 수 있는 숫자의 개수입니다.
* 새 숫자 `current_digit`이 스택 마지막 숫자보다 크면, 작은 앞자리 숫자를 제거합니다.
* 제거는 `while`로 반복합니다. 새 숫자가 여러 개의 작은 앞자리 숫자를 밀어낼 수 있기 때문입니다.
* 모든 숫자를 확인했는데 삭제 횟수가 남았다면 뒤쪽 숫자를 제거합니다.
* 뒤쪽을 제거하는 이유는 숫자가 내림차순처럼 이어져 앞에서 제거할 기회가 없었다는 뜻이기 때문입니다.
* 마지막에는 스택에 남은 숫자를 문자열로 합칩니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 각 숫자는 스택에 한 번 들어갑니다.
* 각 숫자는 많아야 한 번 제거됩니다.
* 따라서 전체 시간복잡도는 `O(n)`입니다.
* 여기서 `n`은 숫자 문자열의 길이입니다.

겉으로는 `while`이 있어서 느려 보일 수 있습니다. 하지만 같은 숫자가 여러 번 제거되는 일은 없습니다. 그래서 전체적으로는 한 번 훑는 것과 비슷하게 동작합니다.

### 공간복잡도

* 스택에 최대 `n`개의 숫자가 들어갈 수 있습니다.
* 따라서 공간복잡도는 `O(n)`입니다.

## 9. 예제로 이해하기

이번에는 `647235`에서 2개를 제거해 보겠습니다.

입력 데이터:

```text
number = "647235"
k = 2
```

처리 과정:

1. `6`을 넣습니다. 스택: `6`
2. `4`를 넣습니다. 스택: `6, 4`
3. `7`이 들어옵니다. `4`보다 크므로 `4`를 제거합니다.
4. `7`은 `6`보다 크므로 `6`도 제거합니다.
5. 제거 횟수 2개를 모두 사용했으므로 더 이상 지울 수 없습니다.
6. 남은 숫자 `7, 2, 3, 5`를 순서대로 유지합니다.

최종 결과:

```text
"7235"
```

여기서 중요한 판단은 `7`을 만났을 때입니다. 앞의 `6`, `4`를 남기면 첫 자리가 작아집니다. 삭제 기회가 남아 있으므로 작은 앞자리 숫자를 제거하고 `7`을 앞으로 당기는 것이 더 좋습니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 숫자 문자열에서 일부 자릿수를 제거하라고 합니다.
* 남은 숫자의 상대적인 순서는 유지해야 합니다.
* 가장 큰 수 또는 가장 작은 수를 만들라고 합니다.
* 앞자리 숫자가 결과 크기에 큰 영향을 줍니다.
* 입력 길이가 매우 커서 조합을 만들 수 없습니다.
* 이전에 선택한 숫자를 조건에 따라 되돌려야 합니다.
* 스택의 마지막 값과 현재 값을 비교하는 흐름이 자연스럽습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 단순 정렬과의 차이

이 문제는 숫자를 마음대로 재배열할 수 없습니다. 원래 문자열에서 남긴 숫자들의 순서는 그대로 유지해야 합니다.

그래서 큰 숫자부터 정렬하면 안 됩니다.

### 조합 완전탐색과의 차이

조합으로 남길 자리를 모두 골라 비교할 수도 있습니다. 하지만 숫자 길이가 크면 경우의 수가 너무 많습니다.

스택 그리디는 같은 목적을 훨씬 빠르게 처리합니다.

### 일반 그리디와의 차이

현재 숫자를 무조건 선택하는 것이 아니라, 이전에 선택했던 작은 숫자를 제거할 수 있습니다.

즉, 그리디 선택을 하되 스택을 이용해 직전 선택들을 조정하는 방식입니다.

### 가장 작은 수 만들기와의 차이

가장 큰 수를 만들 때는 앞의 작은 숫자를 제거합니다. 가장 작은 수를 만들 때는 반대로 앞의 큰 숫자를 제거하는 방향이 됩니다.

## 12. 자주 하는 실수

* 숫자를 정렬해서 순서를 바꿔 버립니다.
* 스택 마지막 숫자와 현재 숫자를 비교하지 않고 전체에서 작은 숫자만 제거합니다.
* `while` 대신 `if`만 사용해 여러 개의 작은 숫자를 제거하지 못합니다.
* 삭제 횟수가 남았을 때 뒤에서 제거하는 처리를 빠뜨립니다.
* `digits[-1]`를 확인하기 전에 스택이 비어 있는지 검사하지 않습니다.
* 제거 횟수를 감소시키지 않아 무한 반복이나 잘못된 결과가 생깁니다.
* 결과 길이가 `len(number) - k`가 되어야 한다는 점을 놓칩니다.
* 숫자가 내림차순인 경우를 따로 생각하지 않아 남은 삭제 횟수 처리가 틀립니다.

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

큰 수를 만들려면 앞자리가 중요합니다. 현재 숫자가 앞에 있는 숫자보다 크다면, 앞의 작은 숫자를 지우는 것이 유리할 수 있습니다.

### 2단계 힌트: 접근 힌트

왼쪽부터 숫자를 보면서 답 후보를 스택에 쌓아 보세요. 새 숫자가 스택의 마지막 숫자보다 크고 아직 지울 수 있다면, 마지막 숫자를 제거합니다.

### 3단계 힌트: 구현 힌트

`while 남은삭제횟수 > 0 and 스택이비지않음 and 스택마지막 < 현재숫자` 조건으로 pop을 반복하세요. 모든 숫자를 처리한 뒤에도 삭제 횟수가 남으면 스택 뒤쪽을 잘라야 합니다.

## 14. 언제 사용하면 좋은가

* 입력 조건: 숫자 문자열의 길이가 커서 모든 경우를 만들 수 없을 때 좋습니다.
* 문제 유형: 자릿수를 제거해 가장 큰 수 또는 가장 작은 수를 만드는 문제에 적합합니다.
* 자주 등장하는 표현: "k개 제거", "가장 큰 숫자", "순서를 유지", "문자열 형태의 숫자"가 단서입니다.
* 적합한 자료구조: 마지막 선택을 빠르게 되돌릴 수 있는 스택이 적합합니다.
* 사용하면 안 되는 경우: 숫자를 재배열할 수 있는 문제라면 정렬이 더 직접적일 수 있습니다. 또한 각 자리 선택에 복잡한 추가 조건이 있으면 DP나 탐색이 필요할 수 있습니다.

## 15. 요약 정리

* 큰 수 만들기는 앞자리를 최대한 크게 만드는 그리디 문제입니다.
* 숫자의 기존 순서는 유지해야 하므로 정렬로 풀 수 없습니다.
* 스택에 숫자를 쌓다가, 현재 숫자가 더 크면 앞의 작은 숫자를 제거합니다.
* 삭제 횟수가 남으면 뒤쪽 숫자를 제거합니다.
* 시간복잡도는 `O(n)`, 공간복잡도는 `O(n)`입니다.
* 핵심 조건은 `남은 삭제 횟수`, `스택 존재 여부`, `스택 마지막 숫자 < 현재 숫자`입니다.
* 초급자는 `while` 반복, 남은 삭제 횟수 처리, 결과 길이를 특히 주의해야 합니다.
