# [알고리즘] 완전탐색 개념

## 1. 한 줄 요약

> 완전탐색은 가능한 답 후보를 빠짐없이 만들어 보고, 각 후보가 조건을 만족하는지 확인하는 가장 기본적인 문제 해결 방법입니다.

---

## 2. 선수 지식

- 반복문
  - 정해진 범위의 값을 하나씩 확인할 때 사용합니다.

- 조건문
  - 현재 후보가 문제의 조건을 만족하는지 판단할 때 필요합니다.

- 리스트
  - 입력값, 선택한 값, 중간 후보를 저장할 때 자주 사용합니다.

- 재귀 함수
  - 선택을 여러 단계로 이어 가야 할 때 사용합니다. 함수가 자기 자신을 다시 호출하는 구조입니다.

- 순열과 조합
  - 순서가 중요한 선택은 순열, 순서가 중요하지 않은 선택은 조합으로 생각합니다.

- 시간복잡도
  - 모든 후보를 확인해도 제한 시간 안에 끝나는지 판단할 때 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

완전탐색은 "가능한 경우가 많아 보이지만, 실제 입력 크기는 작아서 전부 확인할 수 있는 문제"에 잘 맞습니다.

### 기존 방식의 문제

- 감으로 규칙을 찾으려 하면 예외를 놓치기 쉽습니다.
- 복잡한 알고리즘을 억지로 적용하면 구현이 더 어려워질 수 있습니다.
- 정답 후보가 여러 개일 때 일부 후보만 확인하면 틀릴 가능성이 큽니다.

예를 들어 숫자 카드 5장 중 2장을 골라 합이 10이 되는 경우를 찾는다고 해봅시다. 카드가 5장뿐이라면 모든 두 장 조합을 확인해도 부담이 작습니다.

### 이 알고리즘을 사용하면

- 가능한 답을 전부 검사하므로 조건에 맞는 답을 놓치지 않습니다.
- 입력 크기가 작을 때는 구현이 단순하고 안정적입니다.
- 문제의 구조를 파악하는 첫 번째 풀이로 사용하기 좋습니다.

다만 후보 수가 너무 많아지면 시간이 급격히 늘어납니다. 그래서 완전탐색을 쓰기 전에는 "후보가 몇 개나 생기는가"를 먼저 계산해야 합니다.

---

## 4. 핵심 아이디어

완전탐색의 핵심은 세 단계입니다.

1. 가능한 후보를 만든다.
2. 후보가 조건에 맞는지 검사한다.
3. 조건에 맞으면 정답에 반영한다.

### 쉬운 비유

책상 위에 여러 개의 열쇠가 있고, 그중 하나만 서랍을 열 수 있다고 해봅시다. 열쇠가 5개라면 가장 단순한 방법은 하나씩 꽂아 보는 것입니다.

열쇠가 5개일 때는 이 방법이 충분히 빠릅니다. 하지만 열쇠가 백만 개라면 전부 꽂아 보는 방식은 현실적이지 않습니다.

완전탐색도 같습니다. 후보가 적으면 확실하고 좋지만, 후보가 너무 많으면 다른 방법을 찾아야 합니다.

### 직관적으로 이해하기

숫자 `[2, 4, 5, 7]` 중에서 두 수를 골라 합이 `9`가 되는지 확인해봅시다.

- `2 + 4 = 6`
- `2 + 5 = 7`
- `2 + 7 = 9`
- `4 + 5 = 9`
- `4 + 7 = 11`
- `5 + 7 = 12`

모든 쌍을 확인했기 때문에 `9`를 만드는 쌍이 있다는 사실을 확신할 수 있습니다.

## 5. 동작 과정 살펴보기

### 예제 상황

동아리에서 간식 4개 중 3개를 골라야 합니다. 각 간식의 가격이 주어지고, 총 가격이 예산을 넘지 않으면서 최대한 비싸게 고르고 싶습니다.

### 예제 입력

```text
4 10
2 3 5 6
```

첫 줄의 `4`는 간식 개수, `10`은 예산입니다. 둘째 줄은 각 간식의 가격입니다.

### 예제 출력

```text
10
```

`2, 3, 5`를 고르면 합이 `10`입니다. 예산을 넘지 않는 선택 중 가장 큰 합입니다.

### 단계별 동작

1. 간식 가격 목록 `[2, 3, 5, 6]`을 확인합니다.
2. 3개를 고르는 모든 후보를 만듭니다.
3. 각 후보의 합을 계산합니다.
4. 합이 예산 `10` 이하인지 확인합니다.
5. 조건을 만족하면 지금까지의 가장 큰 합과 비교합니다.
6. 모든 후보를 확인한 뒤 가장 큰 합을 출력합니다.

확인하는 후보는 다음과 같습니다.

- `2, 3, 5` → 합 `10`, 가능
- `2, 3, 6` → 합 `11`, 불가능
- `2, 5, 6` → 합 `13`, 불가능
- `3, 5, 6` → 합 `14`, 불가능

## 7. 기본 코드 템플릿

기본 언어는 Python입니다. 아래 코드는 여러 가격 중 3개를 골라 예산을 넘지 않는 최대 합을 구합니다.

```python
from itertools import combinations


def find_best_total(prices, limit):
    best_total = 0

    for selected_prices in combinations(prices, 3):
        current_total = sum(selected_prices)

        if current_total <= limit and current_total > best_total:
            best_total = current_total

    return best_total


item_count, budget = map(int, input().split())
snack_prices = list(map(int, input().split()))

answer = find_best_total(snack_prices, budget)
print(answer)
```

### 코드 흐름 설명

* `prices` 리스트에 후보가 되는 값을 저장합니다.
* `combinations(prices, 3)`은 3개를 고르는 모든 경우를 만들어 줍니다.
* 반복문은 각 후보를 하나씩 꺼내 합을 계산합니다.
* 조건문은 예산을 넘지 않는 후보만 통과시킵니다.
* `best_total`은 지금까지 발견한 가장 좋은 값을 저장합니다.
* 모든 후보를 확인한 뒤 `best_total`이 최종 정답이 됩니다.

## 8. 시간복잡도와 공간복잡도

완전탐색은 후보를 얼마나 많이 만드는지가 가장 중요합니다.

### 시간복잡도

* 평균적인 경우
  - 후보를 거의 모두 확인해야 하므로 후보 개수에 비례합니다.

* 최악의 경우
  - 조건에 맞는 답이 마지막에 나오거나 아예 없으면 모든 후보를 확인합니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 2중 반복문은 보통 `O(N^2)`입니다.
  - 3중 반복문은 보통 `O(N^3)`입니다.
  - 부분집합 전체 탐색은 보통 `O(2^N)`입니다.
  - 순열 전체 탐색은 보통 `O(N!)`입니다.

간단한 판단 기준은 다음과 같습니다.

- `N`이 10 안팎이고 순열을 모두 확인해야 한다면 가능할 수 있습니다.
- `N`이 20 안팎이고 부분집합을 모두 확인해야 한다면 가능할 수 있습니다.
- `N`이 1,000 정도라면 `O(N^2)`도 상황에 따라 가능할 수 있습니다.
- `N`이 100,000 이상이면 단순 완전탐색은 대부분 어렵습니다.

### 공간복잡도

* 반복문만 사용하면 추가 메모리는 보통 작습니다.
* 재귀를 사용하면 호출 깊이만큼 스택 메모리를 사용합니다.
* 후보 목록을 한 번에 리스트로 저장하면 후보 개수만큼 메모리를 더 사용합니다.
* 그래프나 격자 문제에서는 방문 배열, 큐, 스택 등이 추가로 필요할 수 있습니다.

완전탐색에서는 후보를 모두 저장하기보다 하나씩 만들고 바로 검사하는 방식이 메모리를 아끼는 데 좋습니다.

## 9. 예제로 이해하기

이번에는 숫자 5개 중 일부를 골라 합이 목표값이 되는 경우가 있는지 확인해봅시다.

### 입력 데이터

```text
5 8
1 2 4 6 9
```

목표는 일부 숫자를 골라 합이 `8`이 되는지 확인하는 것입니다.

### 처리 과정

각 숫자는 두 가지 선택지를 가집니다.

- 고른다.
- 고르지 않는다.

따라서 숫자가 5개이면 후보는 최대 `2^5 = 32`개입니다.

중간 상태를 일부만 보면 다음과 같습니다.

- `1`만 선택 → 합 `1`
- `1, 2` 선택 → 합 `3`
- `1, 2, 4` 선택 → 합 `7`
- `2, 6` 선택 → 합 `8`

`2`와 `6`을 고른 후보에서 목표 합 `8`을 만들 수 있습니다.

### 최종 결과

```text
YES
```

이 예제에서 중요한 점은 숫자 하나마다 "선택한다 / 선택하지 않는다"라는 분기를 만든다는 것입니다. 이런 구조는 재귀나 비트마스크로 구현하기 좋습니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 입력 크기가 작습니다.
* "가능한 모든 경우"를 확인하라는 느낌이 있습니다.
* "몇 개를 고른다", "순서를 정한다", "배치한다" 같은 표현이 나옵니다.
* 완전탐색으로 계산한 후보 수가 제한 시간 안에 들어올 것 같습니다.
* 정렬, 그리디, DP 규칙이 바로 보이지 않습니다.
* 부분집합, 순열, 조합, 중복 선택이 자연스럽게 떠오릅니다.
* 격자에서 모든 시작점이나 모든 방향을 확인해야 합니다.
* 답이 존재하는지 확인하거나, 가능한 후보 중 최댓값 또는 최솟값을 찾아야 합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 완전탐색과 백트래킹
  - 완전탐색은 모든 후보를 확인합니다.
  - 백트래킹은 후보를 확인하다가 더 볼 필요가 없는 경로를 중간에 멈춥니다.

* 순열과 조합
  - 순열은 순서가 중요합니다.
  - 조합은 순서가 중요하지 않습니다.

* DFS와 완전탐색
  - DFS는 깊이 방향으로 탐색하는 방법입니다.
  - 완전탐색은 가능한 후보를 빠짐없이 확인한다는 풀이 전략입니다.
  - DFS를 이용해 완전탐색을 구현할 수 있습니다.

* 그리디와 완전탐색
  - 그리디는 매 순간 가장 좋아 보이는 선택을 합니다.
  - 완전탐색은 가능한 선택을 모두 확인한 뒤 판단합니다.

* DP와 완전탐색
  - DP는 같은 계산이 반복될 때 결과를 저장해 재사용합니다.
  - 완전탐색은 저장 없이 모든 후보를 직접 확인하는 경우가 많습니다.

## 12. 자주 하는 실수

* 입력 크기를 보지 않고 무조건 완전탐색으로 시작하는 실수
* 후보를 일부만 만들고 전부 확인했다고 착각하는 실수
* 순열이 필요한 문제를 조합으로 처리하는 실수
* 조합이 필요한 문제를 순열로 처리해 같은 경우를 여러 번 세는 실수
* 재귀 함수에서 종료 조건을 빠뜨리는 실수
* 재귀 호출 뒤에 선택 상태를 원래대로 돌리지 않는 실수
* 정답 후보를 갱신하는 조건을 반대로 쓰는 실수
* 공집합을 포함해야 하는지 제외해야 하는지 확인하지 않는 실수
* 후보를 리스트로 모두 저장해 메모리를 불필요하게 많이 쓰는 실수
* 중복 원소가 있을 때 같은 값을 어떻게 처리할지 정하지 않는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

가능한 답 후보의 수가 크지 않은지 먼저 확인해보세요. 후보를 전부 만들어도 제한 시간 안에 끝난다면 완전탐색을 떠올릴 수 있습니다.

### 2단계 힌트: 접근 힌트

각 후보가 어떻게 만들어지는지 정리해보세요. 값을 고르는 문제라면 조합, 순서를 정하는 문제라면 순열, 각 원소를 사용할지 말지 정하는 문제라면 부분집합 탐색으로 생각할 수 있습니다.

### 3단계 힌트: 구현 힌트

반복문, `itertools`, 재귀 중 가장 단순한 방식을 선택하세요. 후보를 하나 만들 때마다 바로 조건을 검사하고, 조건을 만족하면 정답 변수를 갱신하는 구조로 작성하면 됩니다.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - `N`이 작고 후보 수를 계산했을 때 감당할 수 있는 경우

* 문제 유형
  - 순열, 조합, 부분집합, 격자 탐색, 모든 시작점 검사, 모든 배치 확인

* 자주 등장하는 표현
  - "모든 경우", "가능한 조합", "몇 개를 선택", "순서를 정해", "최댓값을 찾아라", "조건을 만족하는 경우의 수"

* 적합한 자료구조
  - 리스트, 집합, 큐, 스택, 방문 배열, 재귀 호출 스택

* 사용하면 안 되는 경우
  - 후보 수가 `2^N` 또는 `N!`인데 `N`이 큰 경우
  - 입력이 100,000 이상이고 모든 쌍이나 모든 부분집합을 확인해야 하는 경우
  - 더 빠른 규칙, 정렬, 이분 탐색, DP가 필요한 경우

## 15. 요약 정리

* 완전탐색의 목적
  - 가능한 답 후보를 빠짐없이 검사해 정답을 찾는 것입니다.

* 핵심 아이디어
  - 후보 생성, 조건 검사, 정답 갱신을 반복합니다.

* 주요 자료구조
  - 리스트, 방문 배열, 스택, 큐, 재귀 호출 스택을 자주 사용합니다.

* 시간복잡도
  - 후보 수에 따라 `O(N^2)`, `O(N^3)`, `O(2^N)`, `O(N!)`처럼 커질 수 있습니다.

* 문제에서 떠올리는 신호
