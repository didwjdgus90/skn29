# [알고리즘] 단조 스택

## 1. 한 줄 요약

> 단조 스택은 스택 안의 값이 증가 또는 감소 흐름을 유지하도록 관리해서, 가까운 큰 값이나 작은 값을 빠르게 찾는 방법입니다.

---

## 2. 선수 지식

- 스택
  - 마지막에 넣은 값을 먼저 꺼내는 자료구조입니다.

- push와 pop
  - `push`는 값을 넣는 동작이고, `pop`은 가장 위의 값을 꺼내는 동작입니다.

- 인덱스
  - 배열에서 값의 위치를 나타냅니다. 단조 스택 문제에서는 값뿐 아니라 위치도 함께 저장하는 경우가 많습니다.

- 비교 연산
  - 현재 값과 스택의 맨 위 값을 비교해서 pop 여부를 결정합니다.

- 완전탐색
  - 각 원소마다 오른쪽 또는 왼쪽을 모두 확인하는 방식입니다. 단조 스택은 이 과정을 줄이기 위해 사용합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

단조 스택은 각 원소 기준으로 왼쪽이나 오른쪽에서 가장 가까운 큰 값 또는 작은 값을 찾아야 할 때 사용합니다.

### 기존 방식의 문제

- 각 원소마다 오른쪽을 끝까지 확인하면 `O(N^2)`이 될 수 있습니다.
- 입력이 커지면 모든 쌍을 비교하는 방식은 시간초과가 나기 쉽습니다.
- "가장 가까운 조건 만족 원소"를 찾는 문제는 단순 정렬로 해결하기 어렵습니다.

예를 들어 `[2, 5, 1, 3]`에서 각 숫자 오른쪽에 있는 첫 번째 큰 값을 찾는다고 해봅시다. 모든 원소마다 오른쪽을 다시 훑으면 같은 구간을 반복해서 확인하게 됩니다.

### 이 알고리즘을 사용하면

- 각 원소는 스택에 한 번 들어가고, 많아야 한 번 나옵니다.
- 전체 배열을 한 번 훑는 방식으로 처리할 수 있습니다.
- 다음 큰 원소, 이전 큰 원소, 다음 작은 원소, 히스토그램 넓이 같은 문제에 적용할 수 있습니다.

입력 크기가 커졌을 때 `O(N^2)` 풀이를 `O(N)`으로 줄일 수 있는 경우가 많습니다.

## 4. 핵심 아이디어

단조 스택은 스택의 규칙을 깨는 값이 들어올 때 기존 값을 꺼냅니다. 이때 꺼낸 값은 현재 값 때문에 자신의 답이 정해지는 경우가 많습니다.

오른쪽에서 처음 만나는 큰 값을 찾는 문제라면 다음 흐름을 사용합니다.

1. 왼쪽부터 값을 확인합니다.
2. 현재 값이 스택 맨 위 값보다 크면, 스택 맨 위 값의 다음 큰 값은 현재 값입니다.
3. 조건이 깨지는 동안 계속 pop합니다.
4. 현재 값을 스택에 넣습니다.

### 쉬운 비유

사람들이 줄을 서 있고, 뒤에서 더 키 큰 사람이 오면 앞의 작은 사람은 더 이상 뒤쪽을 볼 필요가 없다고 생각해봅시다. 방금 온 키 큰 사람이 바로 "처음 만난 더 큰 사람"이 되기 때문입니다.

단조 스택은 아직 답을 찾지 못한 사람들만 줄에 남겨두고, 답이 정해진 사람은 줄에서 빼는 방식입니다.

### 직관적으로 이해하기

배열이 `[2, 1, 4, 3]`이라고 해봅시다.

- `2`는 아직 오른쪽 큰 값을 모릅니다. 스택에 넣습니다.
- `1`도 아직 모릅니다. 스택에 넣습니다.
- `4`를 만났습니다.
  - `1`보다 큽니다. `1`의 다음 큰 값은 `4`입니다.
  - `2`보다도 큽니다. `2`의 다음 큰 값도 `4`입니다.
- `3`은 오른쪽 큰 값을 아직 모르므로 스택에 남습니다.

마지막까지 스택에 남은 값은 오른쪽에서 더 큰 값을 찾지 못한 값입니다.

## 5. 동작 과정 살펴보기

### 예제 상황

각 숫자의 오른쪽에서 처음 만나는 더 큰 숫자를 구합니다. 없으면 `-1`로 표시합니다.

### 예제 입력

```text
6
2 1 5 3 4 0
```

### 예제 출력

```text
5 5 -1 4 -1 -1
```

### 단계별 동작

1. 정답 배열을 모두 `-1`로 초기화합니다.
2. 스택에는 아직 다음 큰 값을 찾지 못한 원소의 인덱스를 넣습니다.
3. 현재 값을 확인합니다.
4. 현재 값이 스택 맨 위 인덱스의 값보다 크면, 그 인덱스의 정답을 현재 값으로 정합니다.
5. 조건이 계속 맞으면 pop을 반복합니다.
6. 현재 인덱스를 스택에 넣고 다음 원소로 이동합니다.

예제에서 `5`를 만났을 때, 앞에 있던 `1`과 `2`는 모두 `5`보다 작습니다. 그래서 두 값의 다음 큰 값이 `5`로 확정됩니다.

## 7. 기본 코드 템플릿

```python
def find_next_greater_numbers(numbers):
    answer = [-1] * len(numbers)
    waiting_stack = []

    for current_index, current_value in enumerate(numbers):
        while waiting_stack and numbers[waiting_stack[-1]] < current_value:
            previous_index = waiting_stack.pop()
            answer[previous_index] = current_value

        waiting_stack.append(current_index)

    return answer


number_count = int(input())
numbers = list(map(int, input().split()))

result = find_next_greater_numbers(numbers)
print(*result)
```

### 코드 흐름 설명

* `answer`는 각 위치의 다음 큰 값을 저장합니다.
* `waiting_stack`에는 아직 답을 찾지 못한 인덱스를 저장합니다.
* 반복문은 배열을 왼쪽부터 오른쪽으로 확인합니다.
* 현재 값이 스택 맨 위 인덱스의 값보다 크면, 그 인덱스의 답이 현재 값으로 확정됩니다.
* `while`을 쓰는 이유는 현재 값 하나가 여러 이전 원소의 답이 될 수 있기 때문입니다.
* 현재 인덱스도 아직 자신의 다음 큰 값을 모르므로 스택에 넣습니다.
* 끝까지 남은 인덱스는 더 큰 값을 찾지 못했으므로 `-1` 그대로 둡니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - 각 원소는 스택에 한 번 들어가고 최대 한 번 나옵니다.
  - 전체 시간복잡도는 `O(N)`입니다.

* 최악의 경우
  - pop이 많이 발생해도 각 원소가 여러 번 pop되지는 않습니다.
  - 따라서 최악의 경우도 `O(N)`입니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 배열을 한 번 순회하므로 입력 크기에 비례합니다.
  - 완전탐색의 `O(N^2)`보다 큰 입력에 유리합니다.

### 공간복잡도

* 정답 배열에 `O(N)` 공간을 사용합니다.
* 스택에도 최악의 경우 `O(N)`개의 인덱스가 들어갈 수 있습니다.
* 전체 공간복잡도는 `O(N)`입니다.

## 9. 예제로 이해하기

앞에서 사용한 예제와 다른 배열을 보겠습니다.

### 입력 데이터

```text
5
4 2 7 1 6
```

### 처리 과정

- `4` 확인
  - 스택이 비어 있으므로 인덱스 0을 넣습니다.
- `2` 확인
  - 2는 4보다 작으므로 인덱스 1을 넣습니다.
- `7` 확인
  - 7은 2보다 큽니다. 2의 답은 7입니다.
  - 7은 4보다 큽니다. 4의 답도 7입니다.
  - 인덱스 2를 넣습니다.
- `1` 확인
  - 1은 7보다 작으므로 인덱스 3을 넣습니다.
- `6` 확인
  - 6은 1보다 큽니다. 1의 답은 6입니다.
  - 6은 7보다 작으므로 멈춥니다.

### 중간 상태 변화

`7`을 만나는 순간 스택에 있던 `2`와 `4`의 답이 한꺼번에 정해집니다.

### 최종 결과

```text
7 7 -1 6 -1
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 오른쪽에서 처음 만나는 더 큰 값을 찾아야 합니다.
* 왼쪽에서 가장 가까운 더 큰 값을 찾아야 합니다.
* 다음 작은 값 또는 이전 작은 값을 찾아야 합니다.
* 각 원소마다 주변 방향으로 조건을 만족하는 가장 가까운 원소가 필요합니다.
* 완전탐색으로 풀면 `O(N^2)`이 됩니다.
* 히스토그램의 가장 큰 직사각형 같은 문제가 등장합니다.
* 온도가 더 높아지는 날까지 며칠 걸리는지 계산해야 합니다.
* "가장 가까운", "다음", "이전", "큰", "작은"이라는 표현이 함께 나옵니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 일반 스택과 단조 스택
  - 일반 스택은 단순히 마지막 값을 먼저 꺼냅니다.
  - 단조 스택은 값의 증가 또는 감소 흐름을 유지하도록 pop 조건을 둡니다.

* 단조 증가 스택과 단조 감소 스택
  - 단조 증가 스택은 작은 값에서 큰 값 방향의 흐름을 유지합니다.
  - 단조 감소 스택은 큰 값에서 작은 값 방향의 흐름을 유지합니다.
  - 문제에서 찾는 값이 큰 값인지 작은 값인지에 따라 pop 조건이 달라집니다.

* 단조 스택과 정렬
  - 정렬은 전체 순서를 바꿉니다.
  - 단조 스택은 원래 배열의 순회 순서를 유지하면서 가까운 원소 정보를 찾습니다.

* 단조 스택과 힙
  - 힙은 최댓값이나 최솟값을 빠르게 꺼내는 자료구조입니다.
  - 단조 스택은 가까운 방향의 조건 만족 원소를 찾는 데 초점이 있습니다.

* 값 저장과 인덱스 저장
  - 값만 필요하면 값을 저장해도 됩니다.
  - 위치 차이, 거리, 정답 배열 갱신이 필요하면 인덱스를 저장하는 편이 좋습니다.

## 12. 자주 하는 실수

* pop 조건의 부등호 방향을 반대로 쓰는 실수
* 같은 값이 있을 때 제거할지 유지할지 정하지 않는 실수
* 값만 저장해놓고 정답 배열의 위치를 갱신하지 못하는 실수
* `if`만 사용해서 여러 원소를 한꺼번에 처리하지 못하는 실수
* 스택에 현재 인덱스를 push하는 과정을 빠뜨리는 실수
* 다음 큰 값을 찾아야 하는데 이전 큰 값 방향으로 순회하는 실수
* 정답이 없는 원소를 초기값으로 처리하지 않는 실수
* 히스토그램 문제처럼 남은 스택을 마지막에 처리해야 하는 유형에서 마무리를 빼먹는 실수
* 단조 스택이 항상 정렬 문제를 해결한다고 착각하는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

각 원소마다 한쪽 방향에서 가장 가까운 큰 값 또는 작은 값을 찾아야 하는지 확인해보세요. 그런 구조라면 단조 스택을 떠올릴 수 있습니다.

### 2단계 힌트: 접근 힌트

아직 답을 찾지 못한 원소의 인덱스를 스택에 보관하세요. 현재 값이 스택 맨 위 원소의 답이 될 수 있으면 pop하면서 정답을 기록합니다.

### 3단계 힌트: 구현 힌트

다음 큰 값을 찾는다면 왼쪽부터 순회하면서 `numbers[stack[-1]] < current_value`인 동안 pop하세요. pop된 인덱스의 답을 현재 값으로 갱신하면 됩니다.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 원소 개수가 많아 `O(N^2)` 비교가 부담되는 경우

* 문제 유형
  - 다음 큰 원소, 이전 큰 원소, 다음 작은 원소, 이전 작은 원소, 일별 온도, 탑 수신, 히스토그램 넓이

* 자주 등장하는 표현
  - "가장 가까운", "오른쪽에서 처음", "왼쪽에서 처음", "더 큰", "더 작은", "며칠 뒤"

* 적합한 자료구조
  - 스택, 정답 배열, 인덱스 배열

* 사용하면 안 되는 경우
  - 가까운 위치가 아니라 전체 최댓값이나 최솟값만 필요한 경우
  - 원소 순서를 바꿔도 되는 단순 정렬 문제
  - 비교 기준이 스택의 top만으로 결정되지 않는 경우

## 15. 요약 정리

* 단조 스택의 목적
  - 가까운 큰 값이나 작은 값을 선형 시간에 찾는 것입니다.

* 핵심 아이디어
  - 스택의 단조성을 깨는 값이 오면 pop하면서 정답을 확정합니다.

* 주요 자료구조
  - 스택과 정답 배열을 사용합니다.

* 시간복잡도
  - 각 원소가 한 번 push되고 최대 한 번 pop되므로 `O(N)`입니다.

* 문제에서 떠올리는 신호
  - 다음 또는 이전의 가장 가까운 큰 값이나 작은 값을 찾는 문제입니다.

* 초급자가 주의할 점
  - 어떤 방향으로 순회할지, 어떤 부등호로 pop할지 먼저 정해야 합니다.
