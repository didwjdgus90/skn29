# [알고리즘] 중복순열과 중복조합

## 1. 한 줄 요약

> 중복순열과 중복조합은 같은 원소를 여러 번 고를 수 있는 선택 문제에서, 순서를 구분할지 말지에 따라 나뉘는 완전탐색 방법입니다.

---

## 2. 선수 지식

- 순열
  - 순서를 중요하게 보는 선택입니다. `A B`와 `B A`를 다른 경우로 봅니다.

- 조합
  - 순서를 중요하게 보지 않는 선택입니다. `A B`와 `B A`를 같은 경우로 봅니다.

- 재귀 함수
  - 같은 선택 과정을 여러 단계 반복할 때 사용합니다.

- 반복문
  - 현재 단계에서 고를 수 있는 후보를 하나씩 확인할 때 사용합니다.

- 리스트
  - 현재까지 고른 값을 순서대로 저장할 때 사용합니다.

- 백트래킹
  - 값을 선택하고, 다음 단계로 이동한 뒤, 다시 돌아와 다른 선택을 시도하는 방식입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

중복순열과 중복조합은 "같은 값을 다시 고를 수 있는가?"가 중요한 문제에서 사용합니다.

### 기존 방식의 문제

- 일반 순열은 한 번 고른 원소를 다시 고르지 않습니다.
- 일반 조합도 같은 원소를 여러 번 선택하지 않습니다.
- 하지만 문제에서 같은 숫자, 같은 문자, 같은 물건을 여러 번 사용할 수 있다면 일반 순열과 조합만으로는 모든 후보를 만들 수 없습니다.

예를 들어 숫자 `1, 2, 3`으로 두 자리 비밀번호를 만든다고 해봅시다. `11`, `22`, `33`처럼 같은 숫자를 두 번 쓰는 경우도 가능하다면 일반 순열로는 부족합니다.

### 이 알고리즘을 사용하면

- 같은 원소를 여러 번 선택하는 경우까지 빠짐없이 만들 수 있습니다.
- 순서가 중요한 문제와 중요하지 않은 문제를 분리해서 생각할 수 있습니다.
- 비밀번호 생성, 주사위 결과, 메뉴 선택, 중복 가능한 숫자 뽑기 문제를 자연스럽게 풀 수 있습니다.

입력 크기가 커지면 후보 수가 빠르게 늘어납니다. 그래서 만들 후보의 개수를 먼저 예상해야 합니다.

---

## 4. 핵심 아이디어

중복순열과 중복조합을 구분하는 기준은 두 가지입니다.

- 순서를 구분하는가?
- 같은 원소를 다시 고를 수 있는가?

중복순열은 순서를 구분하고 중복을 허용합니다. 그래서 매 단계마다 전체 후보를 다시 볼 수 있습니다.

중복조합은 순서를 구분하지 않고 중복을 허용합니다. 그래서 현재 고른 원소와 같은 위치부터 다시 볼 수 있습니다.

### 쉬운 비유

음료 기계에서 맛을 여러 번 선택해 컵을 채운다고 생각해봅시다.

첫 번째 칸, 두 번째 칸처럼 위치가 중요하다면 `딸기-초코`와 `초코-딸기`는 다릅니다. 이때는 중복순열입니다.

반대로 어떤 맛을 몇 번 골랐는지만 중요하다면 `딸기-초코`와 `초코-딸기`는 같습니다. 이때는 중복조합입니다.

### 직관적으로 이해하기

재료가 `A, B, C`이고 2개를 고른다고 해봅시다.

중복순열은 순서를 구분합니다.

- `A A`
- `A B`
- `A C`
- `B A`
- `B B`
- `B C`
- `C A`
- `C B`
- `C C`

중복조합은 순서를 구분하지 않습니다.

- `A A`
- `A B`
- `A C`
- `B B`
- `B C`
- `C C`

둘 다 중복은 허용하지만, 순서를 어떻게 보느냐에 따라 결과가 달라집니다.

## 5. 동작 과정 살펴보기

### 예제 상황

숫자 `1, 2, 3` 중에서 2개를 고릅니다. 같은 숫자는 다시 고를 수 있습니다.

### 예제 입력

```text
3 2
1 2 3
```

첫 줄의 `3`은 숫자 개수, `2`는 고를 개수입니다. 둘째 줄은 선택할 수 있는 숫자입니다.

### 예제 출력

```text
중복순열
1 1
1 2
1 3
2 1
2 2
2 3
3 1
3 2
3 3

중복조합
1 1
1 2
1 3
2 2
2 3
3 3
```

### 단계별 동작

1. 고를 숫자 목록을 확인합니다.
2. 현재까지 고른 숫자 개수를 확인합니다.
3. 목표 개수에 도달하지 않았다면 다음 숫자를 고릅니다.
4. 중복순열은 매번 처음 숫자부터 다시 후보로 봅니다.
5. 중복조합은 현재 선택한 위치부터 뒤쪽 숫자만 후보로 봅니다.
6. 목표 개수에 도달하면 현재 선택을 출력합니다.

## 7. 기본 코드 템플릿

```python
def make_repeated_permutations(items, pick_count):
    result = []
    selected = []

    def backtrack():
        if len(selected) == pick_count:
            result.append(selected[:])
            return

        for item in items:
            selected.append(item)
            backtrack()
            selected.pop()

    backtrack()
    return result


def make_repeated_combinations(items, pick_count):
    result = []
    selected = []

    def backtrack(start_index):
        if len(selected) == pick_count:
            result.append(selected[:])
            return

        for index in range(start_index, len(items)):
            selected.append(items[index])
            backtrack(index)
            selected.pop()

    backtrack(0)
    return result


item_count, pick_count = map(int, input().split())
numbers = list(map(int, input().split()))

print("중복순열")
for case in make_repeated_permutations(numbers, pick_count):
    print(*case)

print()
print("중복조합")
for case in make_repeated_combinations(numbers, pick_count):
    print(*case)
```

### 코드 흐름 설명

* `items` 리스트는 선택할 수 있는 원소를 저장합니다.
* `selected` 리스트는 현재까지 고른 원소를 저장합니다.
* 중복순열 함수는 매 단계마다 `items` 전체를 반복합니다.
* 중복조합 함수는 `start_index`부터 반복합니다.
* 중복조합에서 `backtrack(index)`를 호출하기 때문에 현재 고른 원소를 다음 단계에서 다시 고를 수 있습니다.
* `selected.append()`는 선택을 의미합니다.
* `selected.pop()`은 선택을 취소하고 이전 상태로 돌아가는 동작입니다.
* `len(selected) == pick_count`가 되면 하나의 결과가 완성됩니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - 결과를 모두 만들어야 하므로 생성되는 후보 수에 비례합니다.

* 최악의 경우
  - 중복순열은 원소 `N`개 중 `R`개를 고를 때 `O(N^R)`개의 후보가 생깁니다.
  - 중복조합은 중복순열보다 후보가 적지만, 여전히 후보 수가 빠르게 늘 수 있습니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 선택 개수 `R`이 커질수록 후보 수가 크게 증가합니다.
  - 모든 결과를 리스트에 저장하면 출력보다 메모리가 먼저 부담될 수 있습니다.

### 공간복잡도

* 현재 선택을 저장하는 리스트는 `O(R)` 공간을 사용합니다.
* 재귀 호출 깊이도 최대 `R`입니다.
* 모든 결과를 저장하면 결과 개수에 `R`을 곱한 만큼의 추가 공간이 필요합니다.
* 결과를 바로 출력하면 저장 공간을 줄일 수 있습니다.

## 9. 예제로 이해하기

앞에서 사용한 숫자 예제와 다른 상황을 보겠습니다.

### 입력 데이터

```text
3 2
S M L
```

티셔츠 사이즈 `S, M, L` 중에서 2개를 고릅니다. 같은 사이즈를 여러 장 고를 수 있습니다.

### 처리 과정

중복순열은 첫 번째 선택과 두 번째 선택의 위치를 구분합니다.

- `S M`과 `M S`는 다릅니다.
- 첫 번째 주문 칸과 두 번째 주문 칸이 따로 있다고 보는 방식입니다.

중복조합은 몇 장을 골랐는지만 봅니다.

- `S M`과 `M S`는 같습니다.
- 사이즈별 개수만 중요하다고 보는 방식입니다.

### 중간 상태 변화

중복조합에서 `M`을 고른 뒤에는 `S`로 돌아가지 않습니다.

- `M M`
- `M L`

이렇게 현재 위치부터만 확인하면 `S M`과 `M S`가 동시에 생기는 일을 막을 수 있습니다.

### 최종 결과

중복순열은 `3^2 = 9`가지입니다. 중복조합은 `6`가지입니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 같은 값을 여러 번 사용할 수 있습니다.
* "중복을 허용한다"라는 표현이 나옵니다.
* "순서가 다르면 다른 경우"라는 조건이 있습니다.
* "순서는 상관없다"라는 조건이 있습니다.
* 비밀번호, 주사위, 메뉴 선택, 상품 묶음 같은 문제가 등장합니다.
* `N`개의 후보 중 `R`개를 고르는 구조입니다.
* 모든 가능한 선택 목록을 출력하거나 개수를 세어야 합니다.
* 순열, 조합과 비슷하지만 같은 원소를 다시 쓸 수 있습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 순열과 중복순열
  - 순열은 한 번 고른 원소를 다시 고르지 않습니다.
  - 중복순열은 같은 원소를 다시 고를 수 있습니다.

* 조합과 중복조합
  - 조합은 같은 원소를 다시 고르지 않습니다.
  - 중복조합은 같은 원소를 다시 고를 수 있습니다.

* 중복순열과 중복조합
  - 중복순열은 순서를 구분합니다.
  - 중복조합은 순서를 구분하지 않습니다.

* 조합과 부분집합
  - 조합은 보통 정확히 `R`개를 고릅니다.
  - 부분집합은 각 원소를 고를지 말지 결정합니다.

* 재귀 구현과 라이브러리 사용
  - 라이브러리는 빠르게 결과를 얻는 데 좋습니다.
  - 직접 구현은 순서, 중복, 시작 위치가 어떻게 결과를 바꾸는지 이해하는 데 좋습니다.

## 12. 자주 하는 실수

* 중복순열에서 방문 배열을 사용해 같은 원소를 막는 실수
* 중복조합에서 다음 시작 위치를 `index + 1`로 넘기는 실수
* 중복조합에서 이전 원소까지 다시 탐색해 같은 조합을 여러 번 만드는 실수
* 순서가 중요한 문제를 중복조합으로 푸는 실수
* 순서가 중요하지 않은 문제를 중복순열로 풀어 중복 결과를 만드는 실수
* 재귀 종료 조건을 `pick_count`와 다르게 설정하는 실수
* 결과를 저장할 때 `selected[:]`처럼 복사하지 않는 실수
* 후보 수가 너무 큰데 모든 결과를 리스트에 저장하는 실수
* 입력 원소에 같은 값이 이미 들어 있는 경우를 따로 고려하지 않는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

먼저 같은 원소를 여러 번 사용할 수 있는지 확인하세요. 그다음 순서를 구분하는 문제인지 판단해야 합니다.

### 2단계 힌트: 접근 힌트

순서가 중요하면 매 단계마다 전체 후보를 다시 탐색합니다. 순서가 중요하지 않으면 현재 위치부터 뒤쪽 후보만 탐색합니다.

### 3단계 힌트: 구현 힌트

중복순열은 재귀 함수에 시작 인덱스가 필요하지 않습니다. 중복조합은 `start_index`를 두고, 재귀 호출 시 현재 인덱스를 그대로 넘기면 같은 원소를 다시 고를 수 있습니다.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 후보 개수 `N`과 선택 개수 `R`이 작아 모든 결과를 만들 수 있는 경우

* 문제 유형
  - 중복 가능한 숫자 선택, 비밀번호 생성, 주사위 결과 나열, 메뉴 여러 개 고르기, 상품 묶음 만들기

* 자주 등장하는 표현
  - "중복 허용", "같은 것을 여러 번 선택 가능", "순서가 다르면 다른 경우", "순서는 상관없음"

* 적합한 자료구조
  - 리스트, 재귀 호출 스택, 현재 선택을 저장하는 배열

* 사용하면 안 되는 경우
  - `N^R`개의 결과가 너무 많아 제한 시간 안에 만들 수 없는 경우
  - 실제 결과 목록이 아니라 개수만 필요하고 수학 공식으로 바로 구할 수 있는 경우
  - 문제에 더 강한 조건이 있어 DP나 그리디가 더 적합한 경우

## 15. 요약 정리

* 중복순열과 중복조합의 목적
  - 같은 원소를 다시 고를 수 있는 선택 경우를 빠짐없이 만드는 것입니다.

* 핵심 아이디어
  - 중복순열은 매 단계 전체 후보를 다시 봅니다.
  - 중복조합은 현재 위치부터 다시 봅니다.

* 주요 자료구조
  - 현재 선택을 저장하는 리스트와 재귀 호출 스택을 사용합니다.

* 시간복잡도
  - 중복순열은 보통 `O(N^R)`입니다.
  - 중복조합도 결과 수에 비례하므로 `N`과 `R`이 커지면 부담됩니다.

* 문제에서 떠올리는 신호
