# [알고리즘] HashSet, 해시셋

## 1. 한 줄 요약

> HashSet은 중복 없는 값들을 저장하고, 어떤 값이 이미 있는지 빠르게 확인하기 위한 해시 기반 자료구조입니다.

---

## 2. 선수 지식

- 배열과 리스트: 값을 순서대로 저장하는 기본 자료구조입니다.
- 집합: 같은 값을 중복해서 담지 않는 자료 묶음입니다.
- 해시: 값을 일정한 규칙으로 숫자처럼 다루어 빠르게 찾는 방식입니다.
- 시간복잡도: 자료구조의 삽입, 삭제, 검색이 얼마나 빠른지 판단할 때 필요합니다.
- 반복문: HashSet 안의 값을 하나씩 확인할 때 사용합니다.
- 동등성 비교: 두 값이 같은 값인지 판단하는 기준입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

HashSet은 "값이 이미 등장했는가", "중복을 제거해야 하는가", "두 묶음에 공통 값이 있는가" 같은 문제에서 사용합니다.

### 기존 방식의 문제

- 리스트에서 어떤 값이 있는지 찾으려면 앞에서부터 하나씩 확인해야 합니다.
- 데이터가 많아지면 존재 확인이 느려집니다.
- 중복을 직접 제거하려면 이미 저장한 값인지 계속 검사해야 합니다.

예를 들어 학생 번호가 많이 들어오고, 같은 번호가 여러 번 나올 수 있다고 해봅시다. 리스트만 사용하면 새 번호를 넣기 전에 매번 전체 리스트를 확인해야 합니다.

### 이 알고리즘을 사용하면

- 중복 값이 자동으로 하나만 남습니다.
- 값이 있는지 확인하는 작업이 평균적으로 매우 빠릅니다.
- 합집합, 교집합, 차집합 같은 집합 연산을 간단하게 표현할 수 있습니다.

다만 HashSet은 저장 순서를 보장하지 않습니다. "몇 번째 값"처럼 위치가 중요한 문제라면 리스트나 다른 자료구조가 더 적합할 수 있습니다.

---

## 4. 핵심 아이디어

HashSet은 값을 그대로 줄 세워 찾지 않습니다. 값을 해시 함수에 넣어 저장 위치를 빠르게 계산합니다.

1. 값을 넣으려고 합니다.
2. 값의 해시 결과를 계산합니다.
3. 해당 위치에 같은 값이 있는지 확인합니다.
4. 이미 있으면 추가하지 않습니다.
5. 없으면 새 값으로 저장합니다.

### 쉬운 비유

큰 사물함이 있고, 물건마다 번호표를 붙여 정해진 칸에 넣는다고 생각해봅시다. 물건을 찾을 때 모든 칸을 열어보지 않고, 번호표가 가리키는 칸으로 바로 갑니다.

HashSet도 비슷합니다. 값을 저장할 때 해시를 이용해 찾아갈 위치를 정하므로, 매번 처음부터 끝까지 뒤질 필요가 줄어듭니다.

### 직관적으로 이해하기

방문자 이름 목록이 다음과 같다고 해봅시다.

```text
민수, 지아, 민수, 도윤, 지아
```

HashSet에 넣으면 중복 이름은 다시 저장되지 않습니다.

```text
민수, 지아, 도윤
```

이때 중요한 점은 남은 값들의 출력 순서가 입력 순서와 같다고 기대하면 안 된다는 것입니다. HashSet의 핵심은 순서가 아니라 중복 제거와 빠른 조회입니다.

## 5. 동작 과정 살펴보기

### 예제 상황

온라인 강의에 접속한 학생 번호가 기록됩니다. 같은 학생이 새로고침해서 여러 번 기록될 수 있습니다. 실제로 접속한 학생 수만 알고 싶습니다.

### 예제 입력

```text
8
12 7 12 9 7 21 30 21
```

### 예제 출력

```text
5
```

서로 다른 학생 번호는 `12`, `7`, `9`, `21`, `30`으로 총 5개입니다.

### 단계별 동작

1. 빈 집합을 만듭니다.
2. 첫 번째 학생 번호 `12`를 넣습니다.
3. 다음 번호를 확인하며 집합에 추가합니다.
4. 이미 있는 번호가 다시 나오면 집합 크기는 변하지 않습니다.
5. 모든 번호를 처리합니다.
6. 집합의 크기를 출력합니다.

## 7. 기본 코드 템플릿

```python
def count_unique_values(values):
    seen_values = set()

    for value in values:
        seen_values.add(value)

    return len(seen_values)


def find_common_values(first_values, second_values):
    first_set = set(first_values)
    common_values = []

    for value in second_values:
        if value in first_set:
            common_values.append(value)

    return sorted(set(common_values))


def main():
    count = int(input())
    values = list(map(int, input().split()))

    print(count_unique_values(values))


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `seen_values`는 이미 등장한 값을 저장하는 집합입니다.
* `add`는 값을 집합에 넣습니다. 이미 있는 값이면 집합은 변하지 않습니다.
* `len(seen_values)`는 중복을 제거한 뒤 남은 값의 개수입니다.
* `value in first_set`은 값이 존재하는지 빠르게 확인합니다.
* `find_common_values`는 두 목록에 모두 있는 값을 찾는 예시입니다.
* 결과의 순서가 필요하면 마지막에 `sorted`로 정렬합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: 삽입, 삭제, 존재 확인이 보통 `O(1)`에 가깝습니다.
* 최악의 경우: 해시 충돌이 많이 발생하면 한 위치에 값이 몰려 `O(n)`까지 느려질 수 있습니다.
* 입력 크기가 커졌을 때 부담되는 부분: 값의 개수만큼 저장 공간이 필요하고, 해시 충돌이 많아지면 성능이 떨어질 수 있습니다.

대부분의 코딩 테스트에서는 HashSet의 `in`, `add`, `remove`를 평균 `O(1)`로 생각해도 됩니다.

### 공간복잡도

* 서로 다른 값을 저장해야 하므로 최대 `O(n)` 공간을 사용합니다.
* 중복이 많으면 실제 저장되는 값은 줄어듭니다.
* 집합 연산을 위해 새 집합을 만들면 추가 공간이 필요할 수 있습니다.

## 9. 예제로 이해하기

이번에는 두 동아리 명단에서 둘 다 가입한 학생을 찾는 상황을 보겠습니다.

입력 데이터:

```text
코딩 동아리: 3 8 11 15
로봇 동아리: 2 8 15 20
```

처리 과정:

1. 코딩 동아리 명단을 HashSet으로 만듭니다.
2. 로봇 동아리 명단을 하나씩 확인합니다.
3. `2`는 코딩 동아리 집합에 없으므로 건너뜁니다.
4. `8`은 있으므로 공통 명단에 넣습니다.
5. `15`도 있으므로 공통 명단에 넣습니다.
6. `20`은 없으므로 건너뜁니다.

중간 상태:

```text
확인 값   존재 여부   처리
2         없음        제외
8         있음        추가
15        있음        추가
20        없음        제외
```

최종 결과:

```text
8 15
```

HashSet을 쓰면 두 번째 명단의 각 값이 첫 번째 명단에 있는지 빠르게 확인할 수 있습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### HashSet과 리스트

리스트는 입력 순서를 유지하고 인덱스로 접근할 수 있습니다. HashSet은 인덱스 접근이 없고 순서도 보장하지 않지만, 중복 제거와 존재 확인이 빠릅니다.

### HashSet과 HashMap

HashSet은 값 자체의 존재 여부를 저장합니다. HashMap은 `키 → 값` 형태로 추가 정보를 저장합니다. 등장 횟수가 필요하면 HashMap이나 딕셔너리가 더 적합합니다.

### HashSet과 정렬된 집합

HashSet은 보통 정렬 상태를 유지하지 않습니다. 항상 작은 값부터 꺼내야 하거나 정렬 순회가 필요하면 정렬된 자료구조를 고려해야 합니다.

### 중복 제거와 빈도 계산

HashSet은 같은 값이 몇 번 나왔는지 기억하지 않습니다. 값이 1번 나왔는지 10번 나왔는지 구분해야 한다면 카운터 자료구조를 사용해야 합니다.

## 12. 자주 하는 실수

* HashSet의 출력 순서가 입력 순서와 같다고 생각하는 실수
* 인덱스로 접근하려고 하는 실수
* 중복 횟수가 필요한데 HashSet만 사용하는 실수
* 사용자 정의 객체를 넣을 때 동등성 기준을 제대로 정의하지 않는 실수
* 삭제할 값이 없을 때의 동작을 확인하지 않는 실수
* 정렬된 결과가 필요한데 `sorted` 처리를 빠뜨리는 실수
* 리스트에서 `in`을 쓰는 것과 집합에서 `in`을 쓰는 비용 차이를 고려하지 않는 실수
* 해시 충돌 때문에 최악의 경우가 존재한다는 점을 완전히 잊는 실수

## 14. 언제 사용하면 좋은가

* 중복 제거가 필요할 때 좋습니다.
* 값의 존재 여부를 빠르게 확인해야 할 때 적합합니다.
* 두 데이터 묶음의 교집합, 합집합, 차집합이 필요할 때 사용할 수 있습니다.
* 순서나 인덱스가 중요하지 않을 때 좋습니다.
* 방문 처리, 등록 여부 확인, 금지 목록 검사 같은 문제와 잘 맞습니다.
* 등장 횟수, 입력 순서, 우선순위가 중요하면 다른 자료구조를 함께 고려해야 합니다.

## 15. 요약 정리

* HashSet의 목적은 중복 없는 값을 저장하고 빠르게 조회하는 것입니다.
* 핵심 아이디어는 해시를 이용해 값의 저장 위치를 빠르게 찾는 것입니다.
* 주요 연산은 추가, 삭제, 포함 여부 확인, 집합 연산입니다.
* 평균 시간복잡도는 삽입, 삭제, 검색 모두 `O(1)`에 가깝습니다.
* 문제에서 중복 제거, 존재 확인, 공통 원소가 보이면 HashSet을 떠올릴 수 있습니다.
