# [알고리즘] 내장 정렬 활용

## 1. 한 줄 요약

> 내장 정렬은 직접 정렬 알고리즘을 구현하지 않고, 언어가 제공하는 검증된 정렬 기능으로 데이터를 원하는 기준에 맞게 빠르고 안정적으로 정리하는 방법입니다.

---

## 2. 선수 지식

- 리스트: 정렬할 데이터를 담는 기본 자료구조입니다.
- 오름차순과 내림차순: 작은 값부터 정렬할지, 큰 값부터 정렬할지 정하는 방향입니다.
- key 함수: 어떤 값을 기준으로 정렬할지 알려 주는 함수입니다.
- 람다 함수: 짧은 기준 함수를 한 줄로 작성할 때 사용합니다.
- 안정 정렬: 기준값이 같은 데이터들의 기존 순서를 유지하는 정렬입니다.
- 튜플 비교: `(첫 기준, 둘째 기준)`처럼 여러 기준을 순서대로 비교할 수 있습니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

내장 정렬은 데이터를 직접 구현한 정렬 알고리즘보다 안전하고 빠르게 정리해야 할 때 사용합니다.

### 기존 방식의 문제

- 선택 정렬, 버블 정렬 같은 기본 정렬은 구현은 쉽지만 큰 데이터에 느립니다.
- 직접 구현한 정렬은 경계 조건, 안정성, 성능 문제를 놓치기 쉽습니다.
- 코딩 테스트에서는 정렬 자체보다 "어떤 기준으로 정렬할 것인가"가 더 중요한 경우가 많습니다.

### 이 알고리즘을 사용하면

- 숫자, 문자열, 튜플, 딕셔너리 리스트를 간단히 정렬할 수 있습니다.
- 여러 기준을 한 번에 적용할 수 있습니다.
- Python 내장 정렬은 안정 정렬이므로 같은 기준값의 기존 순서를 유지할 수 있습니다.
- 일반적인 경우 `O(n log n)` 성능으로 충분히 빠르게 동작합니다.

---

## 4. 핵심 아이디어

내장 정렬 활용의 핵심은 정렬 알고리즘을 직접 만드는 것이 아니라, 정렬 기준을 정확히 전달하는 것입니다.

Python에서는 대표적으로 두 가지를 사용합니다.

- `sorted(iterable)`: 정렬된 새 리스트를 반환합니다.
- `list.sort()`: 기존 리스트 자체를 정렬합니다.

그리고 정렬 기준은 `key`로 지정합니다.

### 쉬운 비유

서류 더미를 정리한다고 생각해 봅시다.

서류를 날짜순으로 정리할 수도 있고, 이름순으로 정리할 수도 있고, 부서별로 정리한 뒤 같은 부서 안에서는 이름순으로 정리할 수도 있습니다.

내장 정렬에서 중요한 것은 "서류를 정렬하는 방법"을 새로 만드는 것이 아니라, "정렬 기준표"를 정확히 주는 것입니다.

### 직관적으로 이해하기

학생 데이터가 다음처럼 있다고 해 봅시다.

```text
[
  {"name": "jin", "score": 80},
  {"name": "ara", "score": 95},
  {"name": "min", "score": 80}
]
```

점수순으로 정렬하려면 각 학생에서 `score`만 꺼내 비교하면 됩니다.

점수가 같을 때 이름순으로 정렬하려면 `(score, name)`을 기준으로 주면 됩니다.

## 5. 동작 과정 살펴보기

### 예제 상황

상품 목록을 가격이 낮은 순서로 정렬하고, 가격이 같으면 이름순으로 정렬하겠습니다.

### 예제 입력

```text
items = [
  {"name": "marker", "price": 1200},
  {"name": "clip", "price": 500},
  {"name": "note", "price": 1200},
  {"name": "tape", "price": 900}
]
```

### 예제 출력

```text
[
  {"name": "clip", "price": 500},
  {"name": "tape", "price": 900},
  {"name": "marker", "price": 1200},
  {"name": "note", "price": 1200}
]
```

### 단계별 동작

1. 각 상품에서 가격을 첫 번째 기준으로 꺼냅니다.
2. 가격이 낮은 상품이 앞에 오도록 정렬합니다.
3. 가격이 같은 상품끼리는 이름을 두 번째 기준으로 비교합니다.
4. `marker`와 `note`는 가격이 같으므로 이름순으로 `marker`가 먼저 옵니다.
5. 정렬된 새 리스트를 결과로 사용합니다.

## 7. 기본 코드 템플릿

```python
def sort_numbers(numbers):
    return sorted(numbers)


def sort_words_by_length(words):
    return sorted(words, key=lambda word: (len(word), word))


def sort_products(products):
    return sorted(products, key=lambda product: (product["price"], product["name"]))


def sort_scores_desc(students):
    return sorted(students, key=lambda student: (-student["score"], student["name"]))


if __name__ == "__main__":
    print(sort_numbers([9, 1, 4, 7, 3]))

    words = ["pear", "fig", "apple", "kiwi", "plum"]
    print(sort_words_by_length(words))

    products = [
        {"name": "marker", "price": 1200},
        {"name": "clip", "price": 500},
        {"name": "note", "price": 1200},
        {"name": "tape", "price": 900},
    ]
    print(sort_products(products))

    students = [
        {"name": "jin", "score": 80},
        {"name": "ara", "score": 95},
        {"name": "min", "score": 80},
    ]
    print(sort_scores_desc(students))
```

### 코드 흐름 설명

* `sort_numbers`는 기본 오름차순 정렬입니다.
* `sort_words_by_length`는 단어 길이를 먼저 비교하고, 길이가 같으면 단어 자체를 비교합니다.
* `sort_products`는 가격을 먼저 비교하고, 가격이 같으면 이름을 비교합니다.
* `sort_scores_desc`는 점수를 내림차순으로 정렬하기 위해 `-score`를 사용합니다.
* 점수 내림차순과 이름 오름차순처럼 기준마다 방향이 다르면 `reverse=True`보다 튜플 기준을 조절하는 방식이 편합니다.
* `sorted()`는 원본을 바꾸지 않고 새 리스트를 반환합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* Python 내장 정렬은 일반적으로 `O(n log n)`입니다.
* 이미 어느 정도 정렬된 데이터에서는 더 빠르게 동작할 수 있습니다.
* 최선의 경우 `O(n)`에 가까운 성능을 보일 수 있습니다.
* `key` 함수는 각 원소마다 한 번씩 계산됩니다.

### 공간복잡도

* `sorted()`는 새 리스트를 만들기 때문에 `O(n)` 공간이 필요합니다.
* `list.sort()`는 기존 리스트를 정렬하지만 내부적으로 보조 공간을 사용할 수 있습니다.
* Python 내장 정렬은 안정 정렬이며, 실제 구현은 실전 데이터에 강한 방식으로 최적화되어 있습니다.

1. 점수가 높은 사람이 먼저 옵니다.
2. 점수가 같으면 제출 시간이 빠른 사람이 먼저 옵니다.

```text
players = [

  ("jisu", 90, 28),

```

정렬 기준:

```text
(-점수, 제출시간, 이름)
```

```text
[
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "정렬하라", "순서대로 출력하라"는 표현이 있습니다.
* 여러 기준으로 데이터를 정렬해야 합니다.
* 점수순, 이름순, 길이순, 날짜순 같은 기준이 주어집니다.
* 원본을 유지한 정렬 결과가 필요합니다.
* 같은 값의 기존 순서가 유지되어야 합니다.
* 직접 정렬 알고리즘 구현이 아니라 결과 정렬이 목적입니다.
* 튜플, 리스트, 딕셔너리 형태의 데이터를 기준별로 정리해야 합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### `sort()`와 `sorted()`

`sort()`는 리스트 자체를 바꿉니다. 반환값은 `None`입니다.

`sorted()`는 정렬된 새 리스트를 반환합니다. 원본은 그대로 둡니다.

### `reverse=True`와 음수 key

전체 기준을 한꺼번에 내림차순으로 바꾸려면 `reverse=True`가 편합니다.

하지만 어떤 기준은 내림차순, 어떤 기준은 오름차순이어야 한다면 숫자 기준에 음수를 붙이는 방식이 더 세밀합니다.

### 직접 정렬 구현과 내장 정렬

선택 정렬, 삽입 정렬 같은 직접 구현은 원리 학습에 좋습니다.

실전 문제에서는 특별한 요구가 없다면 내장 정렬이 더 빠르고 안전합니다.

### 안정 정렬과 다중 정렬

안정 정렬은 같은 기준값을 가진 원소들의 기존 순서를 유지합니다.

이 성질 덕분에 여러 번 나누어 정렬해도 의도한 순서를 유지할 수 있습니다. 다만 대부분의 코딩 테스트에서는 튜플 key로 한 번에 기준을 주는 방식이 더 명확합니다.

## 12. 자주 하는 실수

* `arr = arr.sort()`처럼 작성해 `arr`가 `None`이 됩니다.
* 원본을 유지해야 하는데 `sort()`로 직접 바꿉니다.
* 다중 기준의 우선순서를 튜플에 잘못 넣습니다.
* 숫자 문자열을 정수로 바꾸지 않아 `"10"`이 `"2"`보다 앞서는 결과가 나옵니다.
* 전체 `reverse=True`를 사용해 이름순까지 반대로 뒤집습니다.
* 딕셔너리 정렬에서 `key`에 존재하지 않는 필드를 사용합니다.
* 정렬 기준이 같은 경우의 처리 규칙을 빼먹습니다.
* 정렬 후 결과를 다시 저장하지 않고 원본이 바뀐 것으로 착각합니다.

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

이 문제는 직접 정렬 알고리즘을 구현하기보다, 어떤 기준으로 정렬해야 하는지 찾는 것이 중요합니다. 기준이 하나인지 여러 개인지 먼저 확인하세요.

### 2단계 힌트: 접근 힌트

원본을 유지해야 하면 `sorted()`를 사용하고, 원본을 바꿔도 된다면 `sort()`를 사용할 수 있습니다. 여러 기준은 `key`에 튜플로 넣어 보세요.

### 3단계 힌트: 구현 힌트

점수 내림차순과 이름 오름차순처럼 방향이 섞이면 `key=lambda x: (-x[점수], x[이름])` 형태를 고려하세요. 전체를 뒤집는 `reverse=True`가 항상 맞지는 않습니다.

## 14. 언제 사용하면 좋은가

* 입력 조건: 데이터 정렬이 필요하고 직접 정렬 구현을 요구하지 않을 때 좋습니다.
* 문제 유형: 좌표 정렬, 학생 정렬, 파일명 정렬, 문자열 길이 정렬, 우선순위 출력에 적합합니다.
* 자주 등장하는 표현: "오름차순", "내림차순", "같으면", "사전순", "기준으로"가 단서입니다.
* 적합한 자료구조: 리스트, 튜플 리스트, 딕셔너리 리스트에 자주 사용합니다.
* 사용하면 안 되는 경우: 매번 데이터가 추가되고 최솟값만 계속 꺼내야 한다면 힙이 더 적합할 수 있습니다. 특정 값 존재 여부만 빠르게 확인해야 한다면 해시가 더 좋습니다.

## 15. 요약 정리

* Python 내장 정렬은 `sorted()`와 `list.sort()`를 사용합니다.
* `sorted()`는 새 리스트를 반환하고, `sort()`는 원본 리스트를 변경합니다.
* 정렬 기준은 `key`로 지정합니다.
* 여러 기준은 튜플로 표현할 수 있습니다.
* 전체 내림차순은 `reverse=True`를 사용할 수 있습니다.
* 기준마다 방향이 다르면 key 값을 조정하는 방식이 유리합니다.
* Python 내장 정렬은 안정 정렬입니다.
* 실전에서는 직접 구현보다 내장 정렬을 정확히 활용하는 능력이 중요합니다.
