# [알고리즘] 동전 문제

## 1. 한 줄 요약

> 동전 문제는 목표 금액을 만들기 위해 현재 사용할 수 있는 가장 큰 동전부터 선택해 동전 개수를 줄이는 그리디 대표 문제입니다.

---

## 2. 선수 지식

- 그리디 알고리즘
  - 매 순간 가장 좋아 보이는 선택을 하는 알고리즘입니다.

- 정렬
  - 동전 단위를 큰 값부터 확인하기 위해 필요합니다.

- 몫과 나머지
  - 특정 동전을 몇 개 사용할 수 있는지 몫으로 구하고, 남은 금액을 나머지로 구합니다.

- 반복문
  - 여러 동전 단위를 차례대로 확인할 때 사용합니다.

- 시간복잡도
  - 동전 종류가 많아질 때 반복 횟수가 얼마나 늘어나는지 판단할 때 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

동전 문제는 주어진 동전 단위로 목표 금액을 만들 때, 사용하는 동전 개수를 최소로 만들고 싶을 때 등장합니다.

### 기존 방식의 문제

- 모든 동전 조합을 확인하면 경우의 수가 많아질 수 있습니다.
- 목표 금액이 커질수록 가능한 조합을 하나씩 따지는 방식은 느려집니다.
- 단순히 작은 동전부터 쓰면 동전 개수가 불필요하게 많아집니다.

예를 들어 780원을 만들 때 10원부터 채우면 78개가 필요합니다. 하지만 500원, 100원, 50원, 10원을 적절히 사용하면 훨씬 적은 개수로 만들 수 있습니다.

### 이 알고리즘을 사용하면

- 큰 단위 동전을 먼저 사용해 남은 금액을 빠르게 줄일 수 있습니다.
- 동전 종류 수만큼만 반복하면 되므로 구현이 간단합니다.
- 동전 단위가 그리디가 통하는 구조라면 최소 개수를 바로 구할 수 있습니다.

단, 모든 동전 체계에서 큰 동전부터 고르는 방식이 항상 최적은 아닙니다. 동전 단위 조건을 확인해야 합니다.

---

## 4. 핵심 아이디어

동전 문제의 그리디 풀이 흐름은 단순합니다.

1. 동전을 큰 단위부터 확인합니다.
2. 현재 동전으로 만들 수 있는 최대 개수를 사용합니다.
3. 남은 금액을 갱신합니다.
4. 남은 금액이 0이 될 때까지 반복합니다.

### 쉬운 비유

상자에 물건을 담을 때 큰 상자부터 쓰면 작은 상자를 여러 개 쓰는 일을 줄일 수 있습니다. 큰 상자에 담을 수 있는 만큼 담고, 남은 물건만 더 작은 상자로 처리합니다.

동전 문제도 비슷합니다. 큰 동전으로 처리할 수 있는 금액은 먼저 처리하고, 남은 금액만 작은 동전으로 넘깁니다.

### 직관적으로 이해하기

동전 단위가 `500, 100, 50, 10`이고 목표 금액이 `760`이라고 해봅시다.

- 500원은 1개 사용할 수 있습니다. 남은 금액은 260원입니다.
- 100원은 2개 사용할 수 있습니다. 남은 금액은 60원입니다.
- 50원은 1개 사용할 수 있습니다. 남은 금액은 10원입니다.
- 10원은 1개 사용할 수 있습니다. 남은 금액은 0원입니다.

총 동전 수는 `1 + 2 + 1 + 1 = 5`개입니다.

## 5. 동작 과정 살펴보기

### 예제 상황

가게에서 1,260원을 거슬러 줘야 합니다. 사용할 수 있는 동전은 `500원, 100원, 50원, 10원`입니다.

### 예제 입력

```text
4 1260
10
50
100
500
```

첫 줄의 `4`는 동전 종류 수, `1260`은 목표 금액입니다. 이후 줄에는 동전 단위가 주어집니다.

### 예제 출력

```text
6
```

### 단계별 동작

1. 동전 단위를 큰 순서로 정렬합니다.
2. 500원 동전을 최대한 사용합니다.
3. 남은 금액을 계산합니다.
4. 100원 동전을 최대한 사용합니다.
5. 같은 방식으로 50원, 10원을 확인합니다.
6. 남은 금액이 0이 되면 사용한 동전 개수를 반환합니다.

실제 계산은 다음과 같습니다.

- 500원 2개 사용, 남은 금액 260원
- 100원 2개 사용, 남은 금액 60원
- 50원 1개 사용, 남은 금액 10원
- 10원 1개 사용, 남은 금액 0원

## 7. 기본 코드 템플릿

```python
def count_min_coins(coin_values, target_amount):
    coin_values.sort(reverse=True)

    used_count = 0
    remaining_amount = target_amount

    for coin in coin_values:
        if remaining_amount == 0:
            break

        coin_count = remaining_amount // coin
        used_count += coin_count
        remaining_amount %= coin

    return used_count


coin_type_count, amount = map(int, input().split())
coins = []

for _ in range(coin_type_count):
    coins.append(int(input()))

answer = count_min_coins(coins, amount)
print(answer)
```

### 코드 흐름 설명

* `coin_values` 리스트에 사용할 수 있는 동전 단위를 저장합니다.
* `sort(reverse=True)`로 큰 동전부터 확인하도록 정렬합니다.
* 반복문은 동전 단위를 하나씩 확인합니다.
* `remaining_amount // coin`은 현재 동전을 몇 개 쓸 수 있는지 계산합니다.
* `remaining_amount %= coin`은 현재 동전을 사용하고 남은 금액을 계산합니다.
* 남은 금액이 0이 되면 더 이상 확인하지 않아도 됩니다.
* 모든 계산이 끝나면 `used_count`가 사용한 동전 개수입니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - 동전 종류 수를 `N`이라고 하면 정렬 때문에 보통 `O(N log N)`입니다.

* 최악의 경우
  - 모든 동전 단위를 확인하므로 정렬 후 반복은 `O(N)`입니다.
  - 전체는 `O(N log N)`으로 볼 수 있습니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 목표 금액 자체보다 동전 종류 수가 더 중요합니다.
  - 이미 큰 순서로 주어진다면 정렬 없이 `O(N)`으로 처리할 수 있습니다.

### 공간복잡도

* 동전 단위를 저장하는 리스트가 `O(N)` 공간을 사용합니다.
* 추가로 사용하는 변수는 많지 않습니다.
* 정렬 방식에 따라 내부적으로 약간의 추가 공간이 사용될 수 있습니다.


동전 단위를 큰 순서로 보면 `500, 100, 50, 10`입니다.

- 현재 금액 890원
  - 500원 1개 사용
  - 남은 금액 390원
- 현재 금액 390원
  - 100원 3개 사용
  - 남은 금액 90원
- 현재 금액 90원
  - 50원 1개 사용
  - 남은 금액 40원
- 현재 금액 40원
  - 10원 4개 사용
  - 남은 금액 0원

### 중간 상태 변화

동전을 사용할 때마다 목표 금액은 `890 → 390 → 90 → 40 → 0`으로 줄어듭니다.

```text

```

총 동전 수는 `1 + 3 + 1 + 4 = 9`개입니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "동전 개수의 최솟값"을 구해야 합니다.
* 동전 단위가 주어지고 목표 금액을 만들어야 합니다.
* 큰 단위부터 선택해도 손해가 없는 구조입니다.
* 동전 단위가 서로 배수 관계라는 조건이 있습니다.
* 매 순간 가장 큰 동전을 최대한 쓰는 전략이 자연스럽게 보입니다.
* 목표 금액을 나누기와 나머지 연산으로 줄일 수 있습니다.
* 모든 조합을 확인하기에는 비효율적입니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 그리디 동전 문제와 DP 동전 문제
  - 그리디는 큰 동전부터 바로 선택합니다.
  - DP는 금액별 최소 동전 수를 계산해 저장합니다.
  - 동전 단위가 특수하지 않으면 DP가 필요할 수 있습니다.

* 완전탐색과 그리디
  - 완전탐색은 가능한 동전 조합을 모두 확인합니다.
  - 그리디는 현재 가장 좋아 보이는 동전을 바로 선택합니다.

* 큰 동전 우선과 항상 최적
  - 큰 동전을 먼저 쓰는 방식이 항상 맞는 것은 아닙니다.
  - 예를 들어 동전이 `1, 4, 6`이고 목표가 `8`이면 6원 1개와 1원 2개보다 4원 2개가 더 적습니다.

* 거스름돈 문제와 일반 최소 동전 문제
  - 거스름돈 문제는 자주 쓰는 동전 체계에서 그리디가 잘 맞는 경우가 많습니다.
  - 일반 최소 동전 문제는 동전 단위 조건을 더 엄격히 확인해야 합니다.

## 12. 자주 하는 실수

* 동전을 작은 단위부터 확인하는 실수
* 동전 단위를 정렬하지 않고 입력 순서만 믿는 실수
* 몫이 아니라 반복해서 하나씩 빼는 비효율적인 코드 작성
* 남은 금액을 나머지로 갱신하지 않는 실수
* 남은 금액이 0인데도 계속 계산하는 실수
* 모든 동전 체계에서 그리디가 항상 최적이라고 착각하는 실수
* 목표 금액을 정확히 만들 수 없는 경우를 고려하지 않는 실수
* 동전 종류 수와 목표 금액 중 무엇이 시간에 영향을 주는지 혼동하는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

현재 남은 금액에서 가장 큰 동전을 먼저 사용할 수 있는지 생각해보세요. 동전 단위가 배수 관계라면 그리디 접근이 잘 맞을 가능성이 큽니다.

### 2단계 힌트: 접근 힌트

동전을 큰 순서로 정렬한 뒤, 각 동전으로 만들 수 있는 최대 개수를 구하세요. 그다음 남은 금액을 다음 작은 동전으로 넘기면 됩니다.

### 3단계 힌트: 구현 힌트

현재 동전 개수는 `남은 금액 // 동전 단위`로 구할 수 있습니다. 남은 금액은 `남은 금액 % 동전 단위`로 갱신하세요.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 동전 단위가 큰 단위부터 선택해도 최적해가 보장되는 구조입니다.

* 문제 유형
  - 거스름돈 계산, 최소 동전 개수, 배수 관계가 있는 동전 단위 문제

* 자주 등장하는 표현
  - "동전의 개수를 최소로", "큰 단위부터", "각 동전은 이전 동전의 배수", "목표 금액"

* 적합한 자료구조
  - 동전 단위를 저장하는 리스트

* 사용하면 안 되는 경우
  - 동전 단위가 그리디 최적성을 보장하지 않는 경우
  - 목표 금액을 만들 수 없는 경우를 따로 판단해야 하는 경우
  - 모든 금액에 대한 최소 개수를 구해야 해서 DP가 더 적합한 경우

## 15. 요약 정리

* 동전 문제의 목적
  - 목표 금액을 만들기 위해 필요한 동전 개수를 최소로 구하는 것입니다.

* 핵심 아이디어
  - 큰 동전부터 가능한 만큼 사용하고 남은 금액을 줄입니다.

* 주요 자료구조
  - 동전 단위를 담는 리스트를 사용합니다.

* 시간복잡도
  - 정렬이 필요하면 `O(N log N)`, 이미 정렬되어 있으면 `O(N)`입니다.

* 문제에서 떠올리는 신호
  - 최소 동전 개수, 목표 금액, 배수 관계의 동전 단위가 보이면 그리디를 떠올릴 수 있습니다.

* 초급자가 주의할 점
  - 모든 동전 문제를 그리디로 풀 수 있는 것은 아니므로 동전 단위 조건을 확인해야 합니다.
