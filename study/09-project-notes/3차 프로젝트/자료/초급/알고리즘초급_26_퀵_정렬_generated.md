# [알고리즘] 퀵 정렬

## 1. 한 줄 요약

> 퀵 정렬은 기준값인 피벗을 고른 뒤 작은 값과 큰 값으로 나누고, 나뉜 부분을 다시 정렬하는 분할 정복 정렬 알고리즘입니다.

---

## 2. 선수 지식

- 배열 또는 리스트
  - 정렬할 데이터를 저장하는 기본 자료구조입니다.

- 재귀 함수
  - 같은 정렬 과정을 더 작은 구간에 반복해서 적용할 때 사용합니다.

- 분할 정복
  - 큰 문제를 작은 문제로 나누어 해결한 뒤 결과를 합치는 방식입니다.

- 피벗
  - 배열을 작은 값 그룹과 큰 값 그룹으로 나누는 기준값입니다.

- 시간복잡도
  - 피벗 선택에 따라 퀵 정렬의 성능이 크게 달라지므로 이해가 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

퀵 정렬은 많은 데이터를 빠르게 정렬해야 할 때 사용하는 대표적인 정렬 알고리즘입니다.

### 기존 방식의 문제

- 버블 정렬, 선택 정렬처럼 단순한 정렬은 구현은 쉽지만 보통 `O(N^2)` 시간이 걸립니다.
- 데이터가 많아지면 모든 원소를 여러 번 비교하는 방식은 느립니다.
- 더 빠른 정렬을 위해서는 문제를 작은 구간으로 나누는 전략이 필요합니다.

예를 들어 10만 개의 숫자를 정렬해야 한다면 단순 정렬은 시간이 오래 걸릴 수 있습니다. 퀵 정렬은 평균적으로 `O(N log N)`에 가까운 성능을 기대할 수 있습니다.

### 이 알고리즘을 사용하면

- 피벗을 기준으로 데이터를 빠르게 둘로 나눌 수 있습니다.
- 각 부분을 독립적으로 정렬할 수 있습니다.
- 평균적으로 빠른 정렬 성능을 얻을 수 있습니다.
- 제자리 정렬 방식으로 구현하면 추가 메모리 사용도 줄일 수 있습니다.

다만 피벗을 나쁘게 고르면 최악의 경우 `O(N^2)`까지 느려질 수 있습니다.

## 4. 핵심 아이디어

퀵 정렬의 핵심은 피벗입니다.

1. 배열에서 기준값 하나를 고릅니다.
2. 기준값보다 작은 값은 왼쪽 그룹으로 보냅니다.
3. 기준값보다 큰 값은 오른쪽 그룹으로 보냅니다.
4. 왼쪽 그룹과 오른쪽 그룹에 같은 작업을 반복합니다.
5. 더 나눌 수 없을 만큼 작아지면 정렬이 끝납니다.

### 쉬운 비유

시험 점수를 정리한다고 생각해봅시다. 먼저 기준 점수 하나를 정합니다. 기준보다 낮은 점수는 왼쪽 묶음, 높은 점수는 오른쪽 묶음에 둡니다.

그다음 왼쪽 묶음에서도 새 기준을 정하고 다시 나눕니다. 오른쪽 묶음도 같은 방식으로 나눕니다. 작은 묶음들이 모두 정리되면 전체 점수도 정렬됩니다.

### 직관적으로 이해하기

배열 `[6, 2, 8, 1, 5]`가 있습니다. 피벗을 `6`으로 잡아봅시다.

- `6`보다 작은 값: `[2, 1, 5]`
- 피벗: `[6]`
- `6`보다 큰 값: `[8]`

이제 `[2, 1, 5]`만 다시 정렬하면 됩니다. 이 작은 배열에서 피벗을 `2`로 잡으면 다음처럼 나뉩니다.

- `2`보다 작은 값: `[1]`
- 피벗: `[2]`
- `2`보다 큰 값: `[5]`

결과를 합치면 `[1, 2, 5, 6, 8]`이 됩니다.

### 예제 상황

숫자 목록을 오름차순으로 정렬합니다. 이해를 쉽게 하기 위해 새 리스트를 만들어 반환하는 방식으로 살펴봅니다.

### 예제 입력

```text
6
7 3 9 1 6 2
```

### 예제 출력

```text
1 2 3 6 7 9
```

### 단계별 동작

1. 첫 번째 값 `7`을 피벗으로 고릅니다.
2. `7`보다 작은 값은 `[3, 1, 6, 2]`로 모읍니다.
3. `7`보다 큰 값은 `[9]`로 모읍니다.
4. 왼쪽 그룹 `[3, 1, 6, 2]`를 다시 퀵 정렬합니다.
5. 오른쪽 그룹 `[9]`는 원소가 하나이므로 그대로 둡니다.
6. 정렬된 왼쪽 그룹, 피벗, 정렬된 오른쪽 그룹을 합칩니다.

## 7. 기본 코드 템플릿

```python
def quick_sort(numbers):
    if len(numbers) <= 1:
        return numbers[:]

    pivot = numbers[len(numbers) // 2]
    smaller = []
    same = []
    larger = []

    for value in numbers:
        if value < pivot:
            smaller.append(value)
        elif value > pivot:
            larger.append(value)
        else:
            same.append(value)

    return quick_sort(smaller) + same + quick_sort(larger)


number_count = int(input())
numbers = list(map(int, input().split()))

answer = quick_sort(numbers)
print(*answer)
```

### 코드 흐름 설명

* `len(numbers) <= 1`이면 이미 정렬된 상태로 봅니다.
* `pivot`은 가운데 위치의 값을 사용합니다.
* `smaller`에는 피벗보다 작은 값을 넣습니다.
* `same`에는 피벗과 같은 값을 넣습니다.
* `larger`에는 피벗보다 큰 값을 넣습니다.
* `smaller`와 `larger`를 다시 `quick_sort`로 정렬합니다.
* 마지막에 `정렬된 작은 값 + 같은 값 + 정렬된 큰 값`을 합칩니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우
  - 피벗이 배열을 적당히 반으로 나누면 `O(N log N)`입니다.

* 최악의 경우
  - 피벗이 계속 가장 작거나 가장 큰 값으로 선택되면 한쪽으로만 나뉩니다.
  - 이 경우 시간복잡도는 `O(N^2)`입니다.

* 입력 크기가 커졌을 때 부담되는 부분
  - 피벗 선택이 나쁘면 재귀 깊이가 길어집니다.
  - 이미 정렬된 배열에서 첫 값이나 마지막 값을 피벗으로 고르면 불리할 수 있습니다.

### 공간복잡도

* 위 코드처럼 새 리스트를 만드는 방식은 추가 공간을 사용합니다.
* 평균적으로 재귀 호출과 임시 리스트 때문에 `O(N log N)`에 가까운 공간 사용이 생길 수 있습니다.
* 인덱스와 swap을 이용한 제자리 구현은 추가 배열 사용을 줄일 수 있습니다.
* 재귀 호출 스택은 평균 `O(log N)`, 최악 `O(N)`까지 늘 수 있습니다.

## 9. 예제로 이해하기

앞에서 사용한 예제와 다른 배열을 보겠습니다.

### 입력 데이터

```text
7
4 8 2 7 3 6 1
```

### 처리 과정

가운데 값 `7`을 피벗으로 잡습니다.

- 작은 값: `[4, 2, 3, 6, 1]`
- 같은 값: `[7]`
- 큰 값: `[8]`

이제 작은 값 그룹 `[4, 2, 3, 6, 1]`을 다시 정렬합니다. 가운데 값 `3`을 피벗으로 잡으면 다음처럼 나뉩니다.

- 작은 값: `[2, 1]`
- 같은 값: `[3]`
- 큰 값: `[4, 6]`

각 그룹이 더 작아질 때까지 같은 작업을 반복합니다.

### 중간 상태 변화

분할이 반복될수록 배열은 작은 독립 구간으로 나뉩니다. 길이가 0 또는 1인 구간은 더 정렬할 필요가 없습니다.

### 최종 결과

```text
1 2 3 4 6 7 8
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 많은 데이터를 빠르게 정렬해야 합니다.
* 분할 정복 방식으로 설명할 수 있는 정렬 문제가 나옵니다.
* 피벗을 기준으로 작은 값과 큰 값을 나누는 조건이 보입니다.
* 평균적으로 빠른 정렬이 필요합니다.
* 정렬 과정을 직접 구현해야 합니다.
* 추가 메모리를 줄인 제자리 정렬 구현이 요구될 수 있습니다.
* 같은 값의 원래 순서가 반드시 유지될 필요는 없습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 퀵 정렬과 병합 정렬
  - 퀵 정렬은 피벗 기준으로 나누고 정렬합니다.
  - 병합 정렬은 배열을 반으로 나눈 뒤 정렬된 결과를 병합합니다.

* 퀵 정렬과 선택 정렬
  - 선택 정렬은 매번 최솟값 또는 최댓값을 찾아 위치를 확정합니다.
  - 퀵 정렬은 피벗을 기준으로 여러 값을 한 번에 분할합니다.

* 퀵 정렬과 버블 정렬
  - 버블 정렬은 인접한 값끼리 계속 교환합니다.
  - 퀵 정렬은 피벗을 중심으로 구간을 나눕니다.

* 제자리 퀵 정렬과 리스트 기반 퀵 정렬
  - 제자리 구현은 원본 배열 내부에서 swap합니다.
  - 리스트 기반 구현은 이해하기 쉽지만 추가 메모리를 더 사용합니다.

* 안정 정렬과 불안정 정렬
  - 퀵 정렬은 일반적으로 불안정 정렬입니다.
  - 같은 값의 상대적 순서가 중요하다면 주의해야 합니다.

## 12. 자주 하는 실수

* 재귀 종료 조건을 빠뜨리는 실수
* 피벗을 결과에 포함하지 않는 실수
* 피벗과 같은 값을 처리하지 않아 무한 재귀가 생기는 실수
* 작은 값 그룹과 큰 값 그룹의 기준을 반대로 쓰는 실수
* 이미 정렬된 입력에서 나쁜 피벗을 골라 성능이 나빠지는 실수
* 제자리 구현에서 left와 right 포인터 이동 조건을 잘못 쓰는 실수
* 재귀 호출 범위를 잘못 지정해 일부 구간이 정렬되지 않는 실수
* Python에서 큰 입력에 재귀 깊이 제한을 고려하지 않는 실수

## 13. 힌트 생성용 관점

이 문서는 RAG 기반 AI 튜터의 힌트 생성에도 활용될 수 있습니다.

### 1단계 힌트: 개념 힌트

기준값 하나를 정하고, 그 값보다 작은 원소와 큰 원소를 나누는 방식으로 생각해보세요.

### 2단계 힌트: 접근 힌트

배열을 피벗 기준으로 세 그룹으로 나누세요. 작은 값, 같은 값, 큰 값으로 분리하면 중복 값도 안전하게 처리할 수 있습니다.

### 3단계 힌트: 구현 힌트

길이가 1 이하인 리스트는 그대로 반환하세요. 그 외에는 `quick_sort(작은 값) + 같은 값 + quick_sort(큰 값)` 구조로 작성하면 됩니다.

## 14. 언제 사용하면 좋은가

* 입력 조건
  - 평균적으로 빠른 정렬이 필요하고, 최악의 피벗 상황을 어느 정도 피할 수 있는 경우

* 문제 유형
  - 정렬 직접 구현, 분할 정복 학습, 피벗 기반 분할 문제

* 자주 등장하는 표현
  - "피벗", "분할", "왼쪽과 오른쪽 구간", "재귀 정렬", "작은 값과 큰 값"

* 적합한 자료구조
  - 리스트 또는 배열

* 사용하면 안 되는 경우
  - 안정 정렬이 반드시 필요한 경우
  - 재귀 깊이 제한이 큰 문제가 되는 환경
  - 최악의 경우까지 안정적으로 `O(N log N)`을 보장해야 하는 경우

## 15. 요약 정리

* 퀵 정렬의 목적
  - 피벗을 기준으로 데이터를 나누며 빠르게 정렬하는 것입니다.

* 핵심 아이디어
  - 작은 값, 피벗, 큰 값으로 분할하고 각 부분을 재귀적으로 정렬합니다.

  - 리스트 또는 배열을 사용합니다.

* 시간복잡도
  - 평균은 `O(N log N)`, 최악은 `O(N^2)`입니다.

* 문제에서 떠올리는 신호
  - 피벗, 분할, 재귀, 빠른 비교 정렬이 핵심인 문제입니다.

* 초급자가 주의할 점
  - 피벗과 같은 값을 반드시 처리하고, 재귀 종료 조건을 명확히 작성해야 합니다.
