# [알고리즘] 병합 정렬

## 1. 한 줄 요약

> 병합 정렬은 데이터를 계속 반으로 나눈 뒤, 작은 묶음부터 정렬해서 다시 합치며 전체를 정렬하는 알고리즘입니다.

---

## 2. 선수 지식

- 리스트 또는 배열: 여러 값을 순서대로 저장하고 인덱스로 접근하는 자료구조입니다.
- 재귀 함수: 함수가 자기 자신을 다시 호출하는 방식입니다.
- 분할 정복: 큰 문제를 작은 문제로 나눈 뒤, 작은 문제의 결과를 합쳐 전체 문제를 해결하는 생각법입니다.
- 인덱스 범위: 리스트에서 어느 위치부터 어느 위치까지 다룰지 정하는 기준입니다.
- 안정 정렬: 값이 같은 원소들의 기존 순서가 정렬 후에도 유지되는 정렬 방식입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

### 기존 방식의 문제

- 선택 정렬이나 삽입 정렬처럼 단순한 정렬은 구현이 쉽지만, 데이터가 많아지면 비교 횟수가 빠르게 늘어납니다.
- 원소가 1,000개일 때는 괜찮아 보여도, 100,000개 이상이 되면 모든 원소를 여러 번 훑는 방식은 부담이 큽니다.
- 특히 입력 크기가 큰 정렬 문제에서는 `O(n^2)` 방식으로 시간 제한을 통과하기 어렵습니다.

### 이 알고리즘을 사용하면

- 병합 정렬은 입력을 반으로 나누기 때문에 문제 크기가 빠르게 줄어듭니다.
- 각 단계에서 전체 원소를 한 번씩 보면서 합치므로 전체 시간은 `O(n log n)`으로 유지됩니다.
- 데이터가 이미 정렬되어 있든, 거꾸로 되어 있든, 섞여 있든 비교적 일정한 성능을 냅니다.

예를 들어 숫자 카드 8장을 정렬한다고 생각해 봅시다. 처음부터 모든 카드를 서로 비교하기보다, 4장씩 나누고, 2장씩 나누고, 1장씩 만든 뒤 다시 정렬하며 합치면 더 체계적으로 처리할 수 있습니다.

## 4. 핵심 아이디어

### 쉬운 비유

책상 위에 이름표가 뒤섞여 있다고 생각해 봅시다. 한 사람이 모든 이름표를 한꺼번에 정렬하려면 헷갈릴 수 있습니다. 대신 이름표를 반씩 나누어 여러 묶음으로 만들고, 아주 작은 묶음부터 차례대로 정렬해서 합치면 훨씬 덜 복잡합니다.

병합 정렬도 같은 방식입니다. 먼저 정렬하기 쉬울 만큼 작게 나눕니다. 원소가 하나뿐인 리스트는 이미 정렬된 상태로 볼 수 있습니다. 그다음 정렬된 두 묶음을 비교하면서 하나의 정렬된 묶음으로 합칩니다.

### 직관적으로 이해하기

`[8, 3, 6, 1]`을 정렬한다고 해 봅시다.

- `[8, 3]`과 `[6, 1]`로 나눕니다.
- `[8]`, `[3]`, `[6]`, `[1]`처럼 원소 하나짜리 묶음까지 나눕니다.
- `[8]`과 `[3]`을 합치면 `[3, 8]`이 됩니다.
- `[6]`과 `[1]`을 합치면 `[1, 6]`이 됩니다.
- `[3, 8]`과 `[1, 6]`을 비교하며 합치면 `[1, 3, 6, 8]`이 됩니다.

중요한 점은 "나누는 것" 자체가 정렬을 끝내는 것이 아니라는 점입니다. 실제 정렬은 이미 정렬된 두 묶음을 다시 합치는 과정에서 일어납니다.

## 5. 동작 과정 살펴보기

### 예제 상황

학생들의 제출 번호가 섞여 있습니다. 번호를 오름차순으로 정렬하려고 합니다.

### 예제 입력

```text
7 2 9 4 1 5
```

### 예제 출력

```text
1 2 4 5 7 9
```

### 단계별 동작

1. 전체 리스트 `[7, 2, 9, 4, 1, 5]`를 확인합니다.
2. 가운데를 기준으로 `[7, 2, 9]`와 `[4, 1, 5]`로 나눕니다.
3. 각 묶음을 다시 나누어 원소가 하나인 묶음까지 만듭니다.
4. 원소 하나짜리 묶음은 이미 정렬되어 있으므로, 두 묶음을 비교하며 작은 값부터 새 묶음에 넣습니다.
5. `[2, 7, 9]`와 `[1, 4, 5]`처럼 정렬된 큰 묶음이 만들어집니다.
6. 마지막으로 두 묶음의 맨 앞 값을 비교하며 하나의 정렬된 리스트로 합칩니다.

## 7. 기본 코드 템플릿

```python
def combine_sorted_parts(first_part, second_part):
    sorted_numbers = []
    first_index = 0
    second_index = 0

    while first_index < len(first_part) and second_index < len(second_part):
        if first_part[first_index] <= second_part[second_index]:
            sorted_numbers.append(first_part[first_index])
            first_index += 1
        else:
            sorted_numbers.append(second_part[second_index])
            second_index += 1

    while first_index < len(first_part):
        sorted_numbers.append(first_part[first_index])
        first_index += 1

    while second_index < len(second_part):
        sorted_numbers.append(second_part[second_index])
        second_index += 1

    return sorted_numbers


def merge_sort_numbers(numbers):
    if len(numbers) <= 1:
        return numbers

    center = len(numbers) // 2
    left_sorted = merge_sort_numbers(numbers[:center])
    right_sorted = merge_sort_numbers(numbers[center:])

    return combine_sorted_parts(left_sorted, right_sorted)


sample_numbers = [12, 4, 15, 3, 9, 6]
print(merge_sort_numbers(sample_numbers))
```

### 코드 흐름 설명

* 리스트를 사용해 정렬할 숫자들을 저장합니다.
* `merge_sort_numbers` 함수는 리스트를 반으로 나누고, 왼쪽과 오른쪽을 각각 다시 정렬합니다.
* 재귀는 리스트 길이가 1 이하가 될 때 멈춥니다.
* `combine_sorted_parts` 함수는 이미 정렬된 두 리스트를 앞에서부터 비교합니다.
* 조건문은 두 리스트의 현재 값 중 더 작은 값을 고릅니다.
* 한쪽 리스트를 모두 사용하면, 남아 있는 다른 쪽 원소를 결과 뒤에 붙입니다.
* 마지막 병합이 끝나면 전체 정렬 결과가 확정됩니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: `O(n log n)`입니다.
* 최악의 경우: `O(n log n)`입니다.
* 리스트를 계속 반으로 나누면 단계 수는 `log n`개가 됩니다. 각 단계에서 전체 원소를 한 번씩 병합하므로 전체 시간은 `n log n`이 됩니다.
* 입력이 커졌을 때 부담되는 부분은 병합 과정입니다. 각 단계마다 모든 원소가 한 번씩 결과 리스트에 들어가기 때문입니다.

### 공간복잡도

* 일반적인 구현에서는 병합 결과를 저장할 추가 리스트가 필요합니다.
* 슬라이싱을 사용하면 재귀 호출마다 새 리스트가 만들어지므로 메모리 사용이 더 늘어날 수 있습니다.
* 보통 추가 공간은 `O(n)`으로 설명합니다.
* 재귀 호출을 사용하므로 호출 스택도 필요하지만, 핵심 부담은 병합에 사용하는 임시 저장 공간입니다.

## 9. 예제로 이해하기

입력 데이터가 다음과 같다고 해 봅시다.

```text
10 8 11 2 7
```

처리 과정은 다음과 같습니다.

1. `[10, 8, 11, 2, 7]`을 `[10, 8]`과 `[11, 2, 7]`로 나눕니다.
2. `[10, 8]`은 `[10]`과 `[8]`로 나뉘고, 다시 합칠 때 `[8, 10]`이 됩니다.
3. `[11, 2, 7]`은 `[11]`과 `[2, 7]`로 나뉩니다.
4. `[2, 7]`은 `[2]`와 `[7]`로 나뉘고, 합치면 `[2, 7]`입니다.
5. `[11]`과 `[2, 7]`을 합치면 `[2, 7, 11]`이 됩니다.
6. 마지막으로 `[8, 10]`과 `[2, 7, 11]`을 합칩니다.

중간 상태는 다음처럼 변합니다.

```text
[10, 8, 11, 2, 7]
→ [10, 8] + [11, 2, 7]
→ [8, 10] + [2, 7, 11]
→ [2, 7, 8, 10, 11]
```

최종 결과는 다음과 같습니다.

```text
2 7 8 10 11
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 많은 수를 정렬해야 합니다.
* 입력 크기가 커서 `O(n^2)` 정렬로는 부족해 보입니다.
* 최악의 경우에도 일정한 정렬 시간이 필요합니다.
* 안정 정렬이 중요합니다.
* "나누고 합친다", "구간을 반으로 나눈다", "정렬된 두 묶음을 합친다" 같은 흐름이 자연스럽게 보입니다.
* 연결 리스트처럼 중간 삽입보다 순차적인 병합이 어울리는 자료구조를 다룹니다.
* 직접 정렬 알고리즘을 구현해야 하며, 내장 정렬을 사용할 수 없습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

* 퀵 정렬과 병합 정렬은 둘 다 분할 정복을 사용합니다. 퀵 정렬은 기준값을 중심으로 먼저 위치를 나누고, 병합 정렬은 반으로 나눈 뒤 합칠 때 정렬합니다.
* 힙 정렬은 힙 자료구조를 이용해 가장 큰 값이나 작은 값을 꺼내며 정렬합니다. 병합 정렬은 두 정렬된 묶음을 순서대로 합칩니다.
* 삽입 정렬은 작은 입력에서 간단하고 빠를 수 있지만, 큰 입력에서는 병합 정렬보다 느려질 수 있습니다.
* 병합 정렬은 안정 정렬로 만들기 쉽습니다. 두 값이 같을 때 왼쪽 묶음의 값을 먼저 선택하면 기존 순서를 유지할 수 있습니다.
* 병합 정렬은 추가 메모리를 사용합니다. 제자리 정렬이 꼭 필요한 상황에서는 다른 정렬이 더 적합할 수 있습니다.

## 12. 자주 하는 실수

* 재귀 종료 조건을 빠뜨려 함수 호출이 끝나지 않는 실수
* 리스트 길이가 1일 때 그대로 반환하지 않는 실수
* 가운데 인덱스를 잘못 계산해 일부 원소가 빠지는 실수
* 병합할 때 한쪽 리스트에 남은 원소를 붙이지 않는 실수
* 값이 같은 경우를 고려하지 않아 안정 정렬 성질이 깨지는 실수
* 슬라이싱이 새 리스트를 만든다는 점을 모르고 메모리 사용량을 과소평가하는 실수
* 두 포인터 중 하나만 증가시키거나, 잘못된 포인터를 증가시키는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

정렬해야 할 데이터가 많다면 단순히 모든 원소를 계속 비교하는 방식보다, 문제를 작은 구간으로 나누어 생각해 보세요. 원소 하나짜리 구간은 이미 정렬되어 있다는 점이 출발점입니다.

### 2단계 힌트: 접근 힌트

먼저 리스트를 반으로 나누고, 왼쪽과 오른쪽을 각각 정렬된 상태로 만들어 보세요. 그다음 두 정렬된 리스트의 맨 앞 값을 비교하면서 작은 값부터 결과에 넣으면 됩니다.

### 3단계 힌트: 구현 힌트

재귀 함수 하나는 리스트를 나누는 역할을 맡고, 다른 함수는 정렬된 두 리스트를 합치는 역할을 맡게 만들면 구현이 단순해집니다. 병합 함수에서는 왼쪽 인덱스와 오른쪽 인덱스를 따로 두고, 한쪽이 끝난 뒤 남은 원소를 반드시 추가해야 합니다.

## 14. 언제 사용하면 좋은가

* 입력 조건: 정렬할 원소 수가 많고, `O(n log n)` 수준의 정렬이 필요할 때 좋습니다.
* 문제 유형: 직접 정렬 구현, 안정 정렬, 큰 데이터 정렬, 외부 정렬 개념과 관련된 문제에 어울립니다.
* 자주 등장하는 표현: "오름차순으로 정렬", "정렬된 두 배열 병합", "구간을 나누어 처리" 같은 표현이 단서가 됩니다.
* 적합한 자료구조: 배열, 리스트, 연결 리스트에 적용할 수 있습니다.
* 사용하면 안 되는 경우: 추가 메모리가 매우 제한되어 있거나, 입력 크기가 작아 단순 정렬이 더 간단한 경우에는 과한 선택일 수 있습니다.
