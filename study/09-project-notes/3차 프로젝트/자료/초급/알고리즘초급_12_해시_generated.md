# [알고리즘] 해시

## 1. 한 줄 요약

> 해시는 키를 이용해 데이터를 빠르게 저장하고 찾기 위한 자료구조이며, 코딩 테스트에서는 주로 `dict`와 `set`으로 중복 확인, 개수 세기, 빠른 조회를 처리할 때 사용합니다.

---

## 2. 선수 지식

- 배열: 해시 테이블 내부에서 데이터를 담는 기본 공간으로 생각할 수 있습니다.
- 키와 값: 키는 데이터를 찾기 위한 이름이고, 값은 키에 연결된 실제 정보입니다.
- 인덱스: 배열에서 데이터를 저장할 위치입니다.
- 나머지 연산: 큰 숫자를 정해진 범위 안의 인덱스로 바꿀 때 사용합니다.
- 딕셔너리: Python에서 키와 값을 저장하는 대표적인 해시 기반 자료구조입니다.
- 집합: Python에서 중복 없는 값들을 저장하고 존재 여부를 빠르게 확인하는 자료구조입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

해시는 "어떤 값이 이미 나왔는지", "몇 번 나왔는지", "이 키에 연결된 값이 무엇인지"를 빠르게 확인해야 할 때 사용합니다.

### 기존 방식의 문제

- 리스트에서 특정 값이 있는지 찾으려면 앞에서부터 하나씩 확인해야 합니다.
- 값이 많아질수록 조회 시간이 오래 걸립니다.
- 같은 값을 몇 번 봤는지 세려면 매번 전체 목록을 다시 확인해야 할 수 있습니다.
- 두 데이터 사이의 관계를 저장하려면 인덱스만으로는 표현하기 어렵습니다.

예를 들어 학생 이름으로 점수를 찾아야 한다고 해 봅시다. 리스트에 `(이름, 점수)`를 넣고 매번 처음부터 찾으면 학생 수가 많을수록 느려집니다.

### 이 알고리즘을 사용하면

- 이름을 키로, 점수를 값으로 저장해 바로 조회할 수 있습니다.
- 이미 등장한 값인지 평균적으로 빠르게 확인할 수 있습니다.
- 문자열, 숫자 같은 다양한 키를 기준으로 데이터를 묶을 수 있습니다.
- 빈도 계산, 중복 제거, 빠른 매칭 문제를 간단하게 풀 수 있습니다.

## 4. 핵심 아이디어

해시의 핵심은 키를 배열의 위치로 바꾸는 것입니다.

해시 함수는 키를 입력받아 숫자 형태의 해시 값을 만들고, 그 값을 테이블 크기에 맞는 인덱스로 바꿉니다. 그러면 데이터를 저장할 위치를 빠르게 정할 수 있습니다.

다만 서로 다른 키가 같은 인덱스로 바뀔 수 있습니다. 이것을 충돌이라고 합니다. 해시 테이블은 충돌을 처리하는 방법을 함께 가지고 있어야 안정적으로 동작합니다.

### 쉬운 비유

도서관에서 책 제목만 보고 책을 찾는다고 생각해 봅시다. 모든 책장을 처음부터 훑으면 오래 걸립니다.

대신 제목을 기준으로 어느 구역에 꽂을지 규칙을 정해 두면 찾는 속도가 빨라집니다. 예를 들어 제목의 첫 글자에 따라 구역을 나누는 식입니다.

하지만 같은 구역에 책이 여러 권 몰릴 수 있습니다. 이때 그 구역 안에서 다시 순서대로 찾거나, 옆 구역의 빈칸을 쓰는 규칙이 필요합니다. 이것이 해시 충돌 처리와 비슷합니다.

### 직관적으로 이해하기

`"apple"`이라는 키를 저장한다고 해 봅시다.

1. 해시 함수가 `"apple"`을 어떤 숫자로 바꿉니다.
2. 그 숫자를 테이블 크기로 나눈 나머지를 구합니다.
3. 나온 인덱스에 `"apple"`과 연결된 값을 저장합니다.
4. 나중에 `"apple"`을 찾을 때 같은 계산을 다시 해서 같은 위치로 갑니다.

그래서 해시는 빠릅니다. 키를 보고 저장 위치를 직접 계산하기 때문입니다.

## 5. 동작 과정 살펴보기

### 예제 상황

동아리 신청자 명단에서 각 학년이 몇 명씩 신청했는지 세려고 합니다.

### 예제 입력

```text
grades = ["1학년", "2학년", "1학년", "3학년", "2학년", "1학년"]
```

### 예제 출력

```text

2학년: 2
3학년: 1
```

### 단계별 동작

1. 빈 딕셔너리를 준비합니다.
2. 첫 번째 값 `"1학년"`을 확인합니다.
3. 딕셔너리에 없으면 `"1학년": 1`로 저장합니다.
4. 이미 있는 학년이 다시 나오면 값을 1 증가시킵니다.
5. 모든 값을 처리할 때까지 반복합니다.
6. 딕셔너리에 남은 키와 값이 빈도 결과입니다.

## 7. 기본 코드 템플릿

```python
def count_values(items):
    counter = {}

    for item in items:
        if item not in counter:
            counter[item] = 0
        counter[item] += 1

    return counter


def has_duplicate(items):
    seen = set()

    for item in items:
        if item in seen:
            return True
        seen.add(item)

    return False


def find_missing_name(expected, completed):
    name_count = {}

    for name in expected:
        name_count[name] = name_count.get(name, 0) + 1

    for name in completed:
        name_count[name] -= 1

    for name, count in name_count.items():
        if count > 0:
            return name

    return None


if __name__ == "__main__":
    print(count_values(["blue", "red", "blue", "green", "red", "blue"]))
    print(has_duplicate(["A12", "B07", "C31", "B07"]))
    print(find_missing_name(["nara", "jisu", "nara", "min"], ["jisu", "nara", "min"]))
```

### 코드 흐름 설명

* `count_values`는 값이 몇 번 등장했는지 딕셔너리에 저장합니다.
* `counter[item]`에서 `item`은 키이고, 등장 횟수는 값입니다.
* `has_duplicate`는 이미 본 값을 `set`에 저장합니다.
* `set`은 값의 존재 여부를 빠르게 확인할 때 적합합니다.
* `find_missing_name`은 이름별 개수를 먼저 세고, 완료된 이름을 하나씩 빼는 방식입니다.
* 같은 이름이 여러 번 나올 수 있으므로 단순한 `set`이 아니라 개수를 저장하는 딕셔너리를 사용합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 해시 테이블의 삽입, 삭제, 조회는 평균적으로 `O(1)`입니다.
* 데이터 `n`개를 한 번씩 처리하면 보통 `O(n)`에 해결됩니다.
* 충돌이 심하게 몰리면 한 버킷 안에서 여러 값을 확인해야 하므로 최악의 경우 `O(n)`까지 느려질 수 있습니다.
* 실제 코딩 테스트에서는 Python의 `dict`, `set`을 사용하면 평균적인 빠른 성능을 기대할 수 있습니다.

### 공간복잡도

* 서로 다른 키가 최대 `n`개라면 `O(n)` 공간이 필요합니다.
* 해시 테이블은 빠른 조회를 위해 내부적으로 여유 공간을 둘 수 있습니다.
* 빈도 계산이나 중복 확인 문제에서는 입력과 별도로 키 저장 공간이 필요합니다.

## 9. 예제로 이해하기

이번에는 주문 목록에서 가장 많이 주문된 음료를 찾겠습니다.

입력 데이터:

```text
orders = ["tea", "coffee", "tea", "juice", "coffee", "tea"]
```

처리 과정:

1. 빈 딕셔너리 `{}`를 준비합니다.
2. `"tea"`를 보고 `{"tea": 1}`로 저장합니다.
3. `"coffee"`를 보고 `{"tea": 1, "coffee": 1}`로 저장합니다.
4. `"tea"`가 다시 나오면 `{"tea": 2, "coffee": 1}`이 됩니다.
5. `"juice"`를 추가합니다.
6. `"coffee"`의 개수를 2로 올립니다.
7. 마지막 `"tea"`를 처리하면 `"tea"`의 개수는 3이 됩니다.

최종 상태:

```text
{
  "tea": 3,
  "coffee": 2,
  "juice": 1
}
```

해시는 여기서 "이 음료를 전에 본 적이 있는가?"와 "현재 몇 번 나왔는가?"를 빠르게 처리합니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "중복을 제거하라"는 조건이 있습니다.
* "몇 번 등장했는지 세라"는 조건이 있습니다.
* 이름, 문자열, 번호 같은 키로 정보를 찾아야 합니다.
* 두 목록을 비교해서 빠진 값이나 공통 값을 찾아야 합니다.
* 특정 값이 존재하는지 여러 번 확인해야 합니다.
* 정렬 순서보다 빠른 조회가 더 중요합니다.
* `O(n^2)` 탐색으로는 시간 초과가 날 것 같습니다.
* 전화번호부, 참가자 명단, 단어 빈도, 의상 종류, 신고 기록 같은 데이터가 등장합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 해시와 배열

배열은 인덱스로 값을 찾습니다. 해시는 키를 인덱스처럼 사용할 수 있게 해 줍니다.

숫자 인덱스가 아니라 문자열이나 객체를 기준으로 찾고 싶다면 해시가 더 자연스럽습니다.

### 해시와 정렬

정렬은 순서를 만들어 비교하기 좋습니다. 해시는 순서보다 빠른 존재 확인과 조회에 강합니다.

순서가 필요하면 정렬을, 빠른 조회가 필요하면 해시를 먼저 떠올리면 됩니다.

### 해시와 트리

해시는 평균적으로 단일 조회가 빠릅니다. 트리는 정렬된 순서나 범위 검색에 유리합니다.

예를 들어 특정 이름의 점수만 찾는다면 해시가 좋고, 70점 이상 90점 이하의 학생을 순서대로 찾는다면 트리가 더 어울릴 수 있습니다.

### `dict`와 `set`

`dict`는 키에 값을 연결합니다. 예를 들어 이름별 점수, 단어별 개수를 저장합니다.

`set`은 값의 존재 여부만 중요할 때 사용합니다. 예를 들어 이미 나온 번호인지 확인할 때 적합합니다.

## 12. 자주 하는 실수

* 같은 키가 다시 나왔을 때 값을 덮어쓸지, 개수를 증가시킬지 구분하지 않습니다.
* 중복 값이 있을 수 있는데 `set`만 사용해 개수 정보를 잃어버립니다.
* 딕셔너리에 없는 키를 바로 조회해 오류가 발생합니다.
* 키로 사용할 수 없는 mutable 객체를 그대로 사용하려고 합니다.
* 해시는 항상 `O(1)`이라고만 생각하고 충돌이나 최악의 경우를 무시합니다.
* 순서가 필요한 문제인데 해시만 사용해 정렬 조건을 놓칩니다.
* 값 기준으로 찾아야 하는데 키 기준 자료구조인 해시에 억지로 맞춥니다.
* 같은 데이터라도 대소문자나 공백이 다르면 다른 키가 된다는 점을 놓칩니다.

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

이 문제는 값을 반복해서 찾거나, 이미 등장했는지 확인해야 합니다. 매번 리스트를 처음부터 찾지 말고, 키로 바로 접근할 수 있는 자료구조를 생각해 보세요.

### 2단계 힌트: 접근 힌트

값의 존재 여부만 필요하면 `set`, 값별 개수나 연결된 정보가 필요하면 `dict`를 사용해 보세요. 데이터를 한 번 순회하면서 해시 테이블에 기록하면 됩니다.

### 3단계 힌트: 구현 힌트

딕셔너리에서 `get(key, 0)`을 사용하면 처음 나온 키도 안전하게 처리할 수 있습니다. 중복이 있는 목록 비교 문제라면 한쪽에서 개수를 더하고 다른 쪽에서 개수를 빼는 방식을 고려하세요.

## 14. 언제 사용하면 좋은가

* 입력 조건: 데이터가 많고 조회, 삽입, 삭제가 자주 일어날 때 좋습니다.
* 문제 유형: 빈도 계산, 중복 확인, 빠진 값 찾기, 두 배열 비교, 문자열 매칭, 그룹 묶기에 적합합니다.
* 자주 등장하는 표현: "존재하는지", "몇 개", "같은 값", "중복", "서로 대응", "이름별" 같은 표현이 단서입니다.
* 적합한 자료구조: Python에서는 `dict`, `set`, `collections.Counter`, `defaultdict`가 자주 쓰입니다.
* 사용하면 안 되는 경우: 정렬된 순서, 범위 검색, 최소/최대 순차 접근이 핵심이라면 정렬, 힙, 트리 계열 접근이 더 적합할 수 있습니다.

## 15. 요약 정리

* 해시는 키를 이용해 값을 빠르게 저장하고 찾는 자료구조입니다.
* 해시 함수는 키를 해시 값으로 바꾸고, 그 값을 저장 위치로 연결합니다.

* 빈도 계산은 `dict`, 존재 확인과 중복 제거는 `set`을 먼저 떠올리면 좋습니다.
* 순서가 필요한 문제인지, 빠른 조회가 필요한 문제인지 먼저 구분해야 합니다.
