# [알고리즘] 브루트포스

## 1. 한 줄 요약

> 브루트포스는 가능한 답 후보를 전부 만들어 보고, 조건에 맞는 후보를 하나씩 확인해서 정답을 찾는 탐색 방법입니다.

---

## 2. 선수 지식

- 반복문: 후보를 순서대로 확인할 때 사용합니다.
- 조건문: 현재 후보가 문제의 조건을 만족하는지 판단합니다.
- 배열과 리스트: 입력값을 저장하고 인덱스로 접근할 때 필요합니다.
- 재귀: 선택을 여러 단계로 이어 가야 할 때 사용할 수 있습니다.
- 조합과 순열: 여러 값 중 일부를 고르거나 순서를 만들어야 하는 문제에서 자주 등장합니다.
- 시간복잡도: 모든 후보를 확인해도 제한 시간 안에 끝나는지 판단하기 위해 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

브루트포스는 "가능한 경우를 모두 확인하면 답을 구할 수 있는 문제"에서 사용합니다.

### 기존 방식의 문제

- 답을 바로 계산하는 공식이 떠오르지 않을 수 있습니다.
- 조건이 복잡하면 어떤 후보가 정답인지 한 번에 판단하기 어렵습니다.
- 아직 더 좋은 알고리즘을 찾지 못했을 때 풀이 방향을 잡기 어렵습니다.

예를 들어 여러 숫자 중 두 개를 골라 목표값에 가장 가까운 합을 찾아야 한다고 해봅시다. 규칙을 바로 찾기 어렵다면, 일단 모든 두 숫자 조합을 확인하는 방식으로 정답을 구할 수 있습니다.

### 이 알고리즘을 사용하면

- 정답 후보를 빠짐없이 확인하므로 조건을 만족하는 답을 놓칠 가능성이 낮습니다.
- 구현이 단순해서 작은 입력에서는 실수 없이 풀기 좋습니다.
- 더 효율적인 풀이를 생각하기 전, 문제의 구조를 이해하는 기준 풀이가 됩니다.

다만 브루트포스는 입력 크기가 커졌을 때 유리한 알고리즘이 아닙니다. 후보 수가 너무 많아지면 실행 시간이 크게 늘어납니다. 그래서 문제의 입력 제한을 먼저 보고, 모든 후보를 검사해도 되는지 계산해야 합니다.

---

## 4. 핵심 아이디어

브루트포스의 핵심은 "후보 생성"과 "조건 검사"입니다.

1. 만들 수 있는 후보를 정합니다.
2. 후보를 하나씩 꺼냅니다.
3. 문제 조건에 맞는지 검사합니다.
4. 맞으면 정답을 갱신하거나 바로 종료합니다.
5. 모든 후보를 확인할 때까지 반복합니다.

### 쉬운 비유

여러 개의 열쇠가 섞여 있고, 그중 하나만 문을 열 수 있다고 생각해봅시다. 열쇠 모양만 보고 답을 알 수 없다면, 열쇠를 하나씩 꽂아 보는 방법이 있습니다. 오래 걸릴 수는 있지만, 열쇠가 많지 않다면 확실하게 맞는 열쇠를 찾을 수 있습니다.

브루트포스도 이와 비슷합니다. 가능한 후보가 많지 않다면 하나씩 검사하는 것이 가장 단순하고 확실한 방법입니다.

### 직관적으로 이해하기

숫자 카드 `[2, 4, 7, 9]` 중 두 장을 골라 합이 `11`이 되는 경우를 찾는다고 해봅시다.

- `2 + 4 = 6`
- `2 + 7 = 9`
- `2 + 9 = 11`
- `4 + 7 = 11`
- `4 + 9 = 13`
- `7 + 9 = 16`

모든 쌍을 확인하면 `2와 9`, `4와 7`이 조건을 만족한다는 것을 알 수 있습니다. 후보를 건너뛰지 않았기 때문에 정답을 놓치지 않습니다.

## 5. 동작 과정 살펴보기

### 예제 상황

가게에서 간식 두 개를 고르려고 합니다. 예산을 넘지 않으면서 가능한 한 예산에 가까운 합을 만들고 싶습니다.

### 예제 입력

```text
5 12
2 5 8 4 7
```

첫 줄의 `5`는 간식 개수, `12`는 예산입니다. 둘째 줄은 각 간식의 가격입니다.

### 예제 출력

```text
12
```

`5 + 7 = 12`이므로 예산을 넘지 않는 가장 좋은 합은 `12`입니다.

### 단계별 동작

1. 가격 목록과 예산을 확인합니다.
2. 첫 번째 간식을 고정하고, 그 뒤의 간식들을 하나씩 짝지어 봅니다.
3. 두 가격의 합을 계산합니다.
4. 합이 예산을 넘으면 후보에서 제외합니다.
5. 합이 예산 이하이고 지금까지의 최고 합보다 크면 정답을 갱신합니다.
6. 모든 두 간식 조합을 확인한 뒤 최종 정답을 출력합니다.

## 7. 기본 코드 템플릿

```python
def best_pair_sum_under_limit(values, limit):
    best_sum = -1

    for first_index in range(len(values)):
        for second_index in range(first_index + 1, len(values)):
            current_sum = values[first_index] + values[second_index]

            if current_sum <= limit and current_sum > best_sum:
                best_sum = current_sum

    return best_sum


def main():
    count, limit = map(int, input().split())
    values = list(map(int, input().split()))

    answer = best_pair_sum_under_limit(values, limit)
    print(answer)


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `values` 리스트에 입력 숫자를 저장합니다.
* 바깥 반복문은 첫 번째 값을 고릅니다.
* 안쪽 반복문은 첫 번째 값보다 뒤에 있는 값을 두 번째 값으로 고릅니다.
* `first_index + 1`부터 확인하기 때문에 같은 쌍을 중복으로 검사하지 않습니다.
* 조건문은 현재 합이 제한값을 넘지 않는지 확인합니다.
* 조건을 만족하면서 기존 정답보다 좋으면 `best_sum`을 갱신합니다.
* 모든 조합을 확인한 뒤 가장 좋은 값을 반환합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: 두 개를 고르는 예제에서는 모든 쌍을 확인하므로 `O(n^2)`입니다.
* 최악의 경우: 정답이 일찍 나와도 모든 후보를 확인해야 한다면 `O(n^2)`입니다.
* 입력 크기가 커졌을 때 부담되는 부분: 반복문이 겹칠수록 후보 수가 빠르게 늘어납니다. 세 개를 고르면 `O(n^3)`, 모든 순서를 만들면 `O(n!)`까지 커질 수 있습니다.

브루트포스에서는 "반복문이 몇 겹인가", "재귀가 몇 갈래로 뻗는가"를 먼저 확인해야 합니다.

### 공간복잡도

* 단순 반복문만 사용하면 입력 배열 외에 큰 추가 메모리가 필요하지 않습니다.
* 현재 예제의 추가 공간은 정답 변수와 합 변수 정도이므로 `O(1)`입니다.
* 재귀로 모든 선택을 탐색하면 호출 스택이 필요합니다.
* 모든 후보를 리스트에 저장하면 후보 수만큼 추가 공간이 필요하므로 주의해야 합니다.

## 9. 예제로 이해하기

이번에는 숫자 네 개 중 세 개를 골라 합이 목표값과 정확히 같은지 확인해봅시다.

입력 데이터:

```text
4 15
3 6 8 4
```

처리 과정:

1. `3, 6, 8`을 고르면 합은 `17`입니다. 목표값보다 큽니다.
2. `3, 6, 4`를 고르면 합은 `13`입니다. 목표값보다 작습니다.
3. `3, 8, 4`를 고르면 합은 `15`입니다. 목표값과 같습니다.
4. 정답을 찾았으므로 `가능`이라고 판단할 수 있습니다.

중간 상태 변화:

```text
선택한 값        합계   판단
3, 6, 8         17    실패
3, 6, 4         13    실패
3, 8, 4         15    성공
```

최종 결과:

```text
가능
```

이 예제에서 중요한 점은 "좋아 보이는 값부터 고르는 것"이 아니라 "필요한 후보를 빠짐없이 확인하는 것"입니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "모든 경우를 확인한다"는 표현이 나옵니다.
* "가능한 조합", "가능한 순서", "모든 후보"를 찾아야 합니다.
* 입력 크기가 작습니다.
* 제한 시간이 넉넉하고 후보 수를 계산해도 크지 않습니다.
* 정답 조건은 명확하지만 바로 계산하는 공식이 떠오르지 않습니다.
* 두 개, 세 개처럼 고르는 개수가 고정되어 있습니다.
* 비밀번호, 카드 선택, 부분 집합, 순열, 조합, 격자 전체 검사 같은 유형입니다.
* 먼저 완전탐색으로 풀고, 필요하면 가지치기나 다른 알고리즘으로 개선할 수 있습니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 완전탐색과 브루트포스

브루트포스는 완전탐색의 대표적인 방식입니다. 둘 다 가능한 후보를 모두 확인한다는 생각을 공유합니다. 다만 완전탐색은 더 넓은 표현이고, 브루트포스는 그중에서도 단순하게 전부 시도하는 풀이를 가리킬 때 자주 사용합니다.

### 브루트포스와 백트래킹

브루트포스는 후보를 끝까지 확인하는 데 초점이 있습니다. 백트래킹은 탐색 도중 더 볼 필요가 없는 후보를 미리 버립니다. 예를 들어 합이 이미 목표를 넘었다면 그 뒤 선택을 중단하는 식입니다.

### 브루트포스와 그리디

그리디는 매 순간 좋아 보이는 선택을 합니다. 브루트포스는 좋아 보이지 않는 선택까지 모두 검사합니다. 그리디는 빠를 수 있지만 항상 정답을 보장하지는 않습니다. 브루트포스는 느릴 수 있지만 후보를 빠뜨리지 않으면 정답을 보장합니다.

### 반복문 탐색과 재귀 탐색

고르는 개수가 작고 고정되어 있으면 반복문이 편합니다. 선택 단계가 깊어지거나 개수가 유동적이면 재귀가 더 자연스러울 수 있습니다.

## 12. 자주 하는 실수

* 후보를 중복해서 검사하는 실수
* 같은 원소를 두 번 고르는 실수
* 반복문의 시작 인덱스를 잘못 잡는 실수
* 정답을 찾았을 때 바로 종료해도 되는지 확인하지 않는 실수
* 입력 크기를 보지 않고 무조건 완전탐색을 쓰는 실수
* 재귀에서 종료 조건을 빠뜨리는 실수
* 후보를 만들 때 일부 경우를 누락하는 실수
* 중간 결과를 저장한 리스트를 되돌리지 않아 다음 탐색에 영향을 주는 실수
* 모든 후보를 메모리에 저장해서 불필요하게 공간을 많이 쓰는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

정답을 바로 계산하려고 하기보다, 가능한 후보를 모두 나열할 수 있는지 먼저 생각해보세요. 입력 크기가 작다면 모든 후보를 검사하는 접근이 가능할 수 있습니다.

### 2단계 힌트: 접근 힌트

무엇을 하나의 후보로 볼지 정하세요. 예를 들어 숫자 두 개의 합이 필요하다면 후보는 "두 숫자의 쌍"입니다. 그 다음 후보를 하나씩 만들고 조건에 맞는지 확인하세요.

### 3단계 힌트: 구현 힌트

고르는 개수가 정해져 있으면 중첩 반복문을 사용할 수 있습니다. 같은 값을 다시 고르면 안 된다면 다음 반복문의 시작 위치를 이전 인덱스보다 뒤로 잡으세요. 정답 후보를 갱신해야 한다면 현재 후보가 조건을 만족하는지 먼저 검사하세요.

## 14. 언제 사용하면 좋은가

* 입력 크기가 작을 때 사용하기 좋습니다.
* 가능한 후보 수를 직접 계산할 수 있을 때 적합합니다.
* 조합, 순열, 부분 집합, 격자 전체 검사 문제에서 자주 사용합니다.
* 조건이 단순하고 후보 검사 비용이 작을 때 좋습니다.
* 풀이를 처음 설계할 때 기준 풀이로 사용하기 좋습니다.
* 후보 수가 수십만, 수백만을 훨씬 넘고 제한 시간이 짧다면 그대로 사용하면 안 됩니다.
* 더 이상 볼 필요가 없는 후보를 판단할 수 있다면 백트래킹으로 개선하는 것이 좋습니다.
* 정렬, 이분 탐색, 투 포인터, 동적 계획법으로 줄일 수 있는 구조가 보이면 더 효율적인 방법을 고려해야 합니다.

## 15. 요약 정리

* 브루트포스의 목적은 가능한 후보를 모두 검사해 정답을 찾는 것입니다.
* 핵심 아이디어는 후보 생성과 조건 검사입니다.
* 주요 자료구조는 배열, 리스트, 재귀 호출 스택입니다.
* 시간복잡도는 후보 수에 따라 달라지며, 중첩 반복문과 재귀 분기 수를 확인해야 합니다.
* 문제에서 "모든 조합", "모든 경우", "가능한 후보"라는 표현이 보이면 떠올릴 수 있습니다.
* 초급자는 입력 크기, 중복 검사, 인덱스 범위, 종료 조건을 특히 주의해야 합니다.
