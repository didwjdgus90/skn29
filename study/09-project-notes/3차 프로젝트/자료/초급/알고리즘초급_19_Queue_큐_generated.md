# [알고리즘] Queue

## 1. 한 줄 요약

> 큐는 먼저 들어온 데이터가 먼저 나가는 FIFO 구조로, 순서대로 기다렸다가 처리해야 하는 상황에 사용하는 자료구조입니다.

---

## 2. 선수 지식

- 리스트: 여러 값을 순서대로 저장하는 기본 자료구조입니다.
- `deque`: Python에서 큐를 효율적으로 구현할 때 자주 쓰는 자료구조입니다.
- FIFO: First In First Out의 줄임말로, 먼저 들어온 값이 먼저 나간다는 뜻입니다.
- 반복문: 큐가 빌 때까지 데이터를 하나씩 처리할 때 사용합니다.
- BFS: 너비 우선 탐색으로, 가까운 위치부터 차례대로 탐색할 때 큐를 사용합니다.
- 시간복잡도: 큐 연산이 입력 크기에 따라 얼마나 빠른지 판단할 때 필요합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

큐는 "먼저 온 순서대로 처리해야 하는 문제"를 해결하기 위해 사용합니다.

### 기존 방식의 문제

- 리스트 앞쪽에서 값을 계속 꺼내면 남은 원소들이 앞으로 밀려 비효율적입니다.
- 처리 순서를 직접 관리하면 실수하기 쉽습니다.
- 다음에 처리할 대상과 나중에 처리할 대상을 구분하기 어렵습니다.

예를 들어 접수 번호표를 받은 사람들을 순서대로 처리해야 한다면, 가장 먼저 받은 번호가 가장 먼저 호출되어야 합니다. 중간에 나중 사람을 먼저 처리하면 순서가 깨집니다.

### 이 알고리즘을 사용하면

- 들어온 순서를 유지하면서 데이터를 처리할 수 있습니다.
- 새 데이터는 뒤에 넣고, 처리할 데이터는 앞에서 꺼내면 됩니다.
- BFS, 작업 대기열, 프린터 작업, 버퍼 처리 같은 문제를 단순하게 표현할 수 있습니다.

큐의 핵심은 "넣는 곳과 꺼내는 곳이 다르다"는 점입니다.

---

## 4. 핵심 아이디어

큐는 앞쪽과 뒤쪽이 역할을 나누어 가집니다.

1. 새 데이터는 큐의 뒤쪽에 넣습니다.
2. 처리할 데이터는 큐의 앞쪽에서 꺼냅니다.
3. 앞쪽 값을 확인만 할 수도 있습니다.
4. 큐가 비면 더 이상 처리할 데이터가 없습니다.

### 쉬운 비유

은행 번호표 줄을 떠올리면 됩니다. 먼저 번호표를 뽑은 사람이 먼저 창구로 갑니다. 새로 온 사람은 줄 맨 뒤에 서고, 창구에서는 줄 맨 앞 사람부터 부릅니다.

큐도 같은 방식입니다. 데이터가 줄을 서고, 앞에서부터 차례대로 처리됩니다.

### 직관적으로 이해하기

큐에 `10`, `20`, `30`을 차례대로 넣었다고 해봅시다.

```text
앞쪽 [10, 20, 30] 뒤쪽
```

한 번 꺼내면 `10`이 나옵니다.

```text
꺼낸 값: 10
남은 큐: [20, 30]
```

다음에 꺼낼 값은 `20`입니다. 가장 오래 기다린 값이 먼저 처리됩니다.

## 5. 동작 과정 살펴보기

### 예제 상황

고객 요청이 들어온 순서대로 처리되는 간단한 접수 시스템을 만듭니다. 요청은 큐 뒤에 쌓이고, 직원은 큐 앞에서 요청을 하나씩 처리합니다.

### 예제 입력

```text
4
join 민수
join 지아
serve
join 도윤
```

### 예제 출력

```text
민수
```

`serve` 명령이 한 번만 있으므로 가장 먼저 들어온 `민수`가 처리됩니다.

### 단계별 동작

1. 빈 큐를 준비합니다.
2. `join 민수`가 들어오면 큐 뒤에 `민수`를 넣습니다.
3. `join 지아`가 들어오면 큐 뒤에 `지아`를 넣습니다.
4. `serve`가 들어오면 큐 앞에서 `민수`를 꺼냅니다.
5. `join 도윤`이 들어오면 큐 뒤에 `도윤`을 넣습니다.
6. 출력된 처리 대상은 `민수`입니다.

## 7. 기본 코드 템플릿

```python
from collections import deque


def process_requests(commands):
    waiting_line = deque()
    served_people = []

    for command in commands:
        parts = command.split()

        if parts[0] == "join":
            waiting_line.append(parts[1])
        elif parts[0] == "serve":
            if waiting_line:
                served_people.append(waiting_line.popleft())

    return served_people


def main():
    command_count = int(input())
    commands = []

    for _ in range(command_count):
        commands.append(input())

    result = process_requests(commands)

    for name in result:
        print(name)


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `deque`는 양쪽 끝에서 빠르게 넣고 뺄 수 있는 자료구조입니다.
* `waiting_line.append()`는 큐 뒤에 새 데이터를 넣는 enqueue 역할을 합니다.
* `waiting_line.popleft()`는 큐 앞에서 데이터를 꺼내는 dequeue 역할을 합니다.
* `served_people`에는 실제로 처리된 사람을 순서대로 저장합니다.
* `serve` 명령이 들어왔을 때 큐가 비어 있으면 아무것도 꺼내지 않습니다.
* 큐를 리스트로 만들고 `pop(0)`을 반복하면 앞쪽 값을 꺼낼 때마다 나머지 값이 이동하므로 비효율적입니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: `deque`의 `append`와 `popleft`는 각각 `O(1)`입니다.
* 최악의 경우: 명령을 모두 한 번씩 처리하므로 전체는 `O(n)`입니다.
* 입력 크기가 커졌을 때 부담되는 부분: 명령 수가 늘어난 만큼 처리 시간이 선형으로 늘어납니다.

Python 리스트에서 `pop(0)`을 사용하면 앞 원소를 제거한 뒤 뒤의 원소들을 앞으로 당겨야 해서 `O(n)`이 걸립니다. 큐 문제에서는 `deque`를 사용하는 것이 안전합니다.

### 공간복잡도

* 아직 처리되지 않은 데이터가 큐에 저장되므로 최대 `O(n)` 공간을 사용합니다.
* 처리 결과를 따로 저장하면 결과 목록에도 추가 공간이 필요합니다.
* BFS에서는 방문할 좌표나 노드가 큐에 들어가므로 그래프 크기에 따라 공간이 늘어날 수 있습니다.

## 9. 예제로 이해하기

이번에는 숫자를 순서대로 처리해보겠습니다.

입력 데이터:

```text
push 4
push 9
push 1
pop
push 7
pop
```

처리 과정:

```text
명령      큐 상태          결과
push 4   [4]              -
push 9   [4, 9]           -
push 1   [4, 9, 1]        -
pop      [9, 1]           4
push 7   [9, 1, 7]        -
pop      [1, 7]           9
```

최종 출력:

```text
4
9
```

처음 들어온 `4`가 먼저 나가고, 그 다음으로 오래 기다린 `9`가 나갑니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 먼저 들어온 것을 먼저 처리해야 합니다.
* 대기열, 줄서기, 접수, 작업 목록 같은 표현이 나옵니다.
* 현재 처리 대상 뒤에 다음 후보들이 차례대로 쌓입니다.
* BFS처럼 가까운 노드부터 차례대로 탐색해야 합니다.
* 데이터가 순서대로 들어오고, 순서대로 빠져나갑니다.
* 버퍼, 프린터 작업, 네트워크 요청처럼 처리 대기 상황이 등장합니다.
* `push`, `pop`, `front`, `back`, `empty` 같은 큐 연산이 문제에 직접 나오기도 합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 큐와 스택

큐는 먼저 들어온 값이 먼저 나갑니다. 스택은 나중에 들어온 값이 먼저 나갑니다. 순서대로 기다렸다가 처리해야 하면 큐, 최근 값부터 되돌아가야 하면 스택을 생각합니다.

### 큐와 우선순위 큐

일반 큐는 들어온 순서대로 처리합니다. 우선순위 큐는 들어온 순서와 상관없이 우선순위가 높은 값을 먼저 처리합니다. "가장 작은 값", "가장 큰 값"을 계속 꺼내야 하면 우선순위 큐가 맞을 수 있습니다.

### 리스트와 deque

리스트도 큐처럼 사용할 수는 있습니다. 하지만 앞에서 값을 꺼내는 연산이 느립니다. Python에서는 큐가 필요하면 `collections.deque`를 우선 고려하는 것이 좋습니다.

### 큐와 BFS

BFS는 큐를 사용하는 대표 알고리즘입니다. 시작점을 큐에 넣고, 큐 앞에서 하나씩 꺼내며 다음 위치들을 뒤에 추가합니다. 이 구조 덕분에 가까운 위치부터 탐색됩니다.

## 12. 자주 하는 실수

* Python 리스트에서 `pop(0)`을 반복해서 시간초과가 나는 실수
* 큐가 비었는지 확인하지 않고 값을 꺼내는 실수
* `peek`처럼 확인만 해야 하는 상황에서 값을 꺼내버리는 실수
* 스택처럼 뒤에서 꺼내 큐의 순서를 깨는 실수
* BFS에서 방문 처리를 늦게 해서 같은 노드를 여러 번 큐에 넣는 실수
* 큐의 앞과 뒤 역할을 반대로 생각하는 실수
* 처리 결과와 남은 큐 상태를 혼동하는 실수
* 우선순위가 필요한 문제를 일반 큐로 푸는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

문제에서 먼저 들어온 대상이 먼저 처리되어야 하는지 확인해보세요. 그렇다면 FIFO 구조인 큐를 사용할 수 있습니다.

### 2단계 힌트: 접근 힌트

새로 발견하거나 새로 들어온 데이터는 큐 뒤에 넣고, 처리할 때는 큐 앞에서 꺼내세요. 큐가 빌 때까지 이 과정을 반복하면 됩니다.

### 3단계 힌트: 구현 힌트

Python에서는 `from collections import deque`를 사용하세요. 추가는 `append`, 제거는 `popleft`로 처리하면 큐 연산을 효율적으로 구현할 수 있습니다.

## 15. 요약 정리

* 큐의 목적은 데이터를 들어온 순서대로 처리하는 것입니다.
