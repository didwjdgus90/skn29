# [알고리즘] 순열과 조합

## 1. 한 줄 요약

> 순열과 조합은 여러 후보 중 일부를 고를 때, 순서를 결과에 포함할지 말지를 기준으로 모든 가능한 선택을 만드는 방법입니다.

---

## 2. 선수 지식

- 리스트: 선택할 후보들을 순서대로 담아 두는 자료구조입니다.
- 재귀 함수: 함수가 자기 자신을 다시 호출하면서 선택을 한 칸씩 쌓아 가는 방식입니다.
- 백트래킹: 한 선택을 해 보고, 다음 선택을 시도한 뒤, 다시 이전 상태로 돌아와 다른 선택을 확인하는 탐색 방법입니다.
- 인덱스: 리스트에서 몇 번째 원소인지 나타내는 번호입니다.
- 방문 표시: 순열에서 같은 원소를 두 번 쓰지 않기 위해 이미 고른 원소를 체크하는 배열입니다.
- 팩토리얼: `n!`처럼 쓰며, `n * (n - 1) * ... * 1`을 뜻합니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

순열과 조합은 가능한 후보를 직접 만들어 보아야 하는 문제에서 자주 사용합니다.

### 기존 방식의 문제

- 후보 개수가 정해져 있지 않으면 반복문을 몇 겹으로 작성해야 할지 애매합니다.
- 2개를 고르는 문제는 이중 반복문으로 가능하지만, 3개, 4개, 5개로 늘어나면 코드가 빠르게 복잡해집니다.
- 순서가 중요한지 아닌지를 구분하지 않으면 같은 결과를 여러 번 세거나, 필요한 결과를 빼먹기 쉽습니다.

예를 들어 5개의 카드 중 3장을 골라 암호를 만드는 문제는 순서가 중요합니다. `빨강-파랑-초록`과 `초록-파랑-빨강`은 다른 암호입니다.

반대로 5명의 학생 중 3명을 청소 당번으로 고르는 문제는 순서가 중요하지 않습니다. 같은 3명이 뽑혔다면 나열 순서는 결과를 바꾸지 않습니다.

### 이 알고리즘을 사용하면

- 고르는 개수 `r`이 바뀌어도 같은 구조로 처리할 수 있습니다.
- 순서가 중요한 문제와 중요하지 않은 문제를 명확히 나누어 풀 수 있습니다.
- 모든 후보를 만들어 조건을 검사하는 완전탐색 문제의 기본 틀로 사용할 수 있습니다.

입력 크기가 작고 모든 경우를 확인해야 한다면 순열과 조합은 가장 직접적인 해결 방법이 됩니다. 다만 경우의 수가 매우 빠르게 늘어나므로 입력 제한을 반드시 함께 확인해야 합니다.

## 4. 핵심 아이디어

순열과 조합의 핵심 질문은 두 가지입니다.

- 뽑은 순서가 결과를 바꾸는가?
- 같은 원소를 다시 뽑을 수 있는가?

이 두 질문에 따라 문제는 네 가지로 나뉩니다.

- 순열: 순서 중요, 중복 불가
- 중복 순열: 순서 중요, 중복 가능
- 조합: 순서 무관, 중복 불가
- 중복 조합: 순서 무관, 중복 가능

### 쉬운 비유

카페에서 음료를 고른다고 생각해 봅시다.

직원 2명이 차례대로 제조할 음료를 정한다면 첫 번째 직원이 어떤 음료를 맡고 두 번째 직원이 어떤 음료를 맡는지가 중요합니다. 이때는 순열에 가깝습니다.

반대로 회의실에 놓을 간식 2종류를 고르는 것이라면 선택된 간식의 종류만 중요합니다. 먼저 말한 간식과 나중에 말한 간식의 순서는 의미가 없습니다. 이때는 조합에 가깝습니다.

### 직관적으로 이해하기

후보가 `["민트", "라임", "자몽"]`이고 2개를 고른다고 해 봅시다.

순열에서는 첫 번째 칸과 두 번째 칸이 구분됩니다.

- `민트, 라임`
- `라임, 민트`

두 결과는 서로 다릅니다.

조합에서는 어떤 후보들이 선택되었는지만 봅니다.

- `민트, 라임`
- `라임, 민트`

두 결과는 같은 선택입니다. 그래서 조합은 보통 뒤쪽 후보만 이어서 확인해 중복된 나열을 만들지 않습니다.

## 5. 동작 과정 살펴보기

### 예제 상황

세 가지 스티커 `별`, `달`, `구름` 중 2개를 골라 노트 표지를 꾸미려고 합니다.

표지의 위쪽과 아래쪽에 붙일 스티커를 정한다면 위치가 다르므로 순열입니다.

### 예제 입력

```text
stickers = ["별", "달", "구름"]
r = 2
mode = permutation
```

### 예제 출력

```text
["별", "달"]
["별", "구름"]
["달", "별"]
["달", "구름"]
["구름", "별"]
["구름", "달"]
```

### 단계별 동작

1. 결과를 담을 빈 리스트를 준비합니다.
2. 첫 번째 칸에 넣을 수 있는 스티커를 하나 고릅니다.
3. 이미 고른 스티커는 방문 표시를 해 둡니다.
4. 두 번째 칸에 들어갈 수 있는 남은 스티커를 다시 확인합니다.
5. 2개를 모두 골랐다면 현재 선택을 결과에 추가합니다.
6. 마지막 선택을 취소하고 다른 스티커를 시도합니다.
7. 모든 첫 번째 선택에 대해 같은 과정을 반복합니다.

조합이라면 3번의 방문 표시보다 "다음 탐색을 몇 번째 후보부터 시작할지"가 더 중요합니다. 앞에서 이미 만든 묶음을 다시 만들지 않기 위해 항상 현재 선택보다 뒤쪽 후보로만 이동합니다.

## 7. 기본 코드 템플릿

```python
def make_permutations(items, pick_count):
    results = []
    selected = []
    used = [False] * len(items)

    def search():
        if len(selected) == pick_count:
            results.append(selected[:])
            return

        for index in range(len(items)):
            if used[index]:
                continue

            used[index] = True
            selected.append(items[index])
            search()
            selected.pop()
            used[index] = False

    search()
    return results


def make_combinations(items, pick_count):
    results = []
    selected = []

    def search(start_index):
        if len(selected) == pick_count:
            results.append(selected[:])
            return

        for index in range(start_index, len(items)):
            selected.append(items[index])
            search(index + 1)
            selected.pop()

    search(0)
    return results


def make_repeated_permutations(items, pick_count):
    results = []
    selected = []

    def search():
        if len(selected) == pick_count:
            results.append(selected[:])
            return

        for item in items:
            selected.append(item)
            search()
            selected.pop()

    search()
    return results


def make_repeated_combinations(items, pick_count):
    results = []
    selected = []

    def search(start_index):
        if len(selected) == pick_count:
            results.append(selected[:])
            return

        for index in range(start_index, len(items)):
            selected.append(items[index])
            search(index)
            selected.pop()

    search(0)
    return results


if __name__ == "__main__":
    colors = ["red", "blue", "green"]
    count = 2

    print("permutation")
    for case in make_permutations(colors, count):
        print(case)

    print("combination")
    for case in make_combinations(colors, count):
        print(case)

    print("repeated permutation")
    for case in make_repeated_permutations(colors, count):
        print(case)

    print("repeated combination")
    for case in make_repeated_combinations(colors, count):
        print(case)
```

### 코드 흐름 설명

* `selected`는 현재까지 고른 후보를 임시로 담습니다.
* `results`는 완성된 경우를 모아 두는 리스트입니다.
* 순열은 매 칸마다 전체 후보를 다시 확인합니다.
* 순열에서 `used`는 이미 고른 원소를 다시 고르지 않도록 막습니다.
* 조합은 `start_index`를 사용해 앞에서 확인한 후보로 되돌아가지 않습니다.
* 중복 순열은 같은 원소를 다시 고를 수 있으므로 `used`가 필요 없습니다.
* 중복 조합은 같은 원소를 다시 고를 수 있지만 순서는 무시하므로 재귀 호출에 `index`를 그대로 넘깁니다.
* `selected.pop()`은 방금 한 선택을 취소하고 다른 선택을 시도하기 위한 백트래킹 동작입니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 순열: 서로 다른 `n`개 중 `r`개를 순서 있게 고르면 대략 `nPr`개의 결과가 생깁니다. 최악의 경우 `r = n`이면 `O(n!)`입니다.
* 조합: 서로 다른 `n`개 중 `r`개를 순서 없이 고르면 `nCr`개의 결과가 생깁니다.
* 중복 순열: 매 칸마다 `n`개 후보를 모두 고를 수 있으므로 `O(n^r)`입니다.
* 중복 조합: 실제 결과 개수는 `nHr`이며, 구현은 그 결과를 만드는 만큼 시간이 걸립니다.

평균적인 경우라고 해도 결과 자체가 많으면 출력하거나 저장하는 데 시간이 오래 걸립니다. 순열과 조합은 "계산이 느리다"기보다 "만들어야 하는 경우의 수가 많다"는 점이 핵심입니다.

### 공간복잡도

* 결과를 모두 저장하면 결과 개수만큼 메모리가 필요합니다.
* 재귀 호출 깊이는 보통 `r`까지 내려가므로 선택 과정 자체에는 `O(r)` 정도의 추가 공간이 필요합니다.
* 순열은 방문 배열 `used`를 사용하므로 `O(n)` 공간이 추가됩니다.
* 조합은 시작 인덱스만 넘겨도 구현할 수 있어 방문 배열이 필수는 아닙니다.

## 9. 예제로 이해하기

이번에는 네 개의 숫자 카드 `2, 4, 6, 8` 중 2장을 고른다고 하겠습니다.

입력 데이터:

```text
cards = [2, 4, 6, 8]
r = 2
```

조합으로 고르면 `2, 4`와 `4, 2`는 같은 선택입니다. 따라서 가능한 일부 결과는 다음과 같습니다.

```text
[2, 4]
[2, 6]
[2, 8]
[4, 6]
[4, 8]
[6, 8]
```

처리 과정은 다음과 같습니다.

1. 첫 번째 카드로 `2`를 고릅니다.
2. 두 번째 카드는 `2` 뒤에 있는 `4, 6, 8` 중에서만 고릅니다.
3. `2`로 시작하는 조합을 모두 만들면 첫 번째 카드를 `4`로 바꿉니다.
4. 이제 두 번째 카드는 `4` 뒤에 있는 `6, 8` 중에서만 고릅니다.
5. 같은 방식으로 앞쪽 카드를 다시 보지 않으므로 중복된 묶음이 나오지 않습니다.

순열로 고르면 `2, 4`와 `4, 2`는 다른 결과입니다. 첫 번째 칸과 두 번째 칸이 서로 다른 의미를 가지기 때문입니다.

```text
[2, 4]
[2, 6]
[2, 8]
[4, 2]
[4, 6]
[4, 8]
...
```

최종 결과 개수는 조합보다 순열이 더 많습니다. 순서를 구분하면 같은 원소 묶음에서도 여러 배치가 생기기 때문입니다.

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* "서로 다른 M개를 고른다"라는 표현이 있습니다.
* "가능한 모든 경우", "모든 배열", "모든 선택"을 요구합니다.
* "순서가 다르면 다른 경우"라는 조건이 있으면 순열을 의심합니다.
* "오름차순으로 고른다", "순서는 상관없다"라는 조건이 있으면 조합을 의심합니다.
* "같은 수를 여러 번 선택할 수 있다"라는 조건이 있으면 중복 허용 유형을 확인합니다.
* 입력 크기 `N`이 작고, 모든 후보를 직접 검사해도 되는 제한이 주어집니다.
* 결과를 만든 뒤 조건에 맞는지만 확인하면 되는 완전탐색 문제입니다.
* 비밀번호, 줄 세우기, 팀 구성, 메뉴 선택, 부분 집합 후보 만들기 같은 상황이 등장합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 완전탐색과 순열, 조합

완전탐색은 가능한 답을 모두 확인하는 큰 접근 방식입니다. 순열과 조합은 그 가능한 답을 만드는 대표적인 방법입니다.

### 순열과 조합

순열은 뽑은 순서가 의미를 가집니다. 조합은 뽑힌 원소의 집합만 의미를 가집니다.

문제에서 `A, B`와 `B, A`를 다르게 봐야 하면 순열입니다. 같게 봐야 하면 조합입니다.

### 조합과 부분집합

조합은 보통 정확히 `r`개를 고르는 경우를 말합니다. 부분집합은 각 원소를 고르거나 고르지 않는 모든 경우를 말합니다.

예를 들어 원소가 4개라면 부분집합은 0개를 고르는 경우부터 4개를 모두 고르는 경우까지 포함합니다.

### 백트래킹과 순열, 조합

백트래킹은 구현 방법입니다. 순열과 조합을 만들 때 선택을 쌓고 되돌리는 방식으로 백트래킹을 자주 사용합니다.

## 12. 자주 하는 실수

* 순열 문제인데 조합처럼 뒤쪽 후보만 확인해서 필요한 배치를 빠뜨립니다.
* 조합 문제인데 순열처럼 전체 후보를 매번 확인해서 같은 묶음을 여러 번 만듭니다.
* 중복이 허용되지 않는데 방문 처리를 하지 않아 같은 원소를 반복해서 사용합니다.
* 중복 조합에서 재귀 호출에 `index + 1`을 넘겨 같은 원소를 다시 고르지 못하게 만듭니다.
* 재귀 종료 조건을 `len(selected) == r`로 두지 않아 결과가 너무 짧거나 길게 만들어집니다.
* `selected`를 결과에 넣을 때 복사하지 않아 나중에 빈 리스트만 남는 문제가 생깁니다.
* 입력 크기를 보지 않고 모든 순열을 만들어 시간 초과가 발생합니다.
* 문제에서 "출력 순서"를 요구하는데 후보 목록을 정렬하지 않아 원하는 순서와 다르게 출력합니다.

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

이 문제는 후보 중 일부를 고르는 문제입니다. 먼저 순서가 결과에 영향을 주는지 확인해 보세요. 같은 원소 묶음이라도 나열 순서가 다르면 다른 답인지가 핵심입니다.

### 2단계 힌트: 접근 힌트

뽑을 개수만큼 한 칸씩 선택을 쌓아 가면 됩니다. 순서가 중요하면 매 칸에서 전체 후보를 다시 확인하고, 순서가 중요하지 않으면 이전에 고른 위치보다 뒤쪽 후보만 확인해 보세요.

### 3단계 힌트: 구현 힌트

현재 선택을 담는 리스트를 만들고, 길이가 `r`이 되면 결과로 처리하세요. 순열에서는 `used` 배열로 이미 고른 원소를 막고, 조합에서는 `start_index`를 재귀 함수의 매개변수로 넘겨 중복된 묶음을 만들지 않도록 하세요.

## 14. 언제 사용하면 좋은가

* 입력 조건: `N`이 작고 가능한 경우를 직접 만들 수 있을 때 사용합니다.
* 문제 유형: 줄 세우기, 카드 고르기, 팀 만들기, 암호 만들기, 메뉴 묶음 찾기, 조건을 만족하는 후보 찾기에 적합합니다.
* 자주 등장하는 표현: "모든 경우", "M개 선택", "순서 있게", "순서 없이", "중복 허용", "서로 다른" 같은 표현이 단서입니다.
* 적합한 자료구조: 리스트, 방문 배열, 재귀 호출 스택을 주로 사용합니다.

## 15. 요약 정리

* 순열과 조합은 여러 후보 중 일부를 고르는 모든 경우를 만드는 방법입니다.
* 순열은 순서를 구분하고, 조합은 순서를 구분하지 않습니다.
* 중복 허용 여부에 따라 순열, 중복 순열, 조합, 중복 조합으로 나뉩니다.
* 순열은 방문 배열을 자주 사용하고, 조합은 시작 인덱스를 자주 사용합니다.
* 순열의 대표 시간복잡도는 `O(nPr)`, 조합의 대표 시간복잡도는 `O(nCr)`입니다.
* 중복 순열은 `O(n^r)`처럼 빠르게 커질 수 있습니다.
* 문제에서 순서, 중복, 선택 개수를 먼저 확인하면 어떤 유형인지 판단하기 쉽습니다.
* 초급자는 종료 조건, 방문 해제, 리스트 복사, 시작 인덱스 갱신을 특히 주의해야 합니다.
