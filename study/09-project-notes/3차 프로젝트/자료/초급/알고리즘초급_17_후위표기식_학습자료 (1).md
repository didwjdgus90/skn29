# [알고리즘] 후위표기식

## 1. 한 줄 요약

> 후위표기식은 연산자를 숫자 뒤에 배치하여, 괄호 없이도 계산 순서를 스택으로 명확하게 처리할 수 있는 수식 표현 방식입니다.

---

## 2. 선수 지식

- 스택: 마지막에 넣은 값을 먼저 꺼내는 자료구조입니다.
- 중위표기식: `3 + 4`처럼 연산자가 두 값 사이에 있는 일반적인 수식입니다.
- 후위표기식: `3 4 +`처럼 연산자가 필요한 값들 뒤에 나오는 수식입니다.
- 연산자 우선순위: 곱셈과 나눗셈이 덧셈과 뺄셈보다 먼저 계산되는 규칙입니다.
- 괄호: 수식에서 계산 순서를 강제로 바꾸는 기호입니다.
- 문자열 파싱: 수식을 문자 단위 또는 토큰 단위로 나누어 읽는 과정입니다.

---

## 3. 어떤 문제를 해결하기 위해 사용하는가?

컴퓨터는 사람이 쓰는 중위표기식을 그대로 계산하기 어렵습니다. 연산자 우선순위와 괄호를 계속 고려해야 하기 때문입니다.

### 기존 방식의 문제

- 중위표기식은 연산자가 값 사이에 있어 계산 순서를 바로 알기 어렵습니다.
- 괄호가 중첩되면 어떤 연산을 먼저 해야 하는지 추적해야 합니다.
- 단순히 왼쪽부터 계산하면 `+`, `*`, 괄호 우선순위를 틀릴 수 있습니다.

예를 들어 `8 * (3 + 2) - 6 / 2`는 괄호 안 덧셈, 곱셈, 나눗셈, 뺄셈의 순서를 모두 고려해야 합니다.

### 이 알고리즘을 사용하면

- 중위표기식을 후위표기식으로 바꾸어 계산 순서를 명확하게 만들 수 있습니다.
- 후위표기식은 왼쪽부터 읽으며 스택만으로 계산할 수 있습니다.
- 괄호는 변환 과정에서만 필요하고, 후위표기식 결과에는 괄호가 남지 않습니다.

후위표기식의 핵심은 "계산할 준비가 된 연산자만 뒤로 보내는 것"입니다.

---

## 4. 핵심 아이디어

후위표기식 변환에서는 숫자는 바로 출력하고, 연산자는 잠시 스택에 보관합니다.

1. 숫자는 결과에 바로 보냅니다.
2. 여는 괄호는 스택에 넣습니다.
3. 닫는 괄호를 만나면 여는 괄호가 나올 때까지 연산자를 꺼냅니다.
4. 연산자를 만나면 스택 위의 연산자와 우선순위를 비교합니다.
5. 스택 위 연산자가 먼저 계산되어야 하면 꺼내서 결과에 보냅니다.
6. 마지막에 스택에 남은 연산자를 모두 꺼냅니다.

### 쉬운 비유

요리 주문서를 정리한다고 생각해봅시다. 재료는 바로 조리대에 올려도 됩니다. 하지만 조리 순서를 정하는 지시는 잠시 메모판에 붙여 둡니다. 더 급한 지시가 이미 붙어 있으면 먼저 처리하고, 새 지시는 그 다음에 처리합니다.

숫자는 재료이고, 연산자는 조리 지시입니다. 스택은 아직 결과로 보내지 않은 조리 지시를 잠시 보관하는 메모판 역할을 합니다.

### 직관적으로 이해하기

`8 * (3 + 2)`를 후위표기식으로 바꾸면 다음과 같습니다.

```text
8 3 2 + *
```

괄호 안의 `3 + 2`가 먼저 계산되어야 하므로 `3 2 +`가 먼저 나오고, 그 결과와 `8`을 곱하기 위해 `*`가 마지막에 나옵니다.

후위표기식은 계산 순서를 수식 안에 이미 담고 있으므로 괄호가 없어도 됩니다.

## 5. 동작 과정 살펴보기

### 예제 상황

중위표기식 `8 * (3 + 2) - 6 / 2`를 후위표기식으로 바꾸고 계산합니다.

### 예제 입력

```text
8 * (3 + 2) - 6 / 2
```

### 예제 출력

```text
8 3 2 + * 6 2 / -
37.0
```

첫 줄은 변환된 후위표기식이고, 둘째 줄은 계산 결과입니다.

### 단계별 동작

1. 숫자 `8`은 결과에 바로 넣습니다.
2. `*`는 아직 오른쪽 값이 필요하므로 스택에 넣습니다.
3. `(`를 만나면 괄호 내부 연산을 따로 처리하기 위해 스택에 넣습니다.
4. `3`, `2`는 결과에 넣고, `+`는 괄호 안에서 처리됩니다.
5. `)`를 만나면 `(`가 나올 때까지 연산자를 결과로 보냅니다.
6. `-`를 만나면 스택에 남아 있던 `*`를 먼저 결과로 보냅니다.
7. `6 / 2`를 처리한 뒤 마지막에 `-`를 결과로 보냅니다.
8. 만들어진 후위표기식을 다시 스택으로 계산합니다.

## 7. 기본 코드 템플릿

```python
def split_expression(expression):
    tokens = []
    number_buffer = ""

    for character in expression:
        if character.isdigit():
            number_buffer += character
        else:
            if number_buffer:
                tokens.append(number_buffer)
                number_buffer = ""

            if character in "+-*/()":
                tokens.append(character)

    if number_buffer:
        tokens.append(number_buffer)

    return tokens


def infix_to_postfix(expression):
    priority = {
        "+": 1,
        "-": 1,
        "*": 2,
        "/": 2,
    }

    output = []
    operators = []

    for token in split_expression(expression):
        if token.isdigit():
            output.append(token)
        elif token == "(":
            operators.append(token)
        elif token == ")":
            while operators and operators[-1] != "(":
                output.append(operators.pop())
            operators.pop()
        else:
            while (
                operators
                and operators[-1] != "("
                and priority[operators[-1]] >= priority[token]
            ):
                output.append(operators.pop())
            operators.append(token)

    while operators:
        output.append(operators.pop())

    return output


def evaluate_postfix(postfix_tokens):
    numbers = []

    for token in postfix_tokens:
        if token.isdigit():
            numbers.append(float(token))
        else:
            right_value = numbers.pop()
            left_value = numbers.pop()

            if token == "+":
                numbers.append(left_value + right_value)
            elif token == "-":
                numbers.append(left_value - right_value)
            elif token == "*":
                numbers.append(left_value * right_value)
            elif token == "/":
                numbers.append(left_value / right_value)

    return numbers[0]


def main():
    expression = input()
    postfix_tokens = infix_to_postfix(expression)

    print(" ".join(postfix_tokens))
    print(evaluate_postfix(postfix_tokens))


if __name__ == "__main__":
    main()
```

### 코드 흐름 설명

* `split_expression`은 수식을 숫자와 연산자 토큰으로 나눕니다.
* `infix_to_postfix`는 중위표기식을 후위표기식 토큰 목록으로 바꿉니다.
* 숫자는 바로 `output`에 들어갑니다.
* 연산자와 괄호는 `operators` 스택에서 우선순위에 따라 대기합니다.
* 닫는 괄호가 나오면 여는 괄호 전까지의 연산자를 결과로 보냅니다.
* `evaluate_postfix`는 후위표기식을 왼쪽부터 읽으며 숫자 스택으로 계산합니다.
* 연산자를 만나면 오른쪽 값, 왼쪽 값 순서로 꺼내 실제 계산은 `왼쪽 연산자 오른쪽` 순서로 합니다.

## 8. 시간복잡도와 공간복잡도

### 시간복잡도

* 평균적인 경우: 수식을 한 번 토큰화하고, 한 번 변환하고, 한 번 계산하므로 전체적으로 `O(n)`입니다.
* 최악의 경우: 모든 토큰이 스택에 들어갔다 나와도 각 토큰은 제한된 횟수만 처리되므로 `O(n)`입니다.
* 입력 크기가 커졌을 때 부담되는 부분: 토큰 수가 늘어난 만큼 변환과 계산 시간이 선형으로 늘어납니다.

### 공간복잡도

* 토큰 목록, 결과 목록, 연산자 스택을 사용하므로 `O(n)` 공간이 필요합니다.
* 후위표기식을 계산할 때도 숫자 스택이 필요합니다.
* 괄호가 깊게 중첩될수록 연산자 스택에 더 많은 값이 쌓일 수 있습니다.

## 9. 예제로 이해하기

다른 예제로 `10 + 4 * (6 - 1)`을 보겠습니다.

처리 과정:

```text
토큰   결과              연산자 스택
10     10                비어 있음
+      10                +
4      10 4              +
*      10 4              + *
(      10 4              + * (
6      10 4 6            + * (
-      10 4 6            + * ( -
1      10 4 6 1          + * ( -
)      10 4 6 1 -        + *
끝     10 4 6 1 - * +    비어 있음
```

후위표기식:

```text
10 4 6 1 - * +
```

계산 흐름:

1. `6 1 -`를 계산해 `5`를 만듭니다.
2. `4 5 *`를 계산해 `20`을 만듭니다.
3. `10 20 +`를 계산해 `30`을 만듭니다.

최종 결과:

```text
30.0
```

## 10. 문제에서 이 알고리즘을 떠올리는 신호

* 중위표기식을 후위표기식으로 바꾸라고 합니다.
* 수식 계산에서 괄호와 연산자 우선순위를 처리해야 합니다.
* 최근에 본 연산자를 잠시 저장했다가 나중에 꺼내야 합니다.
* 연산자를 만났을 때 앞의 두 값을 꺼내 계산하는 구조가 보입니다.
* "스택을 이용한 수식 계산", "역폴란드 표기법", "Postfix" 같은 표현이 나옵니다.
* 괄호가 끝날 때까지 내부 연산자를 모아 두어야 합니다.
* 왼쪽부터 한 번씩 읽으며 계산 순서를 정리해야 합니다.

## 11. 비슷한 알고리즘과 헷갈리는 부분

### 중위표기식과 후위표기식

중위표기식은 사람이 읽기 쉽습니다. 후위표기식은 컴퓨터가 스택으로 계산하기 쉽습니다. 후위표기식에는 괄호가 없어도 계산 순서가 드러납니다.

### 후위표기식 변환과 후위표기식 계산

변환은 연산자 스택을 사용해 중위표기식을 후위표기식으로 바꾸는 과정입니다. 계산은 숫자 스택을 사용해 후위표기식의 값을 구하는 과정입니다. 둘 다 스택을 쓰지만 스택에 담는 대상이 다릅니다.

### 괄호 검사와 후위표기식

괄호 검사는 괄호의 짝이 맞는지 확인합니다. 후위표기식 변환에서는 괄호가 맞는다는 전제에서 괄호 안의 연산자를 언제 결과로 보낼지 결정합니다.

### 연산자 우선순위와 결합 방향

`*`, `/`는 `+`, `-`보다 우선순위가 높습니다. 같은 우선순위인 `-`, `/`는 왼쪽부터 계산해야 하므로 스택 위의 같은 우선순위 연산자를 먼저 꺼내야 합니다.

## 12. 자주 하는 실수

* 후위표기식 계산에서 오른쪽 값과 왼쪽 값 순서를 바꾸는 실수
* 닫는 괄호를 결과에 넣는 실수
* 여는 괄호를 스택에서 제거하지 않는 실수
* 같은 우선순위 연산자를 처리하지 않고 스택에 계속 쌓는 실수
* 수식 마지막에 스택에 남은 연산자를 꺼내지 않는 실수
* 여러 자리 숫자를 한 글자씩 잘라서 잘못 처리하는 실수
* 공백을 토큰으로 잘못 처리하는 실수
* 단항 마이너스와 이항 뺄셈을 구분하지 않고 처리하는 실수

## 13. 힌트 생성용 관점

### 1단계 힌트: 개념 힌트

연산자 우선순위와 괄호 때문에 바로 계산하기 어렵다면, 연산자를 잠시 스택에 보관하는 방식을 생각해보세요.

### 2단계 힌트: 접근 힌트

숫자는 결과로 바로 보내고, 연산자는 스택 위의 연산자와 우선순위를 비교하세요. 닫는 괄호가 나오면 여는 괄호가 나올 때까지 연산자를 꺼내면 됩니다.

### 3단계 힌트: 구현 힌트

먼저 수식을 숫자와 기호 토큰으로 나누세요. 변환 결과는 리스트에 저장하고, 연산자는 별도 스택에 저장하면 구현이 단순해집니다.

## 14. 언제 사용하면 좋은가

* 수식을 직접 계산하거나 파싱해야 할 때 좋습니다.
* 괄호와 연산자 우선순위를 코드로 처리해야 할 때 적합합니다.
* 컴파일러, 계산기, 수식 해석기 같은 문제의 기초가 됩니다.
* 스택의 활용을 연습하기 좋은 대표 문제입니다.
* 단순한 괄호 검사보다 한 단계 더 복잡한 스택 문제를 풀 때 사용하기 좋습니다.
* 단항 연산자, 함수 호출, 소수점, 변수까지 처리해야 한다면 토큰화 규칙을 더 정교하게 만들어야 합니다.

## 15. 요약 정리

* 후위표기식의 목적은 괄호 없이도 계산 순서를 명확하게 표현하는 것입니다.
* 핵심 아이디어는 숫자는 바로 결과로 보내고, 연산자는 우선순위에 따라 스택에서 관리하는 것입니다.
* 주요 자료구조는 연산자 스택과 계산용 숫자 스택입니다.
* 변환과 계산 모두 시간복잡도는 `O(n)`입니다.
* 문제에서 수식 변환, 연산자 우선순위, 괄호 처리가 보이면 스택을 떠올릴 수 있습니다.
* 초급자는 연산 순서, 괄호 제거, 남은 연산자 처리, 여러 자리 숫자 처리를 특히 주의해야 합니다.
