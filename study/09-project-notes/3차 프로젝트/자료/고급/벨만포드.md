## 1. 한 줄 요약

- 벨만-포드는 **음수 가중치가 있는 그래프에서도 최단 거리를 구할 수 있는 알고리즘**이며, 음수 사이클까지 탐지할 수 있다.

---

## 2. 주요 활용처 및 문제 유형

길찾기 문제를 생각해보자.

```
서울 → 대전 : 5
대전 → 부산 : 3
```

그렇다면

```
서울 → 부산

=

5 + 3 = 8
```

이다.

---

그런데 특이한 상황이 있다고 해보자.

예를 들어 할인 쿠폰이나 보상이 존재한다.

```
A → B : 5
B → C : -3
```

즉

```
이동 비용 5

↓

쿠폰 적용 -3

↓

실제 비용 2
```

처럼 음수 비용이 발생할 수 있다.

---

이때 문제가 생긴다.

우리가 배운 다익스트라는

```
음수 간선
```

을 처리할 수 없다.

그래서 등장한 것이

```
벨만-포드
```

이다.

---

### 코딩 테스트에서 자주 나오는 문제

다음 키워드가 보이면 벨만-포드를 떠올리자.

- 음수 가중치
- 음수 간선
- 웜홀
- 시간 여행
- 보상
- 음수 사이클 탐지

특히

> "음수 간선이 존재한다"
> 

라는 문장이 나오면 거의 벨만-포드 문제다.

---

## 3. 핵심 아이디어

### 다익스트라의 생각

다익스트라는

```
현재 가장 가까운 정점

↓

확정
```

이라는 전략을 사용한다.

---

하지만 음수 간선이 있으면

나중에 더 짧은 길이 발견될 수 있다.

즉

```
확정

↓

사실 틀림
```

이 될 수 있다.

---

### 벨만-포드의 생각

벨만-포드는 매우 단순하다.

> "모든 간선을 계속 확인하면서 최단 거리를 갱신하자"
> 

---

비유하면

길찾기를 한 번에 결정하지 않고

```
1차 검토
2차 검토
3차 검토
...
```

를 반복하는 것이다.

---

그래서 음수 간선이 있어도

결국 진짜 최단 거리를 찾을 수 있다.

---

## 4. 알고리즘 동작 과정 (Step-by-Step 시각화)

다음 그래프를 보자.

```
A
│ \
│  \
4   5
│    \
↓     ↓

B ──(-2)──→ C
```

간선

```
A → B : 4
A → C : 5
B → C : -2
```

---

목표

```
A → C 최단 거리
```

구하기

---

### Step 1. 거리 초기화

시작 정점

```
A
```

---

초기 상태

```
정점     거리

A        0
B        ∞
C        ∞
```

---

### Step 2. 첫 번째 반복

모든 간선을 확인한다.

---

간선 ①

```
A → B : 4
```

갱신

```
0 + 4 < ∞

YES
```

---

```
A : 0
B : 4
C : ∞
```

---

간선 ②

```
A → C : 5
```

갱신

```
0 + 5 < ∞

YES
```

---

```
A : 0
B : 4
C : 5
```

---

간선 ③

```
B → C : -2
```

확인

```
4 + (-2)

=

2
```

---

```
2 < 5
```

더 짧다.

갱신

```
A : 0
B : 4
C : 2
```

---

### Step 3. 두 번째 반복

다시 모든 간선을 검사한다.

---

```
A → B
A → C
B → C
```

모두 확인

---

하지만

```
더 짧은 거리 없음
```

---

상태 유지

```
A : 0
B : 4
C : 2
```

---

최종 결과

```
A → C 최단 거리

2
```

이다.

---

### 왜 여러 번 반복할까?

다음 그래프를 보자.

```
A → B → C → D
```

---

최단 거리 정보가

```
A

↓

B

↓

C

↓

D
```

순서대로 전달된다.

---

그래서

```
정점 개수 - 1 번
```

반복하면

모든 최단 거리가 전파된다.

---

## 5. 파이썬(Python) 구현 코드

```
INF=int(1e9)

# 정점 개수
n=3

# 간선 목록
edges= [
    (1,2,4),
    (1,3,5),
    (2,3,-2)
]

start=1

distance= [INF]* (n+1)
distance[start]=0

# 정점 수 - 1 번 반복
for_inrange(n-1):

fornow,next_node,costinedges:

ifdistance[now]==INF:
continue

ifdistance[now]+cost<distance[next_node]:
distance[next_node]=distance[now]+cost

print(distance[1:])
```

출력

```
[0, 4, 2]
```

---

### 핵심 코드 설명

```
for_inrange(n-1):
```

최단 거리 정보가 그래프 전체에 퍼지도록

```
정점 수 - 1 번
```

반복한다.

---

```
fornow,next_node,costinedges:
```

모든 간선을 검사한다.

---

```
distance[now]+cost
```

현재 정점을 거쳐서 가는 것이

더 짧은지 확인한다.

---

```
distance[next_node]=distance[now]+cost
```

더 짧다면 최단 거리 갱신.

## 6. 음수 사이클(Negative Cycle)

벨만-포드의 가장 강력한 기능이다.

---

다음 그래프를 보자.

```
A → B : 3
B → C : -5
C → A : 1
```

---

한 바퀴 돌면

```
3 + (-5) + 1

=

-1
```

이다.

---

즉

```
돌수록 비용 감소
```

한다.

---

```
0

↓

-1

↓

-2

↓

-3

↓

...
```

무한히 작아질 수 있다.

---

이런 경우

```
최단 거리
```

라는 개념 자체가 무너진다.

---

### 음수 사이클 탐지 방법

정상이라면

```
정점 수 - 1 번
```

반복 후에는 더 이상 갱신이 일어나지 않는다.

---

그런데

```
정점 수 번째
```

반복에서도 갱신이 발생하면

```
음수 사이클 존재
```

이다.

---

코드

```
has_cycle=False

fornow,next_node,costinedges:

ifdistance[now]==INF:
continue

ifdistance[now]+cost<distance[next_node]:
has_cycle=True
break
```

---

## 7. 핵심 요약 및 주의점

### 벨만-포드의 핵심 아이디어

```
모든 간선을

계속 반복 검사한다.
```

---

### 알고리즘 흐름

```
1. 거리 초기화

2. 모든 간선 검사

3. 거리 갱신

4. 정점 수 - 1 번 반복

5. 음수 사이클 확인
```

---

### 시간 복잡도

```
O(V × E)
```

- V = 정점 개수
- E = 간선 개수

---

공간 복잡도

```
O(V)
```

---

## 다익스트라와 차이점

### 같은 점

둘 다

```
한 시작점에서

모든 정점까지의

최단 거리
```

를 구한다.

---

### 가장 중요한 차이

| 항목 | 다익스트라 | 벨만-포드 |
| --- | --- | --- |
| 음수 간선 | ❌ 불가능 | ✅ 가능 |
| 음수 사이클 탐지 | ❌ 불가능 | ✅ 가능 |
| 속도 | 매우 빠름 | 상대적으로 느림 |
| 시간 복잡도 | O(E log V) | O(V × E) |

---

### 왜 다익스트라는 음수 간선에서 실패할까?

다음 그래프를 보자.

```
A → B : 4
A → C : 2
B → C : -5
```

---

다익스트라는

```
A → C = 2
```

를 먼저 확정할 수 있다.

---

하지만 나중에

```
A → B → C

=

4 + (-5)

=

-1
```

을 발견한다.

---

즉

```
확정한 값이
사실 틀림
```

이 된다.

---

그래서 다익스트라는

```
음수 간선 없음
```

이라는 조건이 반드시 필요하다.

---

### 언제 무엇을 사용할까?

### 대부분의 최단 거리 문제

```
음수 간선 없음
```

↓

```
다익스트라 사용
```

---

### 음수 간선 존재

```
음수 간선 있음
```

↓

```
벨만-포드 사용
```

---

### 음수 사이클까지 확인해야 함

```
벨만-포드
```

만 가능

---

### 꼭 기억할 것

```
다익스트라

=
빠르지만
음수 간선 불가
```

```
벨만-포드

=
느리지만
음수 간선 가능
+
음수 사이클 탐지 가능
```

한 문장으로 기억하면,

> **다익스트라는 "빠른 길찾기 전문가", 벨만-포드는 "음수 간선까지 처리하는 안전한 길찾기 전문가"이다.**
