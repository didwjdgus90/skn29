플로이드-워셜 알고리즘 (Floyd-Warshall Algorithm)

## 1. 한 줄 요약

- 플로이드-워셜은 **모든 정점에서 모든 정점까지의 최단 거리(All-Pairs Shortest Path)를 한 번에 구하는 알고리즘**이다.

---

## 2. 주요 활용처 및 문제 유형

다익스트라는 보통

```
한 출발지
↓
모든 정점
```

까지의 최단 거리를 구한다.

예를 들어

```
서울 → 모든 도시
```

까지의 최단 거리를 구하는 문제다.

---

그런데 어떤 문제는 다르다.

```
모든 도시 ↔ 모든 도시
```

사이의 최단 거리가 필요하다.

예를 들어

```
서울 → 부산
서울 → 대구
서울 → 광주

부산 → 서울
부산 → 대구
부산 → 광주

...
```

모든 조합을 알아야 한다.

---

### 현실 예시

### 지도 서비스

```
모든 도시 간 이동 시간 계산
```

---

### 택시 합승 문제

```
A → B

A → C

B → C
```

모든 이동 비용을 알아야 한다.

---

### 회사 조직도 분석

```
직원 A → 직원 B

직원 B → 직원 C

...
```

모든 관계 거리를 계산

---

### 코딩 테스트에서 자주 나오는 문제

다음 문장이 보이면 플로이드-워셜을 떠올려보자.

- 모든 정점 간 최단 거리
- 모든 도시 간 이동 비용
- 모든 노드 쌍
- 최단 거리 행렬
- 정점 개수가 크지 않음 (보통 500 이하)

---

## 3. 핵심 아이디어

### 비유

길찾기를 한다고 생각해보자.

현재

```
A → C
```

로 바로 가는 길이 있다.

비용은

```
10
```

이다.

---

그런데

```
A → B → C
```

로 가면

```
3 + 2 = 5
```

이다.

---

즉

```
직접 가는 길

보다

중간 도시를 거치는 길

이 더 짧을 수 있다.
```

---

플로이드-워셜의 핵심은

> "모든 정점을 중간 경유지로 사용해보자"
> 

이다.

---

### 생각 방식

현재

```
A → C = 10
```

---

B를 경유하면

```
A → B → C

=

5
```

---

더 짧다.

```
10 → 5
```

로 갱신한다.

---

이 작업을

```
A
B
C
D
...
```

모든 정점에 대해 반복한다.

---

## 4. 알고리즘 동작 과정 (Step-by-Step 시각화)

다음 그래프를 보자.

```
A ──4──→ B

│        │
10       3

↓        ↓

C ←──────
```

간선

```
A → B = 4
B → C = 3
A → C = 10
```

---

### Step 1. 초기 거리표 만들기

```
      A   B   C

A     0   4  10

B     ∞   0   3

C     ∞   ∞   0
```

---

의미

```
dist[A][C] = 10
```

현재 A에서 C로 가는 최단 거리는 10

---

### Step 2. B를 경유지로 사용

생각

```
A → C

VS

A → B → C
```

비교

---

현재

```
A → C = 10
```

---

B를 거치면

```
A → B = 4
B → C = 3

4 + 3 = 7
```

---

더 짧다.

```
10 → 7
```

갱신

---

거리표

```
      A   B   C

A     0   4   7

B     ∞   0   3

C     ∞   ∞   0
```

---

### Step 3. 다른 정점도 모두 확인

이번에는

```
A를 경유

C를 경유
```

등도 모두 시도한다.

---

계속 반복하면서

```
직접 가는 길

VS

중간 정점을 거치는 길
```

을 비교한다.

---

### Step 4. 최종 결과

최종 거리표

```
      A   B   C

A     0   4   7

B     ∞   0   3

C     ∞   ∞   0
```

---

이 표 하나만 보면

```
A → B

A → C

B → C
```

모든 최단 거리를 즉시 알 수 있다.

---

## 5. 파이썬(Python) 구현 코드

```
INF=int(1e9)

n=3

# 거리 테이블 생성
graph= [
    [INF]* (n+1)
for_inrange(n+1)
]

# 자기 자신은 0
foriinrange(1,n+1):
graph[i][i]=0

# 간선 정보
graph[1][2]=4
graph[2][3]=3
graph[1][3]=10

# 플로이드-워셜
forkinrange(1,n+1):

forainrange(1,n+1):

forbinrange(1,n+1):

graph[a][b]=min(
graph[a][b],
graph[a][k]+graph[k][b]
            )

# 결과 출력
foriinrange(1,n+1):
print(graph[i][1:])
```

---

출력

```
[0, 4, 7]
[1000000000, 0, 3]
[1000000000, 1000000000, 0]
```

---

### 핵심 코드 설명

---

```
graph[a][b]
```

현재 알고 있는 최단 거리

---

```
graph[a][k]+graph[k][b]
```

k를 거쳐서 가는 거리

---

```
min(
graph[a][b],
graph[a][k]+graph[k][b]
)
```

둘 중 더 짧은 것을 선택한다.

---

### 가장 중요한 부분

```
for k in range(1, n+1):
```

이 루프가 핵심이다.

---

의미

```
1번 정점을 경유해볼까?

2번 정점을 경유해볼까?

3번 정점을 경유해볼까?
```

를 반복하는 것이다.

## 6. 핵심 요약 및 주의점

### 핵심 아이디어

```
A → B

직접 가기

VS

어딘가를 거쳐 가기
```

를 계속 비교한다.

---

### 알고리즘 흐름

```
1. 거리표 생성

2. 모든 정점을 경유지로 선택

3. 더 짧아지면 갱신

4. 반복
```

---

### 시각화

```
현재

A ─────→ C

10
```

---

```
경유

A → B → C

4 + 3 = 7
```

---

```
10 > 7

↓

갱신
```

---

### 시간 복잡도

```
O(V³)
```

V = 정점 수

---

이유

```
경유지 선택

↓

출발지 선택

↓

도착지 선택
```

3중 반복문을 사용하기 때문이다.

---

### 공간 복잡도

```
O(V²)
```

거리표 전체를 저장한다.

---

### 자주 하는 실수

### 1. 자기 자신을 0으로 초기화 안 함

```
graph[i][i]=0
```

반드시 필요하다.

---

### 2. INF 값 너무 작게 설정

```
INF=int(1e9)
```

처럼 충분히 크게 잡아야 한다.

---

### 3. 반복문 순서 변경

반드시

```
for k
for a
for b
```

순서여야 한다.

---

잘못 작성

```
for a
for b
for k
```

는 플로이드-워셜이 아니다.

## 다익스트라와 차이점

| 항목 | 다익스트라 | 플로이드-워셜 |
| --- | --- | --- |
| 구하는 것 | 한 정점 → 모든 정점 | 모든 정점 → 모든 정점 |
| 시간 복잡도 | O(E log V) | O(V³) |
| 사용 방식 | 특정 출발지 기준 | 전체 거리표 생성 |
| 그래프 크기 | 큰 그래프에 유리 | 정점 수가 적을 때 유리 |
