# 본문
## 1. 한 줄 요약

- 유니온 파인드는 **여러 원소가 어떤 그룹에 속해 있는지 빠르게 관리하고, 두 원소가 같은 그룹인지 확인하는 자료구조**이다.

---

## 2. 주요 활용처 및 문제 유형

어떤 사람들 사이에 친구 관계가 있다고 생각해보자.

```
철수 ─ 영희

민수 ─ 지수
```

현재는 두 개의 그룹이 존재한다.

```
그룹 1
철수, 영희

그룹 2
민수, 지수
```

그런데 갑자기

```
영희 ─ 민수
```

가 연결되면?

```
철수 ─ 영희 ─ 민수 ─ 지수
```

모두 하나의 그룹이 된다.

---

이런 상황에서 자주 하는 질문은 다음과 같다.

```
철수와 지수는 같은 그룹인가?

A와 B는 연결되어 있는가?

현재 그룹은 몇 개인가?
```

유니온 파인드는 이런 질문에 매우 빠르게 답할 수 있다.

---

### 코딩 테스트에서 자주 나오는 문제

다음과 같은 키워드가 보이면 유니온 파인드를 의심해보자.

- 네트워크 연결
- 친구 관계
- 같은 집합 여부
- 연결 요소 개수
- 사이클 판별
- 최소 신장 트리(MST)

문제를 읽다가

> "둘을 연결한다"
> 
> 
> "같은 그룹인지 확인한다"
> 

라는 문장이 반복되면 유니온 파인드일 가능성이 높다.

---

## 3. 핵심 아이디어

유니온 파인드는 이름 그대로 두 가지 기능만 제공한다.

### Union

```
두 그룹을 합친다.
```

---

### Find

```
현재 어떤 그룹에 속하는지 찾는다.
```

---

### 비유

회사에서 팀을 관리한다고 생각해보자.

처음에는 모두 각자 팀이다.

```
A

B

C

D
```

---

A와 B를 같은 팀으로 만든다.

```
A-B
```

---

C와 D를 같은 팀으로 만든다.

```
C-D
```

---

B와 C를 연결한다.

```
A-B-C-D
```

그러면 사실상

```
A, B, C, D
```

모두 같은 팀이 된다.

---

유니온 파인드는

> "이 사람의 팀 대표가 누구인가?"
> 

만 관리한다.

대표가 같으면 같은 그룹이다.

---

## 4. 알고리즘 동작 과정 (Step-by-Step 시각화)

원소 1~5가 있다고 가정하자.

---

### Step 1. 처음 상태

모두 자기 자신이 대표이다.

```
1   2   3   4   5

parent

1   2   3   4   5
```

의미

```
1의 대표 = 1
2의 대표 = 2
3의 대표 = 3
4의 대표 = 4
5의 대표 = 5
```

---

### Step 2. Union(1, 2)

1과 2를 합친다.

```
1 ← 2
```

parent 배열

```
index   1 2 3 4 5
parent  1 1 3 4 5
```

---

### Step 3. Union(2, 3)

2와 3을 합친다.

현재

```
1 ← 2
```

이므로

3도 1 그룹으로 들어간다.

```
1
↑
2
↑
3
```

parent

```
index   1 2 3 4 5
parent  1 1 1 4 5
```

---

### Step 4. Union(4, 5)

```
4 ← 5
```

parent

```
index   1 2 3 4 5
parent  1 1 1 4 4
```

---

현재 모습

```
그룹 A

1
↑
2
↑
3

그룹 B

4
↑
5
```

---

### Step 5. 같은 그룹인지 확인

질문

```
2 와 3 은 같은 그룹인가?
```

---

Find(2)

```
2 → 1
```

대표

```
1
```

---

Find(3)

```
3 → 1
```

대표

```
1
```

---

대표가 같으므로

```
2 와 3 은 같은 그룹
```

이다.

---

### Step 6. 다른 그룹인지 확인

질문

```
3 과 5 는 같은 그룹인가?
```

---

Find(3)

```
3 → 1
```

대표

```
1
```

---

Find(5)

```
5 → 4
```

대표

```
4
```

---

대표가 다르므로

```
다른 그룹
```

이다.

## 5. 파이썬(Python) 구현 코드

### 기본 구현

```
# parent[i] = i의 부모
parent= [0,1,2,3,4,5]

deffind(x):
# 대표 노드를 찾는다.
ifparent[x]==x:
returnx

returnfind(parent[x])

defunion(a,b):
# 각 원소의 대표를 찾는다.
root_a=find(a)
root_b=find(b)

# 이미 같은 그룹이면 종료
ifroot_a==root_b:
return

# 두 그룹을 합친다.
parent[root_b]=root_a

union(1,2)
union(2,3)
union(4,5)

print(find(1))
print(find(3))
print(find(5))
```

---

### 핵심 코드 설명

```
root_a=find(a)
root_b=find(b)
```

먼저 각 원소의 대표를 찾는다.

예를 들어

```
1 ← 2 ← 3
```

이라면

```
find(3)
```

결과는

```
1
```

이다.

---

```
parent[root_b]=root_a
```

두 그룹을 합친다.

예를 들어

```
1 ← 2

3 ← 4
```

일 때

```
union(2,4)
```

를 하면

```
1
↑
2

↑

3
↑
4
```

처럼 하나의 그룹이 된다.

---

### 경로 압축(Path Compression) 적용

실전에서는 거의 항상 아래 버전을 사용한다.

```
parent= [0,1,2,3,4,5]

deffind(x):
ifparent[x]!=x:
parent[x]=find(parent[x])

returnparent[x]

defunion(a,b):
root_a=find(a)
root_b=find(b)

ifroot_a!=root_b:
parent[root_b]=root_a
```

---

### 경로 압축이 왜 필요한가?

다음과 같은 구조가 있다고 하자.

```
1
↑
2
↑
3
↑
4
↑
5
```

---

Find(5)를 수행하면

```
5 → 4 → 3 → 2 → 1
```

을 모두 따라가야 한다.

---

경로 압축 후

```
1
↑ ↑ ↑ ↑
2 3 4 5
```

가 된다.

즉

```
5 → 1
```

로 바로 이동 가능하다.

---

그래서 이후 Find 연산이 매우 빨라진다.

---

## 6. 핵심 요약 및 주의점

### 유니온 파인드가 하는 일

```
1. 그룹 합치기
   Union

2. 대표 찾기
   Find
```

---

### 핵심 아이디어

```
같은 그룹인가?

↓

대표가 같은가?
```

만 확인하면 된다.

---

### 시각화

```
1
↑
2
↑
3

find(3)

↓

1
```

---

### 시간 복잡도

경로 압축 적용 시

```
Find  ≈ O(1)
Union ≈ O(1)
```

수준으로 매우 빠르다.

정확히는 거의 상수 시간에 가깝다고 생각하면 된다.

---

### 자주 하는 실수

### 1. 바로 연결하지 않기

잘못된 예

```
parent[b]=a
```

반드시 대표끼리 연결해야 한다.

```
parent[find(b)]=find(a)
```

---

### 2. 같은 그룹인지 확인 안 하기

```
union(a,b)
```

전에

```
find(a)==find(b)
```

인지 확인해야 하는 문제들이 많다.

특히 사이클 판별 문제에서 중요하다.

---

### 3. 경로 압축 빼먹기

```
parent[x]=find(parent[x])
```

를 넣지 않으면 큰 입력에서 속도가 느려질 수 있다.

---

### 꼭 기억할 것

```
유니온 파인드

= 그룹 관리 전문가

Union
→ 그룹 합치기

Find
→ 그룹 대표 찾기

대표가 같으면
같은 그룹이다.
```

그래프 문제에서 "연결 여부"를 빠르게 판단해야 한다면 가장 먼저 떠올려야 하는 자료구조 중 하나이다.
