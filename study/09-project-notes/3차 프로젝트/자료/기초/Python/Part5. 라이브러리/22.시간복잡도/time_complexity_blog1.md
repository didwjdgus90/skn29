## 1. 한 줄 요약

시간복잡도는 **데이터가 많아질수록 코드가 얼마나 느려지는지를 나타내는 기준**이다. Big-O 표기법으로 표현하며, 코딩테스트에서 "시간 초과"를 피하려면 반드시 알아야 한다.

---

## 2. 왜 시간복잡도를 알아야 할까?

같은 결과를 내는 코드라도 속도가 크게 다를 수 있다.

리스트에서 특정 값이 있는지 확인하는 두 가지 방법을 비교해보자.

```python
nums = list(range(1000000))   # 100만 개의 숫자

# 방법 1: 리스트에서 탐색
result = 999999 in nums   # 처음부터 끝까지 전부 확인

# 방법 2: 집합에서 탐색
nums_set = set(nums)
result = 999999 in nums_set   # 즉시 확인
```

데이터가 100만 개일 때, 방법 1은 최악의 경우 100만 번 비교해야 하지만 방법 2는 거의 즉시 결과가 나온다.

코딩테스트에서는 대부분 **시간 제한(보통 1~2초)** 이 있다. 이 시간 안에 실행이 완료되지 않으면 "시간 초과"로 오답 처리된다. 시간복잡도를 알면 내 코드가 제한 시간 안에 통과할지 미리 예측할 수 있다.

---

## 3. 핵심 아이디어 — Big-O 표기법

시간복잡도는 **Big-O(빅오) 표기법**으로 표현한다. `O(n)`, `O(n²)` 같은 식으로 쓰며, 여기서 `n`은 **데이터의 개수**다.

Big-O는 "데이터가 n개일 때, 대략 몇 번 연산하는가"를 나타낸다. 정확한 숫자가 아닌 **대략적인 증가 속도**에 집중한다.

```
데이터 n개일 때 주요 Big-O 비교:

O(1)       → 항상 1번 (데이터 양과 무관)
O(log n)   → 데이터가 2배 늘어도 1번만 더
O(n)       → 데이터에 비례해서 증가
O(n log n) → n보다 조금 더 빠르게 증가
O(n²)      → 데이터가 2배 → 연산은 4배
O(2^n)     → 데이터가 1 늘면 연산이 2배
```

**빠른 순서 (위에서 아래로 느려짐)**

```
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n)
빠름 ←─────────────────────────────────────→ 느림
```

## 4. 각 Big-O 직관적으로 이해하기

### O(1) — 상수 시간

데이터가 아무리 많아도 **항상 같은 시간**이 걸린다. 가장 빠른 복잡도다.

```python
lst = [1, 2, 3, 4, 5]
print(lst[0])      # O(1) — 인덱스로 즉시 접근
lst.append(6)      # O(1) — 맨 뒤에 추가
d = {"a": 1}
print(d["a"])      # O(1) — 딕셔너리 키로 즉시 접근
```

비유: 책의 특정 페이지 번호로 바로 펼치는 것. 책이 두꺼워도 페이지 번호만 알면 바로 찾을 수 있다.

### O(log n) — 로그 시간

데이터가 2배 늘어도 연산이 **1번만 더** 필요하다. 이진 탐색이 대표적이다.

```python
# 이진 탐색: 매 단계마다 탐색 범위를 절반으로 줄임
import bisect
lst = sorted([1, 3, 5, 7, 9])
bisect.bisect_left(lst, 7)   # O(log n)
```

비유: 두꺼운 사전에서 단어를 찾을 때 가운데를 펼쳐서 앞/뒤를 판단하는 것. 책이 2배 두꺼워져도 딱 1번만 더 펼치면 된다.

### O(n) — 선형 시간

데이터가 n개면 **n번** 연산한다. 가장 흔한 복잡도다.

```python
lst = [5, 3, 8, 1, 9]
print(max(lst))    # O(n) — 전체를 한 번 봐야 최댓값을 알 수 있음
print(sum(lst))    # O(n) — 전체를 더해야 함
3 in lst           # O(n) — 최악의 경우 전체 탐색
```

비유: 책에서 특정 단어가 있는지 찾으려고 처음 페이지부터 끝까지 읽는 것. 책이 2배 두꺼우면 2배 오래 걸린다.

### O(n log n) — 선형 로그 시간

대부분의 **효율적인 정렬 알고리즘**이 이 복잡도를 가진다. O(n)보다 조금 느리지만 O(n²)보다 훨씬 빠르다.

```python
lst = [5, 3, 8, 1, 9]
lst.sort()         # O(n log n) — 파이썬 기본 정렬
sorted(lst)        # O(n log n)
```

### O(n²) — 이차 시간

데이터가 2배 → 연산이 **4배**로 늘어난다. 이중 for문이 대표적이다.

```python
lst = [1, 2, 3, 4, 5]

# 이중 for문 → O(n²)
for i in lst:
    for j in lst:
        print(i, j)   # n × n = n² 번 실행
```

데이터가 1,000개면 100만 번 연산, 10,000개면 1억 번 연산이다. n이 커질수록 급격히 느려지므로 주의해야 한다.

## 5. 실제로 얼마나 차이날까?

n이 커질수록 복잡도 차이가 얼마나 크게 벌어지는지 보자.

```
n = 1,000 일 때 연산 횟수:

O(1)       →        1 번
O(log n)   →       10 번
O(n)       →    1,000 번
O(n log n) →   10,000 번
O(n²)      → 1,000,000 번  ← n=1,000이어도 100만 번!
```

```
n = 100,000 일 때 (코딩테스트에서 자주 나오는 범위):

O(n)       →      100,000 번   ✅ 빠름
O(n log n) →    1,700,000 번   ✅ 괜찮음
O(n²)      → 10,000,000,000 번 ❌ 시간 초과 가능성 높음
```

**대략적인 기준 (1초에 약 1억 번 연산 가능)**

```
n의 범위       허용 가능한 복잡도
─────────────────────────────
n ≤ 1,000     O(n²) 이하면 OK
n ≤ 100,000   O(n log n) 이하 권장
n ≤ 1,000,000 O(n) 이하 권장
```

## 6. 파이썬 자료형별 주요 연산의 시간복잡도

코딩테스트에서 자료형을 선택할 때 참고하자.

### 리스트 (list)

```
연산                  복잡도    설명
──────────────────────────────────────────────
lst[i]               O(1)    인덱스 접근
lst.append(x)        O(1)    맨 뒤에 추가
lst.pop()            O(1)    맨 뒤에서 꺼냄
len(lst)             O(1)    길이 확인
x in lst             O(n)    처음부터 탐색
lst.insert(i, x)     O(n)    중간 삽입 (뒤를 밀어야 함)
lst.pop(0)           O(n)    맨 앞 제거 (전체를 한 칸씩 이동)
del lst[i]           O(n)    특정 위치 삭제
lst.sort()           O(n log n) 정렬
min(lst), max(lst)   O(n)    전체 탐색 필요
```

> ⚠️ `lst.pop(0)`은 `O(n)`이다. 맨 앞 원소를 자주 꺼내야 한다면 `deque`를 쓰자.

### 집합(set) / 딕셔너리(dict)

```
연산                  복잡도    설명
──────────────────────────────────────────────
x in set             O(1)    해시로 즉시 확인  ← 리스트의 O(n)과 비교!
set.add(x)           O(1)    추가
set.remove(x)        O(1)    제거
d[k]                 O(1)    키로 접근
d[k] = v             O(1)    저장
k in d               O(1)    키 존재 확인
```

**리스트 vs 집합/딕셔너리 핵심 차이**

```python
# 포함 여부 확인: 리스트 O(n) vs 집합 O(1)
lst = list(range(1000000))
s   = set(range(1000000))

999999 in lst   # O(n) — 느림!
999999 in s     # O(1) — 즉시!
```

탐색과 포함 확인이 주요 작업이라면 **리스트 대신 집합/딕셔너리**를 쓰자.

## 7. 시간복잡도 개선 예시

같은 문제를 O(n²)와 O(n)으로 풀 때 차이를 보자.

**문제: 리스트에서 합이 target인 두 수의 인덱스 찾기**

```python
# O(n²) 풀이 — 이중 for문
def find_pair_slow(nums, target):
    for i in range(len(nums)):
        for j in range(i+1, len(nums)):
            if nums[i] + nums[j] == target:
                return i, j

# O(n) 풀이 — 딕셔너리 활용
def find_pair_fast(nums, target):
    seen = {}                        # 딕셔너리로 O(1) 탐색
    for i, num in enumerate(nums):
        complement = target - num
        if complement in seen:       # O(1) 확인
            return seen[complement], i
        seen[num] = i
```

n이 10만일 때 O(n²)는 100억 번 연산이지만, O(n) 풀이는 10만 번만 연산한다. **딕셔너리를 활용해서 탐색을 O(n) → O(1)로 줄인 것이 핵심이다.**

---

## 8. 마지막 정리

- 시간복잡도는 **데이터가 많아질수록 코드가 얼마나 느려지는지**를 Big-O로 나타낸 것이다.
- 빠른 순서: **O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2^n)**
- n ≤ 100,000이면 **O(n log n)까지 안전**, O(n²)은 시간 초과 위험이 높다.
- **리스트의 `in` 연산은 O(n)**, **집합/딕셔너리의 `in` 연산은 O(1)** — 탐색이 많다면 자료구조를 바꾸자.
- `lst.pop(0)`은 O(n)이다. 맨 앞 제거가 잦으면 **`deque`** 를 쓰자.
- 코드를 짜기 전에 "이 방법으로 하면 몇 번 연산할까?"를 먼저 따져보는 습관이 중요하다.
