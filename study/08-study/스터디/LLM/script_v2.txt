================================================================================
  LLM으로 법률 조항 분류하기 — 발표 대본
  대상: 비전공자, LLM 입문자
  소요 시간: 15~20분
================================================================================

--------------------------------------------------------------------------------
[도입 — 2분]
--------------------------------------------------------------------------------

법률 문서를 한 번 보신 적 있나요?
조항이 수백 개씩 있고, 어떤 건 권리를 설명하고, 어떤 건 처벌을 설명하고,
어떤 건 시행일을 정합니다.

이걸 사람이 하나하나 읽고 분류하면 시간이 엄청 걸립니다.
그래서 컴퓨터가 자동으로 분류할 수 있으면 좋겠죠.

오늘 실습은 딱 이 문제입니다.
법률 조항 하나를 넣으면 컴퓨터가 "이건 처벌 규정이야", "이건 정의 조항이야"라고
자동으로 분류하게 만드는 겁니다.

전체 흐름은 이렇습니다.

  법률 조항 원문 -> 토큰화 -> 숫자로 변환 -> 모델이나 규칙 -> 카테고리 -> 검토

오늘 1강에서는 이 기초를 이해하고, 간단한 규칙으로 분류기를 먼저 만들어 봅니다.
2강에서는 AI(LLM)에게 똑같은 문제를 더 잘 풀도록 지시하는 방법을 배웁니다.

--------------------------------------------------------------------------------
[1강 파트 1: 컴퓨터는 텍스트를 어떻게 읽나 — 6분]
--------------------------------------------------------------------------------

먼저 한 가지만 기억해 주세요.
컴퓨터는 글을 읽지 못합니다. 숫자만 처리할 수 있습니다.
그래서 글을 숫자로 바꾸는 두 단계가 필요합니다.
첫 번째가 토크나이제이션, 두 번째가 임베딩입니다.


[토크나이제이션 — 셀 1-1 실행]

"법원은 피고인에게 징역 3년과 벌금 500만원을 선고했다"

이 문장을 컴퓨터에 그냥 넣으면 처리를 못 합니다.
먼저 잘게 쪼개야 합니다. 이걸 토크나이제이션이라고 합니다.

공백 기준으로 쪼개면 "법원은", "피고인에게" 이렇게 됩니다.
조사가 붙어 있죠.

정규표현식으로 쪼개면 "법원", "피고인", "징역" 이렇게 깔끔하게 분리됩니다.

왜 이게 중요할까요?
우리가 나중에 "징역"이라는 단어가 있으면 처벌 조항이라고 분류할 건데,
"징역에"처럼 조사가 붙어 있으면 "징역"을 못 잡을 수 있습니다.
토크나이저 선택이 분류 결과에 영향을 줍니다.


[임베딩 — 셀 2-1 실행]

토큰으로 쪼갰다면 이제 숫자로 바꿔야 합니다. 이게 임베딩입니다.

가장 단순한 방법은 "이 단어가 있으면 1, 없으면 0"으로 표현하는 겁니다.
화면에 보이는 표가 그겁니다.

S1 문장(처벌 조항)은 징역, 벌금, 처한다가 모두 1입니다.
S3 문장(위원회 조항)은 위원회, 설치가 1이고 징역은 0입니다.

코사인 유사도 결과를 보면,
같은 카테고리인 S1과 S2(둘 다 처벌 조항)는 유사도가 높고,
다른 카테고리인 S1과 S3는 유사도가 낮습니다.

이게 바로 분류의 수학적 근거입니다.
비슷한 의미의 문장은 숫자도 비슷하게 만들어서 같은 카테고리로 묶는 겁니다.


[LLM 원리 — 셀 3-1 실행]

GPT 같은 AI가 어떻게 동작하는지 아주 단순하게 보여드릴게요.

한 문장으로 요약하면: "앞 단어들을 보고 다음 단어를 예측하는 기계"입니다.

"이 법은 국민의..." 다음에 올 단어가 뭘까요?
말뭉치를 보면 "권리를"이 가장 많이 나왔습니다.
그래서 "권리를"을 선택하고, 또 다음 단어를 예측하고... 이걸 반복하면 문장이 완성됩니다.

화면에서 생성 과정을 보면 각 단계에서 가장 빈도가 높은 토큰을 선택하는 걸 볼 수 있습니다.
실제 GPT는 이 확률 계산을 수십억 개의 파라미터로 훨씬 정교하게 하는 것뿐입니다.
원리는 같습니다.

--------------------------------------------------------------------------------
[1강 파트 2: 규칙 기반 분류기 — 5분]
--------------------------------------------------------------------------------

이제 실제로 분류기를 만들어 봅니다.

우리가 분류할 카테고리는 6가지입니다.

  DEF   — 목적이나 용어를 정의하는 조항
  RIGHT — 권리나 의무를 규정하는 조항
  PROC  — 신청, 심사, 처벌 절차를 규정하는 조항
  ORG   — 위원회나 기관을 설치하는 조항
  CRIT  — 자격이나 수치 기준을 정하는 조항
  ETC   — 시행일이나 위임 같은 나머지 조항

가장 단순한 방법은 키워드를 보는 겁니다.
"징역", "벌금", "처한다"가 있으면 PROC.
"위원회", "설치", "구성"이 있으면 ORG.
이런 식입니다.


[셀 6-1 실행 — 키워드 스코어링]

각 문장에서 카테고리별 키워드가 몇 개 매칭됐는지 세는 겁니다.
confident라고 뜨는 문장은 한 카테고리 신호가 명확하게 잡힌 경우고,
ambiguous나 tied는 여러 카테고리 신호가 동시에 나타난 경우입니다.


[셀 7-1 실행 — 규칙 기반 분류기]

결과를 보면 정확도가 나옵니다.
나쁘지 않아 보이지만, 여기서 중요한 실험을 하나 해봅니다.


[셀 7-2 실행 — 우선순위 조합 실험]

키워드 순서를 바꿔가면서 정확도를 비교합니다.
120가지 조합 중 최고와 최저를 보세요.
순서 하나만 바꿔도 정확도가 크게 달라집니다.

왜냐하면 같은 키워드가 여러 카테고리에 겹치기 때문입니다.
"이하"라는 단어는 CRIT(요건 조항)에도 나오고 PROC(처벌 조항)에도 나옵니다.
어느 카테고리를 먼저 확인하느냐가 결과를 결정합니다.

이게 키워드 방식의 근본적인 한계입니다.
문맥을 무시하고 단어만 봅니다.


[셀 8-1 — 애매한 문장]

실제로 헷갈리는 문장을 넣어보면 더 명확합니다.

"세부 안전관리 기준은 대통령령으로 정한다."
키워드를 보면 "기준"이 있으니 CRIT를 선택합니다.
그런데 정답은 ETC입니다.
왜냐하면 기준 내용이 없고, 나중에 대통령령으로 정하겠다는 위임만 있기 때문입니다.

이런 문맥을 이해하려면 단어 하나가 아니라 문장 전체를 봐야 합니다.
이게 바로 2강에서 LLM을 쓰는 이유입니다.

--------------------------------------------------------------------------------
[2강 파트: LLM에게 잘 지시하는 방법 — 7분]
--------------------------------------------------------------------------------

LLM은 문장 전체의 맥락을 봅니다.
그래서 "세부 기준은 대통령령으로 정한다"에서
기준이라는 단어에만 집중하지 않고 "위임한다"는 문장의 의도를 파악할 수 있습니다.

그런데 LLM도 지시가 명확하지 않으면 자기 방식대로 해석합니다.
그래서 프롬프트 설계가 중요합니다.


[셀 2-1 실행 — 프롬프트 구조 확인]

프롬프트는 세 부분으로 구성됩니다.

첫째, System 프롬프트.
  "너는 법률 분류기다. 6개 카테고리 중 하나만 고르고 JSON으로만 답해라."
  모델의 역할과 출력 형식을 고정합니다.

둘째, 라벨 설명.
  각 카테고리가 어떤 문장인지 정의를 써줍니다.
  이게 없으면 모델이 DEF와 ETC의 차이를 자기 방식으로 해석합니다.

셋째, 예시(Shot).
  "이런 문장은 이 카테고리야"라는 예시를 보여줍니다.

Zero-Shot은 예시 없이, One-Shot은 1개, Few-Shot은 여러 개입니다.
화면에서 세 가지 프롬프트의 길이 차이를 보세요.
예시가 늘수록 프롬프트가 길어집니다.


[셀 4-1 실행 — Zero vs One-Shot]

전체 24개 문장을 두 모드로 비교합니다.
예시 하나만 추가했는데 정확도가 올라가는 걸 볼 수 있습니다.
특히 카테고리별 결과를 보면 어떤 카테고리에서 개선됐는지 확인할 수 있습니다.


[셀 5-1 실행 — Temperature 실험]

Temperature는 모델이 얼마나 "창의적으로" 답할지 조절하는 값입니다.

0이면 항상 가장 확률 높은 답을 선택합니다. 매번 같은 결과가 나옵니다.
0.8이면 가끔 다른 선택을 합니다. 다양하지만 불안정합니다.

분류 문제에서는 temperature를 낮게 설정하는 게 좋습니다.
"이 문장이 처벌 조항인가"라는 질문에는 정해진 답이 있으니까요.
창의적인 답이 필요한 게 아닙니다.


[셀 6-1 실행 — Few-Shot 개수 실험]

예시를 많이 줄수록 항상 좋아질까요?

결과를 보면 0개에서 1개로 늘었을 때 가장 크게 좋아집니다.
그런데 3개에서 5개로 늘리면 오히려 나빠질 수 있습니다.

왜냐하면 예시가 편향될 수 있기 때문입니다.
PROC 예시만 3개 넣으면 모델이 PROC를 더 많이 선택하게 됩니다.
예시의 양보다 질이 중요합니다.


[셀 7-1 실행 — 규칙 강화 프롬프트]

가장 효과적인 전략입니다.

예시를 더 넣는 대신, 헷갈리는 경계를 직접 말로 설명합니다.
예를 들어 이렇게 씁니다.

  "숫자나 요건이 있어도 시행일과 경과조치는 ETC로 판단한다."

이 규칙 하나가 "세부 기준은 대통령령으로 정한다" 문장을
ETC로 정확히 분류하는 데 결정적입니다.

결과를 보면 baseline과 rule_aware의 정확도 차이를 확인할 수 있습니다.

실무에서 좋은 방법은 이렇습니다.
오답이 나오면 "왜 틀렸는가"를 분석하고,
그 이유를 규칙으로 써서 프롬프트에 추가합니다.
다시 실행해서 개선됐는지 확인합니다.
이 사이클을 반복합니다.


[셀 8-1 실행 — Label-Only]

마지막으로 출력 단순화입니다.

모델에게 "왜 그렇게 분류했는지 설명해"라고 하면 긴 답변이 나옵니다.
그 과정에서 JSON 형식이 깨지거나 라벨을 틀리는 경우가 생깁니다.

분류 결과만 필요하다면 "라벨만 JSON으로 줘"라고 하면 됩니다.
더 짧고 안정적입니다.

물론 오답 분석이 필요할 때는 이유도 받는 게 좋습니다.
상황에 맞게 선택하면 됩니다.


[셀 9-1 실행 — 전략 종합 비교]

전체 전략을 한눈에 비교합니다.

규칙 기반이 기준선입니다.
Zero-Shot LLM이 규칙 기반보다 낮을 수도 있습니다.
One-Shot을 추가하면 크게 올라갑니다.
규칙 강화 프롬프트가 가장 높습니다.

LLM이 만능이 아닙니다.
지시가 명확하지 않으면 단순한 키워드 방식보다 못할 수 있습니다.
라벨 정의와 경계 규칙을 명확하게 써주는 게 핵심입니다.

--------------------------------------------------------------------------------
[마무리 — 1분]
--------------------------------------------------------------------------------

오늘 핵심을 세 문장으로 요약합니다.

첫째, 키워드 방식은 빠르고 투명하지만 문맥을 무시해서 헷갈리는 문장에서 실패합니다.

둘째, LLM은 문맥을 이해할 수 있지만, 라벨 정의와 경계 규칙을 명확하게 써줘야
      그 능력이 발휘됩니다.

셋째, 오답 분석 후 규칙 추가를 반복하는 게 실무에서 가장 효과적인 방법입니다.

이 코드들은 더미로 동작하지만, 마지막 셀에 실제 API 연결 방법이 적혀 있습니다.
실제 모델로 바꿔도 프롬프트와 평가 코드는 그대로 쓸 수 있습니다.

이상입니다.
